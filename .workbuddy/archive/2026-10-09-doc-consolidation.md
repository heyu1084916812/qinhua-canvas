## 三、怎么核对没有丢东西（三步，都可机械执行）

1. **文件数不减少**
   ```
   git show --stat HEAD   # 看本次提交只新增、不删除
   ```
2. **索引覆盖检查**
   ```
   node scripts/check-doc-index.mjs
   ```
   脚本会把根目录所有 `.md` 与《文档总索引》登记表逐一对账，
   列出**没被登记**的文件；输出 `OK` 才代表没有孤儿文档。
3. **恢复任意一份历史版本**
   ```
   git log --oneline -- 轻画-下一步实施设计.md
   git show <commit>:轻画-下一步实施设计.md
   ```
   因为文档从未删除，任何一次修改都能原样取回。

## 四、为什么不合并

| 合并的做法 | 风险 |
| --- | --- |
| 把 5 份调研/设计合成一份 | 875KB 对账清单里 388 条编号条目的上下文会被压平；合并过程一旦漏抄一段，**不会报错** |
| 删除被取代文档 | 决策的推导过程随之消失，日后"为什么当时否掉某方案"再也查不到 |
| 只保留最新结论 | 无法追溯口径变化（例如电商形态从"画布内视图"改了两次才定稿） |

**结论**：文档的价值不只是"当前结论"，还有"结论是怎么来的"。
索引 + 标注保住了两者，合并只能保住前者。
