## 设计文档评审（用户拿 ChatGPT 回答来对照；链接因网络限制抓不到，改做独立评审）
发现的主要问题（按严重度）：
- **P0 注册表归属与命令层依赖冲突**：NodeDefinition 的 createDefaultData / accepts / collectInputs 在 workbenches 层，但 state 层的命令处理器（node.create 等）需要用它们，而依赖方向禁止 state → workbenches。破坏「新增节点类型只改 3 个文件」的承诺。
- **P0 single-alt 是逻辑空洞**：产品定义了 Alt+R「保留旧内容铺新下游」，但架构命令层 `runPlan.execute.mode` 显式 Exclude 了 'single-alt'，没有实现路径。
- **P0 结果组归属双轨**：parentId / resultGroups 表 / nodes.data.childIds 三处都能表达归属，未规定谁是唯一真源。
- **P0 素材 GC 与永不删除的 runRecords 冲突**：引用计数永远不会归零，§12.2 的素材清理规则失效。
- **P0 执行模式口径不一致**：产品写「三种执行模式」但表列 4 行；架构 RunMode 有 5 个值；traverseDownstream 文件位置两份文档不一致（产品 features/execution/，架构 features/canvas/execution/）。
- P1：撤销后的持久化未定义、视频异步轮询无接口（generateVideo 无 poll/jobId）、画板内是第四套坐标未定义、新建节点无 LiveFingerprint 时陈旧初值未定义、改自身参数也会被标陈旧与产品文案不符、多标签页「最后写入为准」无实现机制且会与全量事务写冲突、容器 >9 个素材行为未定义、项目卡片缩略图生成方案缺失。
