- `removeLeaf(nodes, panelId)`：删叶 + **回收退化切割**（只剩单子的切割节点被提升合并）。
- `instantiateFullPage(panelId)`：空 `layout` → 满页单格（**编辑器首次排版行为**，非领域默认）。
- `divisionRatios(childCount, position)`：`start/center/end` = 1/3:2/3 / 1/2:1/2 / 2/3:1/3（仅二元有意义），子数≠2 回退等分。
- **核心决定：几何与顺序彻底解耦**。`readingOrder.ts` 管顺序、`layoutEdit.ts` 管几何；**RTL 只重排阅读序号、不移动几何**（位置是画出来的、顺序是读出来的）。编辑器因此只按几何序追加 `children`，无需为日漫调换。`layoutEdit.test.ts` 25 项（含浮点用 `toBeCloseTo`，`1-1/3≠2/3` 末位差异）。

**关键设计判断**：
1. **切成「纯函数决策 + 一层接线」**：计划与 SVG 都是纯函数（可单测、不必起浏览器），只有光栅化/组包/落盘是副作用。层级落位：domain 纯函数、shared 通用字节工具、workbenches 接线 —— depcruise 新增 4 模块后仍 0 违规。
2. **为什么自研 ZIP**：`FilePort.saveFile` 只有单文件出口，且产品文档 §10 禁第三方依赖。只做 store（不 deflate）：PNG 已压缩，收益极小，却要把纯函数染成异步。
3. **为什么走 SVG 字符串而非直接画 canvas**：产出是字符串 → 几何/折行/左右顺序都能单测；自包含（底图 `data:` + 颜色写死）→ canvas **不被污染**、`toBlob` 可用；格子几何仍走 `layoutRects`，与编辑器/阅读器同源。
4. **两处刻意「不完美」**：SVG **底色写死**（脱离页面无 `:root`，导出文档必须自包含；取值抄 `ui/tokens.css` 并注明）；折行**按字宽估算**而非 canvas 度量（保住纯函数可单测）。
5. **跨页导出不另立规则**：计划层用 `spreadGroups`、渲染层用 `spreadSlots` —— 阅读与导出**不会有两套「哪几页算一组」的认知**。
6. **缺失素材不阻塞**：未生成/未落库的格跳过底图（保留白底 + 描边）；未排版页计入 `emptyPages` 如实提示而非静默丢弃。

**踩坑/关键发现**：
- **mock 渠道的「图」是假字节**！`platform/channels/mock.ts` 产出 `bytes = TextEncoder.encode('mock-asset:<hash>')` 但 `mime: 'image/png'` —— **G30 只断言了 `src` 以 `blob:` 开头，并未证明 `<img>` 真能解码**。所以「底图真的画进导出 PNG」这条链**离线冒烟证明不了**。对策：G33 里加一段**机制级验证** —— `page.evaluate` 里 `await import('/src/domain/comic/export/sheetSvg.ts')` 动态加载**真实模块**（Vite dev server 能直接服务 TS），在浏览器里现造一张纯红 PNG，内联进 SVG，走同一条 `Image → canvas → toBlob` 路径并**采样像素**：红 1,592,832 / 暗 1,241 / `toBlob` 47.6 kB。这同时证明了「真图内联可光栅化」「文字光栅化落地」「canvas 未被 data: 底图污染」。
- 编辑大文件时把 `const browser = await chromium.launch(...)` 一行误删（替换块吃掉了），靠 `node --check` 立刻发现并补回。**教训：改 smoke 这种「尾部有引导代码」的脚本后，务必 `node --check`。**

**冒烟**：**G33（28 断言，`acceptDownloads: true`）**：三页（格数 1/2/1）→ 默认单页版式 → 导出本话，`page.waitForEvent('download')` 接住 ZIP 并落盘 → 自写 `parseZip` 断条目数与命名（`第 1 话/001.png`…）→ `pngSize` 读 IHDR 断 `1080×1620` → 切跨页断言 **2 张**（`001.png` / `002-003.png`）与并排 `2184×1620` → 切回单页 → 导出整个项目断言 `未命名漫画剧/第 1 话/...` 前缀 → 状态行文案 → 上述机制级验证 → 无未捕获异常。另用 Python `zipfile` 独立解包一次（第三方实现能读 ⇒ 包是标准合规的），并目视核对解出的 PNG（2 格竖切版面正确、跨页左页 2 格 | 中缝 | 右页 1 格）。

### M6-9 缩略底图与页码角标

**交付**：
- **domain 纯函数** `domain/comic/overview/thumbnail.ts`：
  - `overviewCells(page, direction=DEFAULT_READING_DIRECTION): ThumbCell[]` —— 空版式返回 `[]`；否则把 `layoutRects` 映射为 `{panelId,x,y,w,h,order,assetHash?}`，并**按阅读顺序排序**（`readingOrderOf`）。
  - `pageBadgeText(index)` —— **叙事页码**（0→1），负数/NaN/Infinity 夹到 "1"，浮点截断。
  - `hasThumbArt(cells)` —— 至少一格有图。
- **UI** `EpisodeOverview`：新增可选 `direction?: ReadingDirection` prop；每页走 `overviewCells`；结构 `.thumbFrame`（相对定位、2:3、承载角标）→ `.thumbPage`（absolute inset:0）→ `.thumbCell`（absolute + overflow hidden）→ `ThumbArt`；`.badge`（`data-comic-thumb-badge`）显示叙事页码。`title` 带状态提示（`（未排版）` / `（尚未生成）`）。
- `ThumbArt({hash})` 用 `useAsset(hash)` 取图。

**关键判断**：
1. **DOM 顺序 = 阅读顺序** —— 数组已排好序，所以 rtl 镜像是「渲染的自然结果」，不需要 CSS `direction`/翻转；而**角标是叙事页码，刻意不随阅读方向镜像**（第 1 页永远是第 1 页）。
2. **对白层不进缩略** —— 缩略只有 ~100px 宽，对白贴纸挤成一团不可读，纯噪声；缩略的语义是「版面 + 画到哪了」。
3. **取图成本 = 已生成格数** —— `assetHash` 缺失即不挂 `useAsset`，未生成的格退回几何占位。不做懒加载/滚动裁剪：一话页数有限，不值得引入交叉观察器。

### M6-10 拖拽翻页

**交付**：
- **domain 纯函数** `domain/comic/reader/dragNav.ts`：
  - `dragAxis(dx,dy)` —— `|dx|>=|dy| ? 'x':'y'`（相等取 'x'）。
  - `dragTurnThreshold(width)` —— `clamp(48,120,width*0.28)`（宽屏按比例，但不失控）。
  - `dragIntent(input)` —— 非横向或 dx===0 返回 `null`；`forward = direction==='ltr' ? dx<0 : dx>0`；返回 `{delta, blocked}`。
  - `dragTurnOffset(input)` —— `clamp(-72,72, dx*(blocked?0.22:0.55))`。
  - `dragTurnVerdict(input)` —— 非横向 / 未过阈值 / 撞边缘 → `null`；否则 `delta`。
- **UI** `ComicReader`：pointer capture 接管拖拽；`data-comic-reader-dragging` + `data-comic-reader-drag-offset` 供冒烟断言；`--read-drag-x` 驱动 `transform: translateX()`；新增「也可左右拖拽翻页」提示。

**关键判断**：
1. **绝不允许出现第二套翻页语义** —— 拖拽复用与 `readerNav`（按钮/键盘）**同一套「屏幕方向 → 叙事增量」映射**，所以左撇子/RTL 下按钮、键盘、拖拽三者永远一致。这是本组最容易埋雷的地方。
2. **纵向手势不劫持** —— `dragAxis` 判定为 'y' 即不跟手、不出判定，把滚动交还容器（`.stage` 设 `touch-action: pan-y`）。
3. **撞边缘有阻尼（0.22）而非完全不动** —— 首页往回拖 / 末页往前拖时仍给一点位移反馈（上限约 31），让用户「摸到边界」而不是以为卡死；但 `verdict` 恒 `null`，不会翻。
4. **`prefers-reduced-motion` 保留跟手、只去掉过场** —— 跟手是「操作反馈」不是装饰，去掉反而更难用。
5. **「卷页 / 3D 翻折」真实翻页刻意不做** —— 纯装饰、成本高、且 reduced-motion 下必然退化；收益撑不起复杂度。

### 跨层改进：修掉 mock 通道的验证盲区

M6-8 留下的坑——`platform/channels/mock.ts` 产出 `bytes = TextEncoder.encode('mock-asset:<hash>')` 却标 `mime:'image/png'`，`<img>` 拿到 `blob:` URL 但**解码出 0 像素**（`naturalWidth===0`），导致「图真的渲染了」离线冒烟**证明不了**，只能靠机制级像素采样绕过去。

本次**改为输出真实 8×8 灰块 PNG**（72 字节 base64 常量 + `atob`），`width/height = 8`。**收益**：`naturalWidth === 8` 从此是**可信断言**，G34 直接用它证明「缩略底图真的解码渲染了」，不再需要任何 hack。视频仍是假字节（没有依赖解码的断言）。

**教训沉淀**：**假数据的保真度决定断言的上限**。假字节 + 真 mime 是最危险的假数据——它让「链路看起来通了」却悄悄废掉了一整类断言。
