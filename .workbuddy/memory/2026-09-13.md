## M6-23 素材导入链路（画布，§6.3 / §6.8）—— 用户实测报的缺陷（不在对账清单里）

- **触发**：用户实测「生成节点无法导入素材、画布也无法导入素材」。而清单里**没有这一项**——因为文档 §6.8 状态 A 明写「点击 `+` 或拖入文件可上传」，**「文档写了」被当成了「已实现」**。
- **★★ 缺陷一：生成节点 `+` 点了没反应（静默失败）**。`pickFile` 给 File System Access 传 `types = { 'image/png,image/jpeg,image/webp': [] }` —— 把 HTML `accept` 的**逗号串整个当一个 MIME key**；浏览器按规范判非法抛 `TypeError: Invalid type`，外面 `try/catch` 吞成 `null`，调用方当「用户取消」直接 return ⇒ 无报错、无提示、什么都不发生。修法两层：① `acceptToTypes` 按逗号拆 + 查 `EXT_BY_MIME` 产出规范形态 `{ accept: { 'image/png': ['.png'] } }`；② `isUserCancel`（**仅 AbortError**）区分「取消」与「出错」——**只有取消才返 null**，其余一律降级 `<input type=file>`。
  **通则：catch 里返「空/默认值」= 把异常降级成静默；凡"用户主动动作后界面无变化"的 bug，先查是不是异常被吞。**
- **★ 缺陷二：画布根本没有导入入口**。此前只有「往现有生成节点塞图」，新建素材节点要先建空节点再点 `+`。补：顶栏「⬆ 导入素材」（落**视口中心**，`screenToWorld`）+ **拖文件到画布空白**（落拖放点；多文件按 `size.w + 24` 横向排开；非媒体跳过并 `notify('跳过 N 个文件：只支持图片 / 视频素材')`；拖入时 `data-import-hover` 1px 虚线内描边）。
- **两条入口共用一份实现**：新 `features/canvas/importAsset.ts`（`importAssetFile` 读文件→指纹入库→读原始像素；`createAssetNode` 建节点并包 `beginPlan/endPlan`）。此前这段是 `useCanvasPageEvents.handleUpload` 里的内联代码 ⇒ **无法被第二处复用，正是「画布没有导入」长期没人补的结构性原因**。区别只在落点：节点 `+` 写回 `assetHash`，画布导入新建节点。
- **素材节点按原始比例定尺寸**：新纯函数 `domain/canvas/layout/assetNodeSize.ts`（缩到最长边 320 → 撑到最小 200×160）；**极端长条比例退回最小尺寸**——2000×40 撑到最小高度会算出 12000px 宽。「数学正确、体验灾难」要显式挡掉。
- **★★ 故障注入验证断言有效性**：把旧的逗号 key 临时改回去 ⇒ G52 立刻红 2 项；改回复绿。**绿的时候「断言恒真」与「断言有效」长得一模一样，必须注入故障才能区分**（沿用 M6-20 像素断言的手法）。
- **其余易踩点**：`draggedFiles(e)` 只看 `Files` 类型（拖文本/连线时不能劫持）；撤销按钮有 topbar + 撤销条两个 ⇒ `.first()`；画布建生成节点路径是 `[data-toolbar-add]` → `[data-toolbar-menu-item="generation"]`（顶栏没有 ＋生成）。
- **★ 整批导入只占一步撤销，踩到嵌套计划的陷阱**：`createAssetNode` 原每调用一次自包 `beginPlan/endPlan`，而 store 的 `activePlan` 是**单个变量** ⇒ 嵌套 begin 后内层 `endPlan()` 提前把外层计划关掉，后面的节点各自变独立撤销单元（拖 5 张要按 5 次 Ctrl+Z）。修法：`createAssetNode` 加 `ownPlan`（默认 true 给顶栏单文件），拖放由调用方整批开一次、内部传 false。**通则：`activePlan` 式计划不可嵌套；且计划区间内别夹 `await`（先异步取齐素材、再同步建节点）。**
