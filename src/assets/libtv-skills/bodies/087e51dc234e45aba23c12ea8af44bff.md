# 北岛口播视觉包装｜红蓝小人手绘信息图

## 做什么

把口播稿或字幕文件转成一套连续的手绘信息图解释画面：

- 按语义拆分镜头，不机械地一句话只配一张图；
- 用红色小人、蓝色小人、简单道具和箭头解释因果、步骤、对比与变化；
- 先生成静帧和视频提示词，用户确认后再制作动态；
- 保持人物、道具、颜色、线条和空间关系连续；
- 输出静帧、透明素材、准确文字、动态片段和口播对应清单；
- 使用 LibTV 官方能力完成生图、生视频、项目管理和下载。

这个 Skill 只使用下述红蓝小人手绘信息图风格。不要把参考图片中的其他画风带进结果。

## 固定视觉系统

### 背景

- 使用干净、均匀的暖米白或浅奶油色背景；
- 允许极轻微的纸张颗粒，但不能形成旧纸、脏污或强纹理；
- 保持大面积留白，让人物和道具成为视觉主体；
- 只使用轻微的浅米色接触阴影帮助物体落地。

### 线条和造型

- 使用稳定、圆润、略有手绘感的粗黑轮廓线；
- 人物、道具、卡片和箭头使用同一线条粗细逻辑；
- 造型扁平、简单、友好，像知识类儿童绘本与现代信息图的结合；
- 人物比例略可爱，但不要幼儿化、Q 版化或夸张大头；
- 面部只保留黑色圆点眼睛、短眉和简单嘴形，不增加写实五官。

### 固定配色

- 背景：暖米白；
- 主角色与问题、投入、行动：高识别度红色；
- 接收者、结果、工具、信息载体：明亮蓝色；
- 强调、按钮、灯泡和关键节点：少量黄色；
- 轮廓、头发、鞋子和必要结构：黑色；
- 裤子、卡片内部和辅助区域：米白或白色。

不要添加紫色、粉色、绿色大色块或复杂渐变。特殊语义确实需要其他颜色时，只能少量使用并保持红蓝黄仍为主色。

### 固定人物

在同一项目中建立并复用角色设定：

- `R 红色小人`：黑色短发、红色长袖上衣、米白长裤、黑鞋；代表讲述者、操作者、问题发起者或输入端；
- `B 蓝色小人`：与 R 相同的圆润人体比例，蓝色上衣或简化蓝色身体、米白长裤、黑鞋；代表观众、接收者、理解结果或输出端；
- 支持人物只在必要时出现，使用米白、黑线和少量红蓝，不建立新的主角色。

近景可以显示简单头发和五官；远景允许把人物进一步简化成红蓝色块与黑线。不要在连续镜头中改变角色发型、服装、体型和主色。

### 信息图语言

优先使用：

- 红蓝小人之间的投入、传递、观察、修复和理解动作；
- 圆形、方形、三角形、卡片、箭头、流程线和步骤编号；
- 简单机器、传送带、文件、屏幕、灯泡、按钮和工具；
- 左到右、上到下或前后状态对照；
- 一屏一个主要信息关系，最多三个信息层级。

### 严格禁止

- 撕纸边缘、拼贴纸片、胶带、图钉、剪报和贴纸边框；
- 海报排版、复古广告、杂志拼贴和定格纸片动画质感；
- 粗糙破损边缘、强烈投影、纸片层叠和手工剪贴阴影；
- 写实照片、3D 渲染、黏土、毛毡、塑料或高光材质；
- 满屏装饰、复杂场景、过多道具和无关氛围元素；
- 平台 UI、Logo、水印、伪文字或未经要求的标题。

如果生成结果出现以上特征，判定为风格失败并定向重做。

## 需要什么输入

最少提供：

1. 一份完整口播稿；或
2. 一份 SRT、VTT、ASS 字幕文件。

可选提供：

- 内容参考图片、产品截图或需要解释的对象；
- 画面比例，例如 4:3、9:16、16:9；
- 是否需要透明底、准确中文按钮或指定人物位置；
- 是否先确认图片，再继续生成视频；
- 已有 LibTV 项目 UUID 或项目目录。

用户提供的图片默认只用于理解内容、人物动作或道具，不用于改变固定画风。只有用户明确要求修改这套红蓝小人视觉系统时才讨论风格变化。

不要要求用户填写复杂表格、标注每张图片或解释设计术语。只有文本缺失、素材无法读取或内容本身无法理解时才追问。

## 默认设置

- 静帧比例：`4:3`；用户明确指定时覆盖；
- 图片模型：LibTV `lib-image-2`；
- 图片画质：`quality=medium`，即标准画质；
- 图片分辨率：`resolution=2K`；
- 图片数量：每个节点 `count=1`；
- 视频模型：LibTV `star-video2-mini`，即 Seedance 2.0 Mini；
- 视频分辨率：`720p`；
- 普通镜头：`4～5 秒`；
- 多阶段变化镜头：`8 秒`；
- 声音：轻微、真实、与动作同步的道具或环境音效；
- 音乐：不要 BGM；
- 人声：不要旁白，不要新增对白；
- 文字：长句不交给生图模型；准确中文优先后期渲染。

每次正式生成前读取 LibTV 当前模型列表和 schema。模型键变化时选择同名后继模型并说明，不静默换成其他档位。

## 工作流程

### 1. 按语义拆稿

识别：

- 开场问题或钩子；
- 困难、原因、方法和结果；
- 定义、步骤、清单、因果、对比和流程；
- 抽象概念与具体案例；
- 章节切换、结论和行动引导。

不要按标点机械切镜。一个句子包含多个状态时拆成 2～4 个连续镜头。

例如“文章写完了，交给 AI，图很漂亮，但观众没看懂”应拆成：完成文章、送入 AI、漂亮图片输出、观众困惑。

例如“红色小人投入杂乱信息，右侧逐渐产出清晰结果，蓝色小人获得灵感”应使用首尾状态或 8 秒多阶段镜头，不能压缩成一张无过程的静态图。

有字幕时间轴时使用真实时间码。没有时间轴时只记录段落顺序，不伪造精确时间。

### 2. 建立分镜表

为每个镜头记录：

- 镜头编号，例如 `B001`、`B002`；
- 对应口播原句或字幕时间码；
- 观众看完画面必须理解的意思；
- R 与 B 的角色分工；
- 人物动作、道具和信息流方向；
- 需要继承的角色、道具和场景；
- 画面类型：整画面、步骤图、透明叠加、章节转场或 CTA；
- 静帧提示词；
- 视频模式、时长、动作节拍、声音和禁止项。

视觉事件数量由语义复杂度决定，不为凑数量生成装饰图。

### 3. 先交付确认稿

默认先展示：

1. 分镜拆解；
2. 每张图解释的意思；
3. 图片提示词；
4. 视频提示词与时长建议。

用户说“直接生成”“可以，出图”时继续生成静帧。用户一开始已经明确要求直接执行时，不重复确认。

### 4. 编写静帧提示词

每个提示词必须包含：

- 语义目标；
- R 与 B 中实际需要的角色；
- 一个主要动作；
- 道具、箭头和信息结构；
- 主体位置、信息流方向、留白和安全区；
- 上一镜头需要继承的元素；
- 固定视觉锚点；
- 严格禁止项。

固定视觉锚点直接复用：

```text
干净暖米白背景，轻微均匀纸张颗粒，圆润粗黑手绘轮廓，扁平红蓝黄限定色，简单友好的红色小人和蓝色小人，现代知识信息图，留白充足，只有轻微浅米色接触阴影。非照片、非3D、非拼贴、无撕纸、无贴纸、无强阴影、无水印、无无关文字。
```

连续镜头复用同一角色描述。人物不必固定在左侧；根据语义使用居中、左右对照、前后状态或流程式构图。

### 5. 处理透明底和准确中文

用户要求“只保留人物和道具”“无背景”“透明底”时：

- 优先使用支持透明输出的图片能力；
- 不支持时在均匀 `#00FF00` 键控背景上生成；
- 抠除后检查 RGBA、边缘毛刺、绿色溢色、阴影断裂和内部误抠除；
- 交付透明 PNG，并生成浅灰或米白预览图；
- 透明素材仍必须保持红蓝小人固定造型。

准确中文按钮、字幕或 CTA：

- 先生成无字按钮或预留区域；
- 再用可靠文字渲染器叠加准确文本；
- 检查每个字、标点、居中、字重和安全边距；
- 错字、乱码和伪文字不可交付。

### 6. 准备 LibTV 项目

只使用 LibTV 官方 CLI 或平台能力，不调用旧 OpenAPI。

执行前检查：

```powershell
libtv --version
libtv model search --type image
libtv model lib-image-2
libtv model search --type video
libtv model star-video2-mini
```

整套镜头放在同一个项目中。静帧和视频节点使用 `B001` 等统一编号。继续修改时复用原项目和节点，只更新发生变化的部分。

### 7. 选择视频模式

使用单图生视频，当：

- 只有一个清楚动作；
- 构图和物体数量基本不变；
- 4～5 秒能够表达完整。

使用首尾帧生视频，当：

- 有“空白 → 产出”“问题 → 修复”“无灵感 → 灯泡出现”；
- 人物、物体数量或空间关系改变；
- 需要锁定最终结果；
- 单图模式容易让角色或道具变形。

复杂镜头使用 8 秒并分阶段描述。例如：

```text
0～2秒：R 把杂乱纸张和图形投入左侧入口，右侧保持空白。
2～4秒：信息沿通道移动，只有轻微纸张晃动和机械卡嗒声。
4～6秒：右侧依次出现三张清晰步骤卡，不同时爆发出现。
6～8秒：B 看到结果后抬头，头顶黄色灯泡点亮并停留。
```

### 8. 编写视频提示词

视频提示词包含：

- 保持暖米白、粗黑线和红蓝黄限定色；
- 锁定 R、B 的造型、颜色和位置关系；
- 一条主动作，复杂镜头分阶段；
- 摄像机固定或只做克制移动；
- 首尾停留区；
- 轻微真实动作音效；
- 无 BGM、无人声、无新增文字、无水印；
- 禁止角色漂浮、肢体扭曲、道具融化、颜色突变和镜头乱推拉；
- 禁止动态过程中出现撕纸、拼贴、贴纸弹出或纸片翻转。

通用声音句：

```text
加入轻微、真实、与动作同步的纸张摩擦、脚步、按钮点击、机械卡嗒或物体落下声，音量克制。不要BGM，不要旁白，不要人声，不要夸张卡通音效。
```

若视频编码不保留 Alpha，先把透明 PNG 合成到暖米白背景上。不要承诺普通 H.264 视频保留透明通道。

### 9. 生成与下载

- 图片默认使用 `lib-image-2`、标准画质、2K、1 张；
- 视频默认使用 `star-video2-mini`、720p、1 条；
- 先生成一个代表镜头检查红蓝小人风格，再批量执行；
- 只重做失败或用户指出的节点；
- 命令超时但已有任务 ID 时查询原任务，不重复创建；
- 成功必须有完成状态、100% 进度和有效 URL；
- 按平台权限下载并如实说明水印。

## 质量检查

### 静帧

- 画面是否解释了口播，而不只是好看；
- R 与 B 的服装、体型、头发和主色是否连续；
- 背景是否干净暖米白；
- 是否只有红蓝黄主色和稳定粗黑线；
- 是否错误出现拼贴、撕纸、贴纸、剪报或强投影；
- 道具数量、空间关系、人物肢体和信息流是否正确；
- 是否出现错字、伪文字、Logo、水印或平台 UI；
- 透明素材边缘是否干净。

### 视频

4～5 秒镜头检查开头、中间、结尾。8 秒镜头检查 `0/2/4/6/8 秒`五个状态。

确认：

- 动作顺序和口播因果一致；
- 关键结果没有提前出现；
- 最终状态完整且停留足够；
- R、B 和道具没有漂移、变形或凭空增减；
- 动态过程没有风格漂移成拼贴或 3D；
- 准确中文全程稳定；
- 音效轻微真实，无 BGM、无人声；
- 首尾没有突然截断。

修正顺序：文字和事实 → 语义 → 人物连续性 → 固定风格 → 构图 → 动作节奏 → 装饰细节。

```text
project/
```

最终交付：分镜表、图片和视频提示词、2K 静帧、按需生成的透明 PNG、章节转场、步骤图、CTA、Seedance 2.0 Mini 720p 动态片段、LibTV 项目链接和质检说明。

## 什么时候问用户

- 文本为空或文件无法读取；
- 内容存在多种解释且会明显改变分镜；
- 用户要求改变固定红蓝小人画风；
- 用户要求复刻受保护角色、Logo、水印或身份特征；
- 默认先给分镜和提示词确认，除非用户已经明确要求直接生成。

除此之外使用默认设置继续，不重复询问已经给过的信息。

## 边界

- 不把模型生成的长段中文当最终字幕；
- 不伪造数据、日期、因果关系或精确时间码；
- 不复制参考图片中的水印、平台 UI 或账号标识；
- 不读取、展示或上传 LibTV 登录凭据；
- 不无差别重做整套项目，优先定向修改失败节点。
