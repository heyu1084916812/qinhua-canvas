# 动画番剧完整制作工作流（剧本 → 资产 → 视频 + 色调）

本技能是三个本地开发模块的总协调层，负责按顺序驱动一条完整的产线：
```

剧本创作模块 → 资产识别生成模块 → 视频生成与后期色调模块 (animation-series-scriptwriting) (asset-recognition-generation) (video-generation-color-grading)

```

本技能自身不重新定义剧本格式、资产模板或色调库规则；它只负责：阶段排序、锁定交接、缺口检查、以及最终把三个模块的产出汇总成一份可直接使用的完整影视交付包。三个模块各自的详细规则以其自身 `SKILL.md` 为准：

- `../animation-series-scriptwriting/SKILL.md`
- `../asset-recognition-generation/SKILL.md`
- `../video-generation-color-grading/SKILL.md`

## 何时启用本技能

用户要"一条龙""全流程""从剧本直接做到视频提示词""帮我把这一集从头做到尾"时启用本技能。用户只提到某一段（例如"只要资产提示词""只要剧本"）时，直接进入对应单模块技能，不要套用本总控流程。

## 核心原则

1. **锁定交接**：上一模块必须产出"已锁定"结果，下一模块才可以消费它；不得在资产或视频阶段反过来修改剧本事实、人物设定或场景设定。
2. **不跨阶段跳跃**：除非用户明确说"跳过确认，直接走完整条流程"，否则每个模块内部的确认协议（见各模块 `SKILL.md` 的"阶段确认协议"）依然生效。
3. **不重复定义**：色调、镜头、资产模板等具体规则只存在于对应模块，总控层不复制、不改写这些规则，只做引用和调度。
4. **缺口即停**：任何一个模块声明输入缺失（例如资产模块发现剧本没写清角色性别，视频模块发现没有场景资产），先在当前阶段停下来向用户澄清或标记"待确认"，不得替用户编造剧情、人物或资产事实。
5. **全局账本**：跨模块维护一份精简的"总账本"（见下），避免人物、道具、色调在模块之间漂移。

## 总体阶段流程

### 阶段 0：立项与范围确认

在进入模块一之前，先确认：

- 本次目标：单集 / 多集 / 一季试播 / 单一场景验证；
- 目标时长与集数；
- 题材路线、基调、受众；
- 是否需要跳过某些确认环节以加快产出（默认不跳过）；
- 最终交付形态：只要视频提示词投喂，还是要完整分析过程。

将这些写入"总账本"的顶部，作为后续三个模块共享的项目背景。

### 阶段 1：剧本创作（调用 animation-series-scriptwriting）

按 `animation-series-scriptwriting/SKILL.md` 的六阶段工作流（脑洞 → 故事核心 → 人物 → 季度/分集结构 → 细纲锁定 → 好莱坞格式剧本）执行，严格遵守其"阶段确认协议"和"细纲锁定协议"。

本阶段结束标准：拿到至少一集"好莱坞格式剧本"，并通过该模块自带的"剧本一致性审计"。

产出必须归档为：

- 已锁定的人物设定表（姓名、性别、年龄感、外观、关系、弧光）；
- 已锁定的场景/道具事实（只要剧本中出现的，不需要单独审美加工）；
- 已锁定的分集细纲；
- 好莱坞格式剧本正文。

未完成剧本一致性审计之前，不进入阶段 2。

### 阶段 2：资产识别生成（调用 asset-recognition-generation）

把阶段 1 锁定的剧本原文、人物表、场景/道具事实作为唯一输入，按 `asset-recognition-generation/SKILL.md` 的五步流程执行：资产盘点 → 去重 → 摘要 → 三类模板路由（男性角色 / 女性角色 / 场景与道具）→ 输出资产卡。

强制规则：

- 只从阶段 1 的剧本事实提取资产，不得新增剧情或角色；
- 男性、女性角色分别走各自模板，场景与道具单独编号；
- 性别、年龄、身份不明确时标记"待确认"并回到用户，不擅自补全为确定事实。

本阶段结束标准：交付一份完整的"资产识别总表"+ 逐条资产卡（含连续性锚点），且所有"待确认"项已由用户澄清或明确接受低风险默认方案。

未清空关键"待确认"项之前（尤其是主要角色和主要场景），不建议进入阶段 3；如用户坚持先走完整条流程看效果，可继续但需在最终交付包中保留待确认标记。

### 阶段 3：视频生成与后期色调（调用 video-generation-color-grading）

把阶段 1 的剧本 Beat／分镜、以及阶段 2 已批准的角色资产卡、场景资产卡、道具资产卡作为输入，按 `video-generation-color-grading/SKILL.md` 的五阶段流程执行：输入审计 → 视觉单元拆分 → 视频提示词生成 → 后期色调选择 → 连续性审计。

强制规则：

- 视频单元里引用的角色、场景、道具必须是阶段 2 已产出的资产卡，不得在此阶段临时新造资产或重新设计外观；
- 不在本阶段修改剧本事件顺序、人物动机、台词核心内容；
- 全剧建立一个主色调，每集最多一个辅助色调，色调切换必须有剧情/时空依据；
- 连续性审计要覆盖角色、道具、光源、色调与声音。

本阶段结束标准：交付"剧集色调总表" + 全部"视频单元提示词"，并通过连续性审计。

## 总账本（跨模块维护）

每次进入新阶段前，先检查并更新以下账本，而不是重新发明：

- **项目背景**：题材、受众、基调、目标时长、集数范围（阶段 0 产出，全程不变，除非用户明确修改）；
- **人物账**：姓名、性别、年龄感、关系、目标、弧光位置、当前外观状态（剧本模块建立，资产模块细化外观，视频模块继承状态）；
- **世界与规则账**：力量/科技/魔法系统边界、阵营、代价规则（只在剧本模块写入，后续模块只读不改）；
- **资产账**：每个角色/场景/道具的资产卡编号、连续性锚点、状态版本（资产模块建立，视频模块继承并在单元间追踪状态变化）；
- **色调账**：主色调、辅助色调、适用集数与切换条件（视频模块建立并维护）；
- **待确认清单**：跨模块尚未拍板的事项，注明卡在哪个阶段、谁需要回答。

任何模块发现要修改上游已锁定的账本内容（例如视频阶段发现某道具状态和剧本矛盾），必须先停下来，说明影响范围，等待用户确认后再回退到对应上游阶段修正，不允许在下游模块里静默改写上游事实。

## 标准执行顺序（供本技能内部自查）

1. 阶段 0：确认项目背景，写入总账本。
2. 阶段 1：调用剧本创作模块，走完六阶段直到"好莱坞格式剧本"+一致性审计通过；把关键结果写入总账本。
3. 检查点：剧本是否已锁定？未锁定则停留在阶段 1。
4. 阶段 2：调用资产识别生成模块，只用阶段 1 锁定内容做输入；产出资产识别总表与资产卡；把资产账写入总账本。
5. 检查点：主要角色/场景资产是否已批准？关键"待确认"是否已澄清？
6. 阶段 3：调用视频生成与后期色调模块，只用阶段 1+阶段 2 的锁定结果做输入；产出视频单元提示词与剧集色调总表；把色调账写入总账本。
7. 检查点：连续性审计是否通过？

## 最终交付包

用户要求"完整交付"或走完三阶段后，默认汇总输出：

```text
【完整影视工作流交付包】

一、项目背景
（题材、受众、基调、时长、集数范围）

二、剧本产出（模块一）
- 已锁定人物设定
- 已锁定分集细纲
- 好莱坞格式剧本正文
- 剧本一致性审计结果

三、资产产出（模块二）
- 资产识别总表（男性角色/女性角色/场景/道具）
- 逐条资产卡（含最终三维资产提示词与连续性锚点）
- 待确认清单（如有）

四、视频与色调产出（模块三）
- 剧集色调总表（主色调/辅助色调/切换条件）
- 全部视频单元提示词（按剧情顺序排列）
- 色调与连续性审计结果

五、总账本快照
（人物账、资产账、色调账、待确认清单的最终状态）
```

用户要求"直接投喂"时，只输出第二～四部分中的最终可复制提示词（剧本正文、资产提示词、视频单元提示词、色调参数），略去分析过程和账本细节；用户要求"方案选择"或"分阶段看"时，按阶段 1→2→3 顺序分批呈现并等待确认，不一次性甩出全部内容。

## 明确边界

- 不在总控层重新发明剧本格式、资产模板字段或色调参数体系；具体规则始终以对应模块的 `SKILL.md` 和 `references/` 为准。
- 不允许资产模块或视频模块反向篡改已锁定的剧本事实；也不允许视频模块反向篡改已批准的资产设计。
- 不把三个模块的输出强行压缩成一次性长文本而跳过用户的阶段确认，除非用户明确要求跳过确认快速看整体效果。
- 不在任何阶段凭空新增角色、道具、地点、特效或剧情反转。
