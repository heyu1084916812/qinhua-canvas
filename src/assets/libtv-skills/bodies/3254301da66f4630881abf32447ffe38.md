## name: prompt-director-skill description: 根据参考图、简短描述、情绪词、人物设定或场景概念，生成具有明确观看关系、事件阶段、主体层级、尺度锚点、明暗骨架、叙事压力和媒介质感的图片提示词，并默认分别交付原始中文 Image Prompt 与适配 Midjourney 当前语法的英文 Prompt。用于文生图、图生图、风格与色调复刻、电影剧照、真实抓拍、硬闪时尚摄影、巨构废墟、灾难科幻、暗黑幻想、边缘空间、建筑环境概念图、动漫分镜、CG/游戏概念图、插画及一致性镜头组规划；尤其适合画面只有元素描述、缺少导演关系、视觉阅读顺序或宏观空间设计时。

# Cinematic Narrative Image Director

## Core Principle

先分析导演关系，再压缩成可生成的自然语言 prompt。

不要只描述画面里有什么。先确定谁在看、从哪里看、为什么现在看、事件发展到哪一步、观众先读到什么、光线揭示或隐藏什么；再补人物、环境、前景、动态、纹理、色调和媒介参数。

导演分析可以很细，但最终生成稿保持中等密度、关系明确、色调集中，并给模型留下构图和细节空间。导演关系是骨架，写实摄影、幻想、灾难、动漫、CG 和插画是不同的表现媒介。

## Default Output

用户未指定格式时，默认分别输出两个版本：

```text
【Image Prompt】
2-4 段中文自然语言，可用于通用文生图或继续修改。

【Midjourney Prompt】
1 段经过重排和压缩的英文 prompt，必要参数统一放在末尾。
```

Image Prompt 按以下结构组织：

```text
第一段：画幅 + 媒介/风格 + 场景 + 谁在看 + 从哪里看 + 事件阶段。
第二段：第一视觉主体 + 动作/情绪 + 为什么是现在 + 关键环境信息。
第三段：光线来源与作用 + 前景/背景关系 + 叙事压力 + 动态与纹理。
第四段：符合媒介的镜头、景深、线条、材质、渲染、色调或成像质感。
```

允许合并为 2-3 段，但不要压成一句参数串。Midjourney Prompt 不逐字翻译，而是保留同一导演意图后重新组织成模型容易解析的英文视觉短语。用户提供参考格式时，优先匹配用户的密度和段落感。

两个版本必须表达同一幅画面：主体、观看位置、事件阶段、第一视觉、光线、色调和媒介不能互相漂移。

## Output Modes

- 默认模式：分别输出【Image Prompt】和【Midjourney Prompt】，两者都可直接复制。
- 极简模式：用户说“极简版”“短一点”“抽卡”时，Image Prompt 输出 1 段；Midjourney Prompt 仍输出对应的英文单段。
- 详细模式：用户说“详细版”“分析版”“结构版”时，先展示导演关系和媒介选择，再补双版本 prompt。
- 多镜头模式：每个方案至少改变观看身份、镜头位置、事件阶段或第一视觉落点中的一项，不要只更换焦段。
- 镜头组/组图模式：先提取统一的世界、人物、设计语言、色调和材质不变量，再为每一帧分别写完整 prompt。除非用户明确要求拼贴或联系表，不要把多个镜头塞进一张图。
- 单平台模式：用户明确说“只要 Image Prompt”或“只要 Midjourney”时，才省略另一版本。
- 用户只提供参考图且未说明需求时，先简短分析参考图角色和可见特征，再给默认 prompt。

参考图本身是多格拼图、概念板或镜头联系表时，先判断用户想复刻的是单帧气质还是整组镜头语言。需要整组时读取 references/shot-family.md。

## Missing Information

非关键细节缺失时，根据上下文做克制推断并直接输出。只有当媒介、主体身份或数量、时代、画幅、事件阶段、参考图用途或必须保留的内容会明显改变结果时，才向用户确认。

## Director Workflow

按以下顺序在内部完成判断，不要把问题清单原样输出：

 1. 识别参考图角色与不变量：编辑目标、身份、构图、色调、材质、世界观或风格参考。
 2. 选择主媒介：写实摄影、写实幻想/科幻、灾难、动漫、CG/游戏概念图、插画或混合媒介。
 3. 确定叙事主体类型：人物、环境、建筑、物体或现象。人物不一定是主角，也可以只是尺度锚点。
 4. 确定谁在看：参与者、同行者、躲避者、旁观者、远观者、固定设备或客观镜头。
 5. 确定从哪里看：摄影机可存在的位置、距离、方向以及合理遮挡。
 6. 确定为什么现在看：动作未完成、信息刚出现、危险将抵达、结果刚显现，或静止空间正处于不安的潜伏状态。
 7. 选择一个事件状态：预兆、潜伏静止、首次破裂、持续升级、临界转折、刚刚结束或长期余波。
 8. 建立第一视觉主体和最多三级阅读顺序。
 9. 选择一个主要叙事压力：接近、阻断、遮蔽、尺度、矛盾、画外原因、时间压力或巨大空旷造成的压迫。
10. 先规划大明暗形状、空间层次和尺度梯度，再让具体光源、动态和纹理证明上述关系。
11. 补充符合媒介的镜头、渲染、线条、材质和色调语言，先完成中文 Image Prompt。
12. 在不改变导演关系的前提下，把 Image Prompt 转换为 Midjourney 英文结构并添加必要参数。

复杂场景、灾难、悬疑或多镜头规划时，读取 references/directorial-relations.md。

## Prompt Density

默认 prompt 必须保留这些生成必需信息：

- 画幅和媒介/风格。
- 核心场景与一个明确事件阶段。
- 镜头从哪里看，以及观看者与现场的关系。
- 主体是谁，处在画面哪个大致区域，在做什么。
- 主体的动作、情绪和“为什么是现在”。
- 第一视觉落点与一个主要叙事压力。
- 环境或巨构画面中的明暗骨架、空间层次和尺度锚点。
- 关键环境和道具，但不要列成清单。
- 光线来源、落点、遮挡和叙事作用。
- 与媒介一致的摄影机、线条、材质、渲染或笔触设置。
- 色调、对比、饱和度和成像/合成质感。
- 目标为真实拍摄时，加入少量有场景依据的拍摄损失。
- 目标为硬闪时尚摄影时，写清闪光与环境曝光的关系、姿态和造型轮廓。

不要只写“很电影感”“很高级”“很有氛围”“很有故事”。把感受翻译成可见的空间、动作、光线、材质和因果。

## Observation First

优先写镜头如何观察主体，而不是只写主体和背景。明确观看身份、摄影机位置、距离、前景遮挡和空间层次。

特殊角度必须有理由。极低视角、俯视、过肩、门缝观察、反射、监控、长焦远观、强透视或倾斜构图应改变权力、距离、危险或信息量，不能只是视觉装饰。

## Subject And Reading Priority

先确定第一视觉主体，再安排其他元素和奇观。主体可以是人物，也可以是空间、建筑、自然现象或巨大异常。通过面积、轮廓、焦点、受光、色彩对比、动作方向或遮挡后的揭示建立优先级，不要求人物必须居中。

人物是叙事主体时，脸部、眼神、手势、轮廓或关键动作至少保留一项清楚可读。人物只是尺度锚点时，可以很小，但轮廓必须足以说明空间尺度。第二眼补充原因、威胁或结果；第三眼最多保留一个延迟发现的信息。不要设置三个同样响亮的视觉中心。

## Why Now And Event Stage

一张图只选择一个主要阶段或状态。不要把灾难前、发生中和结束后同时塞进一帧。非灾难场景可以是人物准备开口、刚听见回答、转身离开、情绪余波，或功能已经停止但危险与记忆仍潜伏在空间里的静止状态。

“为什么是现在”必须留下可见证据：未完成的动作、沿明确方向传播的危险、刚落下的粉尘、正在熄灭的灯、人物尚未来得及完成的反应，或结果刚被发现的瞬间。

## Narrative Pressure

叙事压力不是让画面更吵，而是让观众意识到这一帧之前或之后必然还有事情发生。只选择一个主要来源：危险逼近、退路被堵、原因被遮挡、尺度悬殊、平静动作与异常背景矛盾、画外原因只留下后果，或动作即将改变结果。

背景必须明确承担原因、威胁、结果或空间证据中的一种角色，不能只是壮观装饰。

## Light, Space And Visual Life

写清光从哪里来、经过什么、落在哪里，以及它揭示或隐藏什么。让光承担暴露人物、延迟揭示威胁、划分安全与危险、显示烟尘厚度、强调尺度或制造错误安全感的作用。

在复杂环境中先建立明暗骨架，再描述光效：把画面压缩成 2-4 个大明暗形状，决定最亮区域的唯一预算、主要暗部如何包围空间，以及一处强调色落在哪里。不要让所有窗户、火焰、屏幕和天空同时发亮。

把前景、动态、呼吸感和特殊视角当成可选工具。画面过平时增加合理前中后景；人物像摆拍时使用未完成动作、发丝、衣角、重心变化或环境动态；光线太平均时让光经过遮挡、移动或反射；构图太标准时选择有叙事理由的观察位置。

只保留最有效的 1-2 种手法。画面已经清楚有趣时，不要为了复杂继续添加。需要具体前景、动态、呼吸感和角度手法时，读取 references/photographic-craft.md 的相应部分。

## Texture As Evidence

纹理不是单纯颗粒或“细节丰富”，而是世界发生过什么的证据。选择 1-2 类：物质纹理、空气介质、时间痕迹或媒介成像纹理。

裂缝、焦痕、潮湿、粉尘、灰烬、热浪、新鲜断面、旧污垢、植物侵入、动漫合成层和 CG 材质响应都必须服务事件阶段、空间距离或主体状态。不要同时堆叠雨、雾、火星、颗粒和镜头污渍。

环境设计还要保持材质家族一致：先规定主要结构材料、次要磨损方式和一种异常介质，再让新旧、干湿、光滑与粗糙形成对比。不要让每个表面使用完全不同的随机纹理。

## Avoid Over-Locking

一条 prompt 只建立一个主要观看关系、一个事件阶段、一个第一视觉主体、一个主要压力来源，并只锁 1-2 个强镜头条件。强条件包括低机位、仰拍、缝隙观察、强前景遮挡、人物位置、具体手势、焦段、光圈和特殊背景物件。

保留关系、因果和气质，少规定唯一答案。不要同时锁死精确机位、焦段、人物位置、手势、光源、遮挡和所有背景物件。

## Medium Routing

先选择媒介，再使用对应语言。写实摄影使用焦段、景深、快门、胶片和拍摄损失；动漫使用分镜、线条、赛璐璐或厚涂和图形化光影；CG 使用资产层级、材质区分、PBR 响应和体积介质；插画使用形状、透视、笔触、边缘和色块节奏。

幻想、科幻和灾难不是单一媒介：先选择写实、动漫、CG 或插画，再加入世界规则、物理传播方向、尺度和事件阶段。非写实或混合媒介请求必须读取 references/medium-routing.md，不要把摄影规则机械套用到所有风格。

目标为巨构、废墟、边缘空间、灾难环境、暗黑幻想场景或建筑概念图时，必须读取 references/environment-concept-art.md。

## Photographic Mode

目标为真实照片、电影剧照、生活抓拍或参考图真实拍摄感时，读取 references/photographic-craft.md。保留焦段、光圈/景深、手持或静态状态、胶片与镜头质感、具体色彩关系和少量摄影损失。

真实感优先来自合理动作、材质、空间、光线和摄影位置，拍摄损失只是辅助。通常只选择 1-2 种局部损失，并确保眼神、表情或关键动作仍然清楚；不要把真实等同于整张图故意拍糊。

目标为车内、夜景、奢华造型、直打闪光、杂志感人物或闪光冻结与环境拖影并存的时尚画面时，必须读取 references/editorial-fashion.md。这类画面不默认使用柔和自然光和浅景深生活抓拍逻辑。

## Reference Image Workflow

先判断参考图角色并写清必须保留和允许改变的内容。涉及人物时，优先确认身份、脸部、发型、体型、姿态和服装中的不变量。

在内部拆解十层：

 1. 参考图角色和不变量。
 2. 影像媒介、世界规则和情绪。
 3. 谁在看、从哪里看、前景如何遮挡。
 4. 为什么是现在、事件阶段和叙事压力。
 5. 叙事主体类型、第一视觉落点和最多三级阅读顺序。
 6. 大明暗形状、空间层次、尺度梯度、虚实和留白。
 7. 光源、落点、遮挡和最亮区域预算。
 8. 摄影机、线条、材质、渲染和适度损失。
 9. 白、黑、高光、阴影、对比、饱和度和强调色预算。
10. 若为镜头组，哪些世界、人物、设计和色调必须跨帧保持一致。

最终不要把十层做成标题，压进 2-4 段自然语言。

## Named Styles

用户引用电影、摄影作品、动漫、游戏、艺术家或视觉风格时，先拆成可生成特征：时代和场景、人物表演、观察距离、构图、事件密度、线条或材质、光源、色彩、空间、镜头和渲染方式。

不要只依赖作品名称，也不要默认复制具体镜头、演员或角色身份。用户同时提供参考图时，以图中可观察特征和用户明确要求为准。

## Negative Constraints

负面约束匹配媒介和本次失败风险，只在最后加入最关键的短句。写实限制塑料皮肤、商业摆拍、所有区域同样锐利或无依据 HDR；动漫限制真人皮肤、错误透视、线条混乱或无理由 3D 塑料感；CG 限制材质同质化、尺度不明、无意义粒子或过度 bloom。

不要固定加入“不要动漫感”“不要 CG 感”或“不要 AI 感”。把抽象问题翻译成具体可见错误。

## Midjourney Conversion

默认读取 references/midjourney-output.md，将中文 Image Prompt 转换为适配 Midjourney 的英文版本。

按以下顺序组织英文正文：主体与环境 → 观看位置和构图 → 动作与事件阶段 → 第一视觉和叙事压力 → 光线与明暗 → 材质、色彩和媒介质感。使用具体英文名词、动词和空间关系，不输出导演分析问题，不机械翻译中文长句。

参数统一放在正文末尾。至少根据用户画幅添加 `--ar`；只有需要更强提示遵循时才添加 `--raw`，只有需要调整艺术解释程度时才添加 `--s`，只有确有必要时才使用简短 `--no`。不要为了看起来专业而堆参数。

默认不写旧式 `::` 多提示词权重。默认不固定版本号，让用户当前设置生效；用户要求可复现的当前版本时才使用 `--v 8.1`。动漫请求可以按用户意图选择 `--niji 7`，不要同时写 `--v 8.1`。

用户提供参考图但没有可公开访问的 URL 时，不要虚构图片 URL、`--sref`、`--oref` 或 `--iw` 参数。先输出纯文本 Midjourney Prompt；如有必要，在 prompt 外简短说明上传图片后再加入对应引用。

## Detailed Mode

用户明确要求详细版时，可按这些标题解释：

```text
【媒介与世界规则】
【观看关系与事件阶段】
【主体与阅读顺序】
【叙事压力与空间】
【光影、动态与纹理】
【摄影/线条/材质/渲染】
【色调与生成约束】
```

详细版用于解释和推导，最后仍补一版可直接出图的简单版。

## Final Check

输出前检查：

- 是否像导演调度，而不是元素或参数清单？
- 谁在看，镜头为什么能出现在这里？
- 为什么是现在，事件是否只处于一个主要阶段？
- 第一眼读到什么，背景是否抢走叙事核心？
- 主体是人物、环境还是现象？小人物是否只是有效尺度锚点？
- 光从哪里来，它揭示或隐藏了什么？
- 大明暗形状、最亮区域和强调色是否有明确预算？
- 压力来自哪里，画面前后是否仍有事情发生？
- 巨构或环境场景是否有尺度梯度、空间路径和功能/废弃逻辑？
- 前景、动态、留白和特殊角度是否有场景依据？
- 纹理是否证明事件、距离或时间，而不是装饰堆叠？
- 摄影、动漫、CG 或插画语言是否一致？
- 硬闪时尚画面是否处理了闪光冻结、环境压暗、镜面高光和姿态轮廓？
- 镜头组是否保持世界、人物、设计语言和色调不变量，同时真正改变镜头关系？
- 是否自然加入了必要的镜头、色调和媒介质感？
- 是否避免锁死所有构图、手势和物件？
- Image Prompt 是否符合用户要求的密度，并保持 2-4 段可直接生成？
- Midjourney Prompt 是否与 Image Prompt 表达同一画面，而不是重新创作？
- Midjourney 参数是否全部位于末尾、语法兼容当前目标版本且没有无意义堆叠？
