## name: short-drama-dialogue-audio-repair description: 修复短剧、剧情短片、广告或访谈成片中的对白底噪、嗡声、低频震动、齿音、混响、硬切、跨镜声底跳变、句间响度不稳和交付测量问题，并交付可回退的对白轨、环境轨、混音母版、时间码变更表与验收报告。用于已有锁定画面或声音素材的原语声音后期；不用于画面质检、镜头重生成、多语言翻译配音、未授权声音克隆或冒充任意平台合规。

# 短剧对白声音修复

把“听起来有问题”转成带时间码、可复现、能回退的声音后期任务。先救可懂度和连续性，再平衡对白，最后按明确目的地测量；不要用一个降噪按钮或一次响度归一化掩盖所有问题。

开始前按需读取：

- 需要核对标准、来源适用条件或争议时，读取 `references/research-notes.md`。
- 每次交付都读取并填写 `references/deliverable-template.md`。
- 需要参考正常、缺失信息和失败案例时，读取 `references/examples.md`。
- 本地存在 FFmpeg 时，可运行 `python scripts/audio_qc.py <音频或视频>` 生成流信息、响度测量与静音区间初检；脚本结果只是证据，不替代监听。

## 先锁定边界

- 从已有锁定版画面、原语对白或音轨开始，只负责声音后期。不要检查角色、轴线、镜头节奏或画面连续性，也不要重生成镜头。
- 不做翻译改写、目标语配音、口型生成或声音选角；这些属于多语言本地化流程。
- 只处理本人、委托方或明确授权的录音。不得克隆真人、演员、公众人物或客户声纹，不用电影对白、商业音乐或来源不明素材做演示。
- 不承诺“一键消除所有噪声”。修复会损伤辅音、呼吸、音色或表演时，保留原轨并转入替代 take、ADR/重录或接受可控噪声分支。
- ITU-R BS.1770 规定测量方法，不规定所有平台的统一目标。EBU、ATSC、Netflix 或用户平台的数值只能在其适用条件下使用；目的地未知时不得声称“平台合规”。

## 1. 建立输入闸门

先收集：

1. 锁定版视频、帧率、时长、起始时间码和是否仍会改剪；
2. 原始对白、boom、lav、混合轨、音乐、音效、环境声及前后 handles；
3. 台词稿、说话人、优选 take、替代 take、现场录音报告和 room tone；
4. 已知问题、重要表演、允许保留的粗粝程度与不能改变的呼吸、笑、哭或停顿；
5. 交付目的地、声道、采样率、位深、响度、真峰值、文件命名和截止时间；
6. 素材权利、演员重录授权、是否允许合成环境声以及需保留的原始版本。

缺信息时先输出四栏：`已知｜未知｜可逆默认｜阻塞项`。只有视频和混合轨时，可以做标注版初检和低风险预览，但不能虚构分轨、原始 room tone 或平台规格。源片未锁定、素材权利不明、关键台词缺字、目的地未确认却要求合规声明，均属于阻塞项。

## 2. 复制原始素材并建立时间主轴

保留只读原件，所有处理写入新版本。统一项目帧率、采样率、起始时间码和声道映射；先检查整体同步，再判断单句问题。建立事件表：

`ID｜入点｜出点｜说话人｜镜头/场景｜来源轨｜症状｜证据｜严重度｜保留表演｜候选修复｜复检结果`

严重度分为 P0 阻断交付、P1 明显妨碍理解或暴露剪辑、P2 可接受但建议优化。不要把个人偏好伪装成故障。

## 3. 先诊断再处理

至少完成以下证据检查：

- 同步：句首、句尾、切点和下一镜是否一起漂移；
- 完整性：削波、丢字、辅音缺失、数字错误、重复或硬切；
- 噪声：稳定底噪、50/60 Hz 嗡声、低频震动、衣物摩擦、风声、点击和瞬态干扰；
- 音色：boom/lav、距离、角度、房间反射和不同 take 的频谱差异；
- 连续性：每个切点前后约一秒的声底、响度、混响尾音、呼吸和 room tone；
- 混音：对白是否被音乐或音效遮蔽，手机、耳机和单声道是否仍可懂；
- 交付：完整成片的综合响度、真峰值、声道、采样率、位深和文件长度。

一次只改变一个主要变量并做响度匹配 A/B。听感改善但表演、辅音或空间被破坏，视为失败。

## 4. 选择最小修复路径

按以下顺序工作，不要反过来：

1. **换源**：优先选择更清楚的 boom、lav、替代 take 或相邻 handle；
2. **剪辑**：修切点、补前后余量、重排呼吸和自然停顿；
3. **修复**：针对主症状做低频切除、去嗡、局部降噪、去齿音或轻量去混响；
4. **连续**：铺原场景 room tone，做短交叉淡化并匹配音色与混响尾音；
5. **平衡**：先用 clip gain/automation 平衡句子，再少量使用压缩或限制；
6. **交付**：最后才对完整成片执行目标响度和真峰值检查。

无法从现有素材恢复缺失辅音或严重削波时，停止激进处理，输出 ADR/重录清单。不要用生成声音猜台词。

## 5. 修跨镜声音连续性

逐切点对比声底、音色、响度、空间和表演。优先从同场原始素材提取无对白 room tone，放在独立轨并跨过切点；再用短淡化衔接，不要把每个空隙填成绝对静音。没有原始 room tone 时，先寻找相邻 handles 或可授权的现场环境；只有用户允许且不冒充真实录音时，才使用合成或匹配方案，并标记来源。

按麦克风、空间和噪声指纹分组，不机械按角色分组。同一角色跨房间可以不同，同一房间不同角色反而需要共享声底逻辑。

## 6. 平衡对白并选择交付档案

先让相邻台词在正常监听电平下连贯可懂，保留戏剧动态；不要把每句压成同一音量，也不要用 peak normalize 代替对白平衡。对白稳定后，按目的地选择：

- **用户给定规格**：以书面规格为准，记录测量算法和容差；
- **EBU R 128**：仅用于采用该体系的广播或交换，完整节目目标通常为 -23 LUFS；
- **ATSC A/85**：仅用于相应电视、交换或明确采用该实践的流媒体档案；
- **Netflix 品牌内容**：单独使用其对白门控和交付要求，不能外推到一般短剧平台；
- **未知目的地**：只报告当前测量值和“待确认目标”，可给带醒目标记的临时预览值，但不写“已合规”。

响度、真峰值和对白可懂度是不同指标，必须分别验收。

## 7. 按症状做最小修复

始终写成“症状→原因→最小修复→复检”：

1. **切点突然真空** → 删除对白时连同声底一起切掉 → 从同场 handles 补 room tone 并做短淡化 → 盲听切点、查看波形且检查循环感。
2. **两个机位像换了房间** → boom/lav 或距离与混响不匹配 → 先换同源 take，再做轻量音色和早期反射匹配 → 以相同响度 A/B，检查辅音与空间尾音。
3. **降噪后像水下或金属声** → 处理量过大且误伤语音 → 回退到原轨，降低强度或仅处理噪声暴露区 → 独听擦音、齿音、呼吸和句尾。
4. **对白忽大忽小** → 录音距离和 clip gain 未整理 → 先逐句 automation，再少量压缩 → 在手机、耳机和单声道连续播放，不只看表头。
5. **越播越不同步** → 帧率、变帧率、采样率或时间基准错误 → 先修项目基准并重新对齐整段 → 检查首句、末句和每个切点，禁止逐句随机偏移。
6. **有嗡声但去除后人声变薄** → 50/60 Hz 及谐波与人声低频重叠 → 只对稳定频率做窄带处理并保留原轨 → 复听低声部、爆破音和环境自然度。

## 8. 输出可复制交付包

严格按 `references/deliverable-template.md` 输出：

1. 已知/未知/默认/阻塞项；
2. 权利与源文件清单；
3. 问题时间码表和修复决策表；
4. 接缝与 room-tone 地图；
5. 原始保留轨、修复对白轨、环境轨、必要 stems 和完整混音；
6. 完整成片的响度、真峰值、声道、采样率、位深、同步与文件长度报告；
7. A/B 抽检记录、未解决项、ADR/重录清单和版本回退点。

## 9. 三类前向测试

- **正常输入**：锁定视频、分轨、台词、room tone 和交付规格齐全；必须生成可执行事件表、修复链、真实音频交付和验收报告。
- **信息缺失**：只有一条混合视频和“把对白弄清楚”；不得虚构源轨或合规数值，先给初检、可逆预览、缺失项和停止条件。
- **约束冲突**：要求克隆未授权演员、用电影对白做样片、彻底消噪且绝不改变音色、目的地未知却保证合规；拒绝侵权或虚假承诺，给原声最小修复、授权重录和待确认规格替代。

任一测试缺少真实交付物、违背用户约束、把临时值写成标准、破坏台词或无法回退，都先修改再重测。

## 10. 验收与停止条件

至少完整播放一次，并抽检每个说话人首句、末句、最快句、最低声句、情绪峰值和所有切点。可观察验收标准：关键台词无丢字或可感知漂移；切点声底不突变；无新增水声、金属声、点击或泵动；音乐与音效不遮蔽对白；原轨可恢复；文件长度与锁定画面一致；报告数值与所声明档案一致。

出现以下任一情况立即停止并报告：素材或声纹权利不明、源片未锁定、关键辅音或整句缺失、严重削波无法恢复、同步漂移无法由现有素材定位、不同空间无法合理匹配、修复伪影比原噪声更明显、需要演员重录却无授权，或用户拒绝为物理限制放宽任何约束。
