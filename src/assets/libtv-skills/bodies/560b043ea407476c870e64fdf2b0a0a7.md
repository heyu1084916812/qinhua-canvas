# 故事板 Skill

## 这个 Skill 做什么

用户输入任意形式的剧本内容（文档 / 故事 / 要求 / 一句话），Skill 分两个阶段处理：**阶段一**建立全局锚点；**阶段二**逐条生成每条视频的故事板与视频。

> 📁 **文件依赖说明（必读）**：本 Skill 由五个文件组成——`SKILL.md`（本文件，流程主干 ＋ 生成参数 ＋ 第零阶段改剧本 ＋ 阶段一/阶段二）、`SKILL-rules.md`（全局禁止规则 28 条 ＋ 迭代记录）、`SKILL-style.md`（画面风格与电影级词库）、`image-prompt.md`（图片侧模板正文与口径）、`video-prompt.md`（视频侧规则与示例）。
>
> 🔴 **后两个文件需按需加载**：本文件不复述模板正文，凡写「模板正文见 `image-prompt.md` / `video-prompt.md`」处，**执行到该处时必须先用 `skill_file` 加载对应文件再动手**，禁止凭印象或凭记忆替代原文；模板与后缀模板**必须从对应文件原样复制**（逐字复用、拼完回读比对）。

## 生成参数（默认值固定，可按需切换）

| 类型 | 模型（默认） | 画质/分辨率（默认） | 比例（默认） |
| --- | --- | --- | --- |
| 图片（三视图/故事板） | Lib Image 2.5 Pro | 低画质 1K | 16:9 |
| 视频 | Seedance 2.0 Fast（2.0 mini） | 480p | 4:3 |

> 所有图片生成（三视图和故事板）默认使用 Lib Image 2.5 Pro 低画质 1K 16:9；所有视频生成默认使用 Seedance 2.0 Fast 480p 4:3。
>
> 🔄 **弹性（不是锁死，是按需切）**：上表是**默认值**，不是「永久固定」。当本次任务有明确需要时——例如需要更高画质出海报级三视图、需要竖屏 9:16 用于短视频、或用户指定了其他模型——**可以按需切换模型 / 画质 / 比例**，切换原则见下。
>
> - **切换时机**：① 用户明确指定；② 该条产出用途要求不同画幅（如竖屏短视频、方形封面）；③ 默认画质不满足某类高精度需求（如角色海报、需放大印刷的定妆图）。除此之外一律沿用默认值，不得为「显得高级」擅自升级画质浪费积分。
> - **切换纪律**：切换**只改参数、不改流程**。模型/画质/比例变了，其余步骤、模板、口径、负面框、校验规则全部不变。
> - **切换须留痕**：一旦切换，在账本该条备注里写明「参数切换：原默认 X → 现 Y，原因 Z」。

### 参数字段落地口径（避免 schema 拒绝）

- 图片 `quality` 字段**只填 `low`**（平台 schema 允许值：low / medium / high / xhigh / max）；**禁止**把「低画质 1K」这类描述性文字直接写进 quality 字段——那是给人看的口径，不是字段值。分辨率 1K 由模型默认档位承载，不需要也不应在 quality 里表达。
- 视频的「无音乐」由**两个字段共同实现**：`sound: on`（保留环境音与对白——本 Skill 必写的「环境音设计」与「台词承载音频与口型」两项的载体）＋ `need_bgm: false`（只关背景音乐）。**不得**把 sound 设为 off——那会连环境音与对白一起丢掉，与 `video-prompt.md` 的「环境音设计必写」「台词是音频与口型」直接冲突。
- 自检口径：**`need_bgm: false` 管的是音乐，`sound` 管的是这条视频有没有声音**，两者不是同一件事。

## 第零阶段：改剧本（可选，按需触发）

> **这个环节是干什么的**：用户给进来的剧本，常常是「小学生文本」——有情节没张力、有对话没冲突、人物动机不清、情绪压不下来。本 Skill 不能拿这种文本直接进故事板，那等于把一个「没立起来的骨架」拍成「没立起来的成片」。改剧本这一步，就是把粗糙文本**升级成有戏剧张力的成片剧本**，是后面所有环节（锚点、切分、故事板、视频）的地基。
>
> **什么时候触发**：步骤0 入口问询里新增一问「是否要改剧本」——用户选「要」则执行本环节；用户选「不要」或已提供成熟剧本，则跳过本环节，直接进阶段一。**判断原则：剧本是「成品」还是「素材」**——成品（已立骨架、有冲突、对白能立人物）不改；素材（流水账、报幕式交代、对白只会说事不会演戏）则改。

### 改剧本的六条工法（本厂实测，来源：契诃夫/特鲁比/陆军/麦基/Succession，逐字读正文）

改剧本不是「润色辞藻」，是**把戏立起来**。按以下六条逐项过，缺哪补哪：

1. **先立「核心冲突」，不写流水账**：先问一句「这出戏，谁想要什么、谁挡着、为什么非要现在」——这是全剧的发动机。没有这三问，后面再改都是缝补。**特鲁比四角对立**：主角之外，还要有**对手、假盟友、副对手**——光主角 vs 反派是单薄的，权谋戏尤其要「六角对手同时开火」（Gangster 类型节拍）。
2. **对白是行动，不是说明**：每一句台词都要「逼对方回应、推动事情往前走」，删掉所有「报幕式交代」（角色用台词告诉观众「我是谁、我在哪、我要干嘛」）。**麦基场景五步**：每个场景要有「价值转折」——人物带着一个「正值」进场，离开时变成「负值」（或反之），无转折的场景要么删、要么并。
3. **情绪外化，不写内心形容词**：不许写「他很愤怒」「她很悲伤」，要写成身体动作——「攥紧的拳头」「别过脸去」「声音低到几乎听不见」。观众看的是身体，不是情绪名词。
4. **羞辱向下传导（Succession 工法，群像/权谋最对口）**：写不出下一场戏时，问「刚才谁被羞辱了？他身边最弱的人是谁？」——权贵的恶不会悬空，它总砸在更低处的人身上，这就是下一场戏。
5. **道具贯穿链（陆军《桃花扇》工法，历史剧以小见大）**：找一件能反复出场的物件（一柄扇、一枚印、一封信），让它在关键转折处**每次改换身份**——第一次是定情信物，第二次是罪证，第三次是遗物。一件道具七次改身份，比七个新道具更有力量。
6. **删「画蛇添足的升华」**：结尾不喊口号、不点题、不解释「这告诉我们什么」。**契诃夫三层结尾**：事情结束了，但情绪没落地，留一个「还在继续」的余味。戏演完了，人还在路上。

### 改剧本的硬边界（守住，否则改坏）

- **改「戏」，不改「史实与人物立场」**：不得改变历史事实、人物立场、核心事件与情节走向。改的是「怎么把已有的戏演出来、演得有力」，不是「另编一个新故事」。
- **戏剧化与史实的边界判据（防止「加冲突」和「守史实」打架）**：戏剧化改写**可以**补人物动机、给对白上钩子、把流水账改成有冲突的场景、把情绪压成身体动作；**不可以**虚构历史事件、篡改人物立场、添加史实里没有的关键人物或关键事件节点。一句话判据——**「把已有的戏演得更狠」是允许的，「编一个史实里没有的戏」是不允许的**。拿不准某处改动是否越界时，**只改表达、不动事实**，并在这处改动旁标注，交给用户回读时定夺。
- **不擅自扩写新情节**：除非用户明确要求，否则**只强化已有冲突、补人物动机、给对白上钩子**，不新增用户剧本里没有的人物和事件。
- **改完必须回读给用户**：改剧本的结果（改前/改后对照，或直接是改写稿）**必须呈给用户确认**，用户点头后才进入阶段一。这是「剧本」这一环的人工把关点，不静默改、不静默替换。
- **改后产物落文件**：改写稿写入 `scripts/<剧名>-compressed.md`（与压缩稿同路径，作为阶段一的输入），不得只留在对话上下文。

## 第一部分：流程

### 阶段一：全局锚点建立（整个剧本只做一次）

**工作文件约定（固定三处路径）**

| 产物 | 路径 |
| --- | --- |
| 压缩稿与切分摘要 | `scripts/<剧名>-compressed.md` |
| 锚点清单（含出镜过滤名单、画面风格、角色形象描述） | `anchors/<剧名>-anchors.md` |
| 进度账本 | `progress/<剧名>-ledger.md` |

- 三份文件在**阶段一四步串行期间即建立并写入**，**不得只存在于对话上下文**。
- 断点续做时**先回读这三份**；**不回读账本不得开始任何动作**。

**步骤0：入口问询**（阶段一开始前，**一次合并选项卡问询，不逐题追问**；结果写入 task/memory，**全程有效、不重复问**）

① **对白语言**：中文 / 日语 / 英语 / 自定义
② **是否有整体时长目标**：无 / 3 分钟内 / 5 分钟内 / 自定义（选「有」→ 触发台词压缩规则，压缩前须向用户说明）
③ **剧本内容确认**：用户已在消息中提供剧本则**跳过此项**
④ **是否要改剧本**：要 / 不要（选「要」→ 触发第零阶段「改剧本」，把粗糙文本升级成有戏剧张力的成片剧本；选「不要」或已是成熟剧本 → 跳过，直接进阶段一）

**强制串行顺序**（不得与图片生成调用并行）：

> 1 任务初始化（分析输入、识别人物/场景/风格）→ 2 角色出镜前置过滤（确定建图名单）→ 3 锚点集写入（输出锚点清单全字段）→ 4 任务状态更新（确认清单就绪）。**四步全部完成才可发起图片生成调用。**

**步骤1**：自动分析输入内容，识别人物、场景、风格信息。

**步骤2：角色出镜前置过滤（强制，必须先于三视图生成执行）**

逐一核对每个角色在全剧本中**是否有实际出镜镜头**（动作、表情、特写、正面或任何可辨识出场，含对白镜头及旁白/独白中可辨识的本人形象）。

- **不出镜**：仅在被他人提及、本人从未在画面中出现（如只被提到名字的萧淑妃、太平公主这类角色）。
- **不建图**：仅作无名背景人群，无姓名、无个体辨识度（如群臣、宫女、太监、羽林军这类群体角色）。
- **建图**：真正有出镜镜头、画面中可辨识其本人形象。

处理方式：

- **不出镜**或**不建图**的角色：**一律不生成三视图**，只在锚点清单中登记为「角色（不出镜/不建图）」，节点Key 与提示词填「—」，**不创建任何图片节点，避免浪费积分**。
- **建图**的角色：进入步骤3，创建并生成三视图。
- 过滤结果**必须以「建图名单 / 不建图名单」形式明确列出**，作为步骤5 输出锚点清单的输入；**未完成本步骤，不得发起任何三视图生成调用**。

**步骤3：生成人物三视图（角色锚点）**，全剧本复用：**仅对判定为「建图」的角色执行**。

将 agent 整理的角色形象描述与 **`image-prompt.md` 中的「三视图提示词模板」正文**组合后作为 prompt 发送给生图模型；**模板正文、七槽位映射与填充示例见 `image-prompt.md`，执行前必须用 `skill_file` 加载该文件，模板正文逐字复用、不得凭印象复述**；**不得让生图模型自行决定排版或风格**。

**角色形象描述写法（强制规范）**

- **只写画面可见特征、不编造**：不得臆造剧本与史料均无依据的信息。
- **输出形式**：写成**一段话**，不分行、不列点、不加小标题。
- **严格按 9 项顺序**写成：

  | 序号 | 项目 | 写作要求 |
  | --- | --- | --- |
  | 1 | 年龄感与族裔 | 年龄段（青年/中年/老年等）与族裔外观特征 |
  | 2 | 头发 | 发型、发色、发质、束发或披发等可见形态 |
  | 3 | 胡须 | 有无胡须及类型（长须 / 短髭 / 无须） |
  | 4 | 脸型与面部年龄感 | **剧本优先**；剧本未写则**上网查史料、画像记载**；**有依据才写、不得凭空编造**；**禁止千篇一律套用「鹅蛋脸」一类默认词**；不同角色之间必须可区分 |
  | 5 | 表情 | 该角色惯常或在该剧情中的表情 |
  | 6 | 外套 | 外层服装的形制、颜色、材质 |
  | 7 | 内搭 | 内层衣物的形制、领型、配色 |
  | 8 | 整体气质 | 整体呈现的气质感受 |
  | 9 | 职业/身份/背景 | 写**客观身份**（如朱元璋是皇帝），属事实陈述 |

- **依据来源优先级**：剧本原文 > 网络史料/画像记载 > 无依据则不写（第 4 项查不到依据时只写面部年龄感，不得为凑项目编造脸型）。
- **儿童安全（涉及未成年角色时强制）**：禁止「**未成年数字年龄 ＋ 身体围度/身形尺寸词 ＋ 暴露服装**」三者同时出现；年龄一律改用**学龄气质词**（总角年纪 / 垂髫之年 / 少年 / 学童气质），**不写具体岁数、不写身体围度与贴身暴露描述**。该约束同样适用于**锚点清单中的角色提示词**与**三视图模板槽位填充**（槽位映射见 `image-prompt.md`）。
  - **（区分口径）**该条款约束的是**外貌描述与三视图槽位**（不写未成年数字年龄、不写身体围度、不写暴露服装）；**剧本原文中出现的数字年龄台词（如「你才十四岁」）属于台词，按「逐字保留原文、不节选」规则处理，不受本条限制、不得删改**。两者分工：外貌侧用学龄气质词（豆蔻年纪／总角年纪等），台词侧照原文——**同一角色可以台词说岁数、外貌不写岁数**。
- **锚点名称与三视图标签**必须使用剧情原文人物原名（如郑成功、揆一），不得用自行概括的描述性称谓。
- 生图参数：**Lib Image 2.5 Pro / 低画质 1K / 16:9**。
- **三视图的作用**：保证故事板中人物形象一致，作为参考图传入故事板生成（阶段二步骤4）；阶段二步骤6 生成视频时作为角色板 reference 直接传入，锁定长相、服装与细节一致性。
- **创建即已就绪**：三视图无上游引用，节点 node_key 创建后即可被下游引用；创建下游不必等它出片，只有实际运行下游才要求已生效。**该要求只决定提交时机，不构成流程门禁**（见全局禁止规则「禁止混淆创建节点与运行节点的前置条件」）。

**步骤4：提炼画面风格** → 输出为统一文字提示词（**不生成色彩参考图**），全剧本复用。

**写法指引（强制）**

- 必须按以下基线措辞：**35mm 电影焦段**；**自然漫射生活光为主光（光源＋方向＋色温写死，不留给模型猜：主光写明「来自哪、什么方向、什么色温」，如「窗外天光从左侧漫射，约 5600K」）**；**暖调自然保留、不做冷调纠偏**；**平实通透、无柔光滤镜、无 halation、无光雾**；**中等对比、暗部干净（不死黑、不压暗）**；**中等景深、保留空间纵深**；**35mm 干净胶片温润密度、不脏不做旧**；整体为**克制平实的日常凝视温度**。
- **禁止使用「暗部压重高光克制」这类压暗、往死黑走的措辞**，出现即改写为「中等对比、暗部干净不死黑」一类表述。
- 本指引**只约束文字写法，不新增任何资产类型**，不引入 moodboard 风格锚、纯环境空景场景图或白底道具合图；「禁止单独生成场景锚点」「故事板是场景/道具/环境唯一视觉底本」两条保持不变、不得削弱。
- 画面风格仍只输出为**一段统一文字**，全剧本复用，不生成色彩参考图。

**电影级增强（可选，仅在用户明确要「电影感」时叠加，默认不启用）**

- 上述基线是「克制平实的日常凝视温度」，**默认照此执行，不得因「电影感」三个字擅自改掉**。当用户明确要求「像电影」「有电影感」时，才在基线之上**叠加一段五变量技术词块**，叠加项不替代基线、只做增强。
- 🔴 **核心结论（一句话记死）**：「电影感」不是写「高级/史诗/电影感」这类形容词，而是写 **5 个可控变量：镜头（lens）→ 灯光（lighting）→ 调色（grade）→ 胶片（stock/纹理）→ 运镜（movement）**。五变量写成一段技术词块，效果远超堆十句情绪形容词。多来源一致：**「密度＞长度」「具名光源＞具名情绪」「报导演名只占 20%，技术簇占 80%」**。
- 🔴 **完整词库见 `SKILL-style.md`**：五变量英文词表、导演风格→技术簇拆解表、10 个可直接粘贴的 LUT 风格块、写法顺序、三条避坑、七条硬约束，**全部原样放在 `SKILL-style.md` 分册**（为控制单文件不超过 2 万字符而拆分）。**执行电影级增强时先加载 `SKILL-style.md` 取词，不得凭印象复述。**

**步骤5：输出锚点清单**

| 字段 | 说明 |
| --- | --- |
| 锚点名称 | 该锚点的名称 |
| 锚点类型 | 角色/风格等（**不含场景类型，不单独生成场景锚点**）；不出镜/不建图角色填「角色（不出镜/不建图）」 |
| 节点Key | 对应节点的 Key；不建图填「—」 |
| 提示词 | 直接用于后续生图/生视频的提示词，非解释性描述；角色锚点须含按 9 项顺序写成的一段话外貌描述（涉未成年须守儿童安全约束）；不建图填「—」 |
| 适用范围 | 全剧本 / 某条视频 |

> 阶段一只建立角色锚点和画面风格，**不单独生成场景锚点图**（场景信息已由故事板分镜自然呈现）；只为**有实际出镜镜头**的角色建图。

### 阶段二：每条视频生成（每条视频重复此流程）

**输入来源**：直接从阶段一输入里按台词字数自动划分，**不重复让用户输入**。

#### 🧭 流程弹性（按复杂度裁减，不是每条都机械走满六步）

阶段二名义上是「每条视频重复六步」，但**六步是上限，不是每条的强制固定步数**。执行前先按本条复杂度判断一次，**简单条目走精简路径、复杂条目才走满六步**——目的是少烧积分、少卡确认、快进快出，而不是每条都一板一眼走完全程。

- **精简路径（简单条目）**：单角色、单一空间、台词短（≤约 45 字）、无权力对峙、无复杂道具交接。这类条目**步骤5 的统一确认可降级**——不必每次都打包三样选项卡确认，改为**与相邻几条合并成一次批量确认**，或在本条明显简单时**一次性放行、仅在账本标注「简单条目，步骤5 降级为批量确认」**。其余步骤（切分、时长、视角、分镜设计表、故事板、视频）**仍照常执行，只裁剪确认环节**。
- **满流程路径（复杂条目）**：多角色同框、权力对峙、多空间切换、长台词、需精确运镜衔接。这类条目**六步一步不缺**，步骤5 单独确认，不得降级。
- **判断权在 agent，但判断必须留痕**：本条走精简还是满流程，**必须写进账本备注**（如「精简：单角色短台词，步骤5 降级批量确认」），不得只在脑内决定。
- 🔴 **边界（防偷懒）**：精简路径**只裁剪「步骤5 确认」这一环**，**不得裁剪**切分、时长计算、视角判定、分镜设计表、故事板生成、视频生成中的任何一环——这些是产出质量的底线，精简的是「人工确认次数」，不是「生成质量」。

#### 🧾 进度账本与断点续做（多条时必须）

- **建立**：处理第一条之前在 task 的 working file 建账本（固定路径见阶段一「工作文件约定」：`progress/<剧名>-ledger.md`；示例 `progress/storyboard-ledger.md`）。
- **逐条登记（每行一条视频）九字段**：条号｜该条台词摘要（或首句）｜台词字数与 duration_sec｜视角｜分镜设计表状态｜故事板节点Key与状态｜统一确认状态｜视频节点Key与状态｜备注。状态取值：分镜设计表＝未做/已做；故事板节点、视频节点＝未创建/已创建/已生效/失败；统一确认＝待确认/确认无误/需调整已修订（搭建模式的取值见下节「🔧 两种执行模式」）。
- **立即回填**：每完成一个动作（做完分镜设计表、创建/提交故事板节点、故事板出图、统一确认、创建/提交视频节点等）**立即回填对应单元格，不攒批**。
- 🔴 **断点续做**：会话中断、重新接手或用户说「继续」时**先回读账本**，从第一条处于「**未生效/未完成**」的环节继续——**不重新划分条目、不重做已确认通过的条、不重复创建已有 node_key 的节点**。
- **版本区分衔接**：某条重建（v2/v3）时在该条备注记下**旧 node_key 与替换/失败原因**。
- **边界**：账本是**进度载体**，不改变任何既有步骤顺序、确认环节与生成规则。

#### 🔧 两种执行模式（搭建 / 生成）

**搭建模式**（用户要求先出蓝图、或明确不生成资产时）：

- 全部节点按本 Skill 口径**创建但不运行**，**零积分消耗**。
- 步骤5 统一确认**不适用**（它把关的是「已产出的故事板图」，搭建期无图）；但**必须在账本该条备注里写明「搭建模式，步骤5 挂起」**，不得静默跳过、不得留空。
- 账本「故事板节点状态」「视频节点状态」填「**已创建（未运行）**」，「统一确认状态」填「**挂起（搭建模式）**」——**这三列在搭建期有确定取值，不是空着**。
- 搭建模式的产物是**可核对的蓝图**：每条的分镜设计表、prompt、引用关系必须齐备，使得后续任何时候切入生成模式都能直接按依赖顺序提交，不需重新设计。

**生成模式**（用户授权运行后）：

- 按「锚点 → 故事板 → 视频」三波提交，同批互不引用的并行（**每批上限 5 个**）。
- **步骤5 在生成模式下恢复强制执行**——每条故事板图出图后、提交该条视频前，打包三样做一次选项卡确认。

🔴 **关键边界**：**两种模式都不改变步骤顺序、不改变任何取值**；模式只决定「是否调用 run_node」与「步骤5 是否生效」。

#### 视频划分规则（强制）

- **不得**按文档幕/场次/章节/段落结构决定视频条数（文档结构仅供参考）。
- 必须将全剧本台词（含对白、旁白、独白）逐字统计，**以 75 字为上限**自动切分为若干条。
- **单条下限**：切分时单条台词**不宜低于 30 字（约 6 秒）**；低于此值的条目应与其相邻条合并（优先并入语义更连贯的一侧），除非该条是剧情上必须独立成镜的收束句或转折句。
  - 🔴 **边界**：合并后**仍不得超过 75 字上限**、仍不得改变 `duration_sec` 的计算口径（字数 ÷ 5）；本条只约束「过碎条目要合并」，**不放宽任何上限**。
- 以自然语义为边界（句末、段落末），不在句子中间强行截断；某句加入后超 75 字则该句**整体划入下一条**。
- 不含台词的纯动作/场景描述段落**合并至前一条或后一条**，不单独成条。
- 切分完后先输出**视频条数与每条台词摘要**供内部确认，再按顺序逐条执行。

#### 台词压缩规则（用户有时长要求时）

若用户明确提出整体时长目标或单条时长上限（含步骤0 采集到的时长目标），切分前先压缩：

- 按目标时长反推全剧本台词总字数上限（**目标秒数 × 5 字/秒**）；
- 在保留核心剧情、关键对白和人物关系前提下，删减次要台词、重复表达与过渡性对白至目标字数内；
- 允许合理改编（合并、精简、重新表述），但**不得改变人物立场、核心事件和情节走向**；
- 压缩后版本作为本次输入，**仍按 75 字/条切分**；
- **压缩前须向用户说明**，并在切分摘要中标注哪些段落做了压缩。

**压缩的取舍纪律（不是机械删字，是「保冲突、砍铺垫」）**：

- **先砍「铺垫与过渡」，后砍「冲突与转折」**：说明性交代、场景过渡、重复表达、寒暄客套——这些是第一批砍的；冲突爆发、价值转折、关键对白、钩子——这些到最后都要保住。**宁可删掉一整段铺垫，也不要把一场关键冲突压缩成一句话带过**。
- **删「说事」的对白，留「演戏」的对白**：报幕式交代（用台词告诉观众发生了什么）可以删；但「逼对方回应、推动事情往前走」的对白再短也要留。
- **压缩不等于稀释冲突**：压完之后逐条回读，确认**每一处价值转折还在**（麦基场景五步：人物带着正值进场、负值离场的那个「转折点」没被砍掉）；若压没了一个转折，就砍别处补回来，而不是让这条戏变平。
- **单条合并时按「语义连贯」优先**：过碎条目合并，优先并入「冲突更完整」的一侧，而不是就近随便并。

#### 前置过滤

每条开始处理前，先检查该条是否含台词或对话；**不含则跳过该条**，不生成故事板和视频，避免浪费积分。

#### 📋 模板与规范的加载时机（按需加载，不预加载）

本 Skill 的模板正文与示例分置两个附属文件，**执行到对应步骤时必须先用 `skill_file` 加载**：

- **`image-prompt.md`**：阶段一步骤3 生成三视图前（取三视图模板正文与七槽位映射）、阶段二步骤3 定景别运镜前（取统一景别档位表、落差规则、统一运镜词表）、阶段二步骤4 拼故事板 prompt 前（取两套后缀模板正文与各自负面框、故事板示例）。

🔴 读到的**模板正文必须逐字复用**，不得转写、缩写专名或凭印象复述。

#### 🚦 不索要图片生成确认

阶段二各步骤**默认按顺序自动推进**。三视图、故事板等图片生成都是常规流程步骤，需要时**按常规流程创建节点并提交生成即可**，**不作为除步骤5 资产与分镜表统一确认以外的前置条件**；被参考节点尚未出片时先提交其生成、待生效后继续提交下游调用，**不主动向用户索要「是否必须先生成图片才能继续下一步」一类确认**，也不因参考图未出片而暂停流程等待授权。

#### 步骤1：计算视频时长

统计该条台词总字数 ÷ 5 得出时长（秒），作为 `duration_sec` 传入视频生成调用。

🔴 **唯一口径**：总时长**只由「该条台词总字数 ÷ 5」决定**，不得用节奏、分镜秒数或其它因素反推改动，也不得为凑镜头时长增删台词；`duration_sec` **必传**。每镜秒数只是该总时长**内部的分配**（见 `video-prompt.md`「剪辑节奏」）。

#### 步骤2：判断视角

整体判断该条适合哪种视角，确定后**整张故事板统一使用、不混用**；不同故事板可各自不同。取值：**POV 第一视角** / **第三视角（电影分镜）**。

🔴 **判定结果必须落纸**：判定结果**必须写入账本「视角」列**，不允许只在脑内判定。**判定为第三视角也要写进账本**——「没写」不等于「默认了」；**账本该列为空即视为步骤2 未完成，不得进入步骤3**。

**判定依据**（避免一律默认第三视角）：

- **考虑 POV**：该条是否有「**只能以主角眼睛看**」的段落——主角独自看、独自走、伸手触摸某物、主观搜寻。
- **一律第三视角**：**对白戏、多人同框、权力对峙**。

该视角同时用于 `video-prompt.md`「整体场景与氛围」的**视角设定**一项，须写明**整条不混用**。

#### 步骤3：产出「分镜设计表」（强制，先于故事板生成执行）

> 🔴 **「分镜设计表」与「剧情原文」不是二选一，是故事板的两半**：**剧情原文负责「每格画什么内容」**（谁、在哪、发生了什么），**分镜设计表负责「每格的技术标注」**（什么景别、什么运镜）。二者拼在一起才是一张完整故事板——剧情原文给画面内容，分镜设计表给每格下方那行「景别：XX / 运镜：XX」。**分镜设计表不单独输出一张表给用户看，而是作为「内部口径」落地成两处**：①故事板图每格下方的技术信息行；②视频提示词分镜时间轴的每镜景别运镜（同词同值）。所以「填进图片提示词的是剧情原文」和「分镜设计表决定每格景别运镜」**并不冲突**——一个是内容、一个是镜头技术，各管一头。

**景别与运镜一律由 agent 决定一次，生图模型不得自行设计**。为本条逐镜列一张表（镜号｜景别｜运镜｜核心动作一句话），作为本条故事板景别与运镜的**唯一事实源**。

- **先加载 `image-prompt.md`**，景别取该文件「统一景别档位表」取值、运镜取同处「统一运镜词表」取值（运动方向：`推 / 拉 / 摇 / 移 / 跟 / 升 / 降`，稳定性：`手持拍摄`）；不得自创第三种叫法。
- **镜号**从「01」起顺序编号，**行数即本条故事板格数（= 镜头总数量）**，每格照填该行取值。
- **落差规则**制定本表时即须满足：相邻镜头景别**明显不同（至少隔一档）**；同一景别不算有效切换；跨多档只要**有叙事理由**即正当（不是暴跳）；同景别静静停留则**不切、一镜到底**（数档口径与示例见 `image-prompt.md`「落差规则」）。
- **落差必须逐对实际校验并留痕**：相邻两镜在统一景别档位表上**逐对**数档，确认「景别明显不同」；跨多档时确认「有叙事动机」。**禁止**只在 prompt 里写一句「落差按隔一档执行」当作已完成校验。
- **格数范围 2\~9**：由剧情自动决定，不得少于 2 或多于 9（短台词条目按实际剧情只需 2\~3 格，不必为凑格数虚设镜头）。
- **表只管故事板，不管视频条数**：分镜设计表是**故事板的镜头清单**（决定格数、逐格照填，保证图片侧与视频侧同词同值）；视频分镜时间轴是**剧情演出脚本**（按剧情与时长写，可有选择取用格子，不要求逐格对齐）。两者**不是同一份清单的两个副本**。
- **表必须落文件**：本表**必须作为独立产物写入账本或工作文件**（逐镜：镜号｜景别｜运镜｜核心动作），**不得只内联进故事板 prompt 就算完成**。
- 表产出后**直接继续进入步骤4**，不停顿索要「是否必须先生成图片」一类确认。

#### 步骤4：生成故事板（模板与示例见 `image-prompt.md`）

**分镜照填**：每格下方技术信息行的「景别：XX / 运镜：XX」**逐格照填步骤3 表取值**（镜号即格序、行数即格数），生图模型**不得自行设计或更改**。

**子步骤 4-A：命名与占位符替换**（仅用于命名，不进入 prompt 剧情叙述部分）

- 从该条剧情原文提取 **4\~8 字剧情概括**，与固定词「故事板」＋该条**全局两位阿拉伯数字序号**拼合。格式：**剧情概括 + 故事板 + 两位编号**，不加括号或分隔符，从「01」顺序递增，**只标当前编号不标总条数**。
- **重新生成时的版本区分规则**：新版本命名**必须与旧版本有明确区分**。
- **加载 `image-prompt.md`**，按该条判定视角二选一取用后缀模板正文（POV 第一视角版 / 第三视角电影分镜版，**不得混用**），并替换：`[故事板名称]`、`[画面风格]`（取阶段一步骤4 产出）、`[镜头总数量]`（取步骤3 行数即本条格数）；两套模板各带自己的独立负面框，按所选视角取用对应那一份。
- 该名称同时作为**图片文件名**保存，用于归档排序。

**子步骤 4-B：七维度检验、拼接并发送**

拼接前先对该条剧情原文逐项核对七个维度是否已含：

| 维度 | 说明 |
| --- | --- |
| 场景 | 地点、环境、空间特征 |
| 道具 | 画面中出现的物件 |
| 光线 | 光源方向、强弱、质感 |
| 色彩 | 主色调、色温、饱和度倾向 |
| 构图 | 画面布局、主体位置、前后景关系 |
| 摄影机 | 角度与运动：机位高低、拍摄角度、运镜方式 |
| 声音 | 环境音、动作音效、对白氛围 |

- 规则：**原文已有描述的直接使用不修改**；**缺失维度由 agent 按剧情语境补全**。
- **补全写法规则（正反两条，分别对应两类文本，不得混读）**：
  - 🔴 **剧情叙述段：禁止维度标题行**。补全内容必须**自然融入叙述、写成一段连贯画面描述**，**严禁**出现「场景：」「道具：」「光线：」「色彩：」「构图：」「摄影机：」「声音：」等维度标题行。
  - ✅ **技术参数段：允许维度标题行**。阶段一画面风格文字、各模板独立负面框与版式规格说明，**允许并鼓励**用「光线：」「质感：」「色彩：」这类维度标题行分段标注。
  - 两条的边界判据只有一句：**写的是「画面里发生了什么」（叙述）就禁标题行；写的是「生成的技术规格/约束」（参数）就可用标题行**。
- **正确写法**（要求）：厦门中军帐内，夜色深沉，烛火摇曳，暖黄光源将墙上挂满的海图映得忽明忽暗。正中一张巨大的台湾地图格外醒目，图上山川河流、港口城郭皆用朱笔标注，佩刀插于地图之上，令箭置于帅案一侧。
- **错误写法**（禁止，与上例同素材对照）：`场景：厦门中军帐内部，夜晚，低矮营帐空间。道具：巨大台湾地图、朱笔标注、佩刀、令箭。光线：烛火摇曳，暖黄光源。` ——**把补全写成维度标题行，就是把一段连贯画面描述拆成清单，画面感丢失、生图模型只能逐条对号入座拼贴，故严禁**；正确做法是像上一条那样把这些信息自然织进一段叙述里。
- 补全完成后将**本条台词内容（含压缩改编版本若有）与补全内容合并**，再与完成替换的**后缀模板**（正文见 `image-prompt.md`）拼接作为 prompt 发送，同时把角色锚点图作为参考图**实际传入**（reference node）。
- 🔴 **模板逐字复用与回读比对（防漏字）**：模板正文与后缀模板**必须从 `image-prompt.md` 原文原样复制**，禁止凭印象复述、禁止转写、禁止缩写专有名词（例：画面风格里的「柘黄」不得写成「黄」、「halation」不得写成「哈雷」）；拼接完成后**必须回读比对**——把 prompt 中的模板段与 `image-prompt.md` 原文逐句核对一次，确认无漏字、无改写、占位符只剩已替换的三处。
- **创建即已就绪**：创建故事板节点只要求角色锚点已有 node_key（哪怕尚未生成）；只有实际运行才要求已生效。**该要求只决定提交时机、不构成流程门禁**——先按常规流程提交三视图生成、待生效后提交故事板即可，**不得因三视图未出片而暂停流程或索要「是否必须先生成图片」的确认**。
- ⚠️ **拼接规则**：后缀模板文字必须**原封不动**传给生图模型，除 4-A 已完成的方括号占位符替换外模板其余文字原封不动，不得用自己的语言改写。剧情原文允许追加缺失维度补全描述；若用户有时长要求且已执行台词压缩则用压缩改编版本（不再受「原文不得修改」约束）；**无时长要求时原文已有内容不得修改、润色或重新表述**。
- 🔴 **「原文不得修改」的边界（与第零阶段改剧本的衔接，防止自相矛盾）**：这里「原文」指的是**已经过第零阶段改剧本、且经用户确认后的最终稿**。改剧本是**阶段一之前**的事——那时可以改、应当改；一旦进入阶段二拼接，「原文」已是定稿，不得再改。**时序是：先改剧本（第零阶段）→ 用户确认 → 定稿 → 之后一律照稿不改**。不得把「拼接时不得改」误解成「连第零阶段也不许改剧本」，两者不是同一件事。
- 生图参数：**Lib Image 2.5 Pro / 低画质 1K / 16:9**。

#### 步骤5：资产与分镜表统一确认（提交本条视频生成前的人工把关点）

- **时机**：本条故事板图（步骤4）**已产出后**、提交本条视频生成（步骤6）**之前**；**步骤4 生成故事板图的动作本身在确认之前执行**——先出资产再打包确认，不得以「等确认」为由推迟故事板图生成。
- **打包内容（三样一并给出）**：本条**分镜设计表**（步骤3）＋ 本条**已生成的故事板图** ＋ 本条所引用的**角色三视图**（**首条视频时一并展示**）。
- **确认方式**：**一次**选项卡确认，选项「**确认无误 / 需要调整**」，**不逐项分问**。
- 选「**需要调整**」：据反馈修订——先改分镜设计表，必要时据此**重出该条故事板图**，然后**再次确认**；通过才提交该条视频生成。
- 选「**确认无误**」：直接进入步骤6。
- **边界**：该确认是**内容级人工把关**；不得借此索要「是否必须先生成图片才能继续下一步」一类确认，参考图（角色板/故事板）尚未出片时仍按常规流程提交其生成、不因此暂停流程。
- **模式衔接**：本步骤在**生成模式下强制执行**；**搭建模式下不适用**，但必须在账本备注写明「搭建模式，步骤5 挂起」（见〈阶段二·两种执行模式〉与全局禁止规则「禁止静默跳过步骤5」）。

#### 步骤6：生成视频（规则与示例见 `video-prompt.md`）

**先加载 `video-prompt.md`**，按其中的固定格式六段、镜间硬切与分镜时间轴写法、剪辑节奏、皮肤去脏、静态禁写／动态必写、POV 适配、六组负面框、运镜最小公式与正确示例逐项落地；**示例与规则正文必须从该文件读取，不得凭记忆写**。

- 将该条对应的**故事板图节点**和**角色板图节点**同时作为参考图**实际传入**（reference node）。三者分工：**故事板**负责镜头、构图、动作示意和分镜节奏，**定画面结构**；**角色板**作为人物 reference 直接传入，锁定长相、服装和细节一致性，**定人物一致性**；**视频提示词**补充动作、运动、氛围和镜头语言，**定动态表演**。核心公式：**故事板定构图，角色板定人物，视频提示词定动态**。
- ⚠️ **本 Skill 无场景锚点**：故事板是场景/道具/环境的**唯一视觉底本**——参考关系在开头说一次、全程有效；视频按剧情取用，不得脱离该底本另编画面。
- ⚠️ **有选择取用**：视频分镜时间轴按剧情推进写，条数由剧情与时长自行决定，**不要求等于故事板格数**——可只取用若干格，也可把相邻两格演成一镜。**唯一边界**：不得超出故事板已预演的画面范围另编新场景、新环境、新道具。
- ⚠️ **术语同词同值**：景别与运镜取值一律对齐步骤3 分镜设计表与 `image-prompt.md` 两表，不得自创叫法（图片侧写中近景、视频侧不得写特写）；**固定机位是正当选择**，本厂默认手持呼吸感，但需要画面纹丝不动时可写「固定机位 / static shot」；机位不作大幅位移时取「**手持拍摄**」并写人手握持不稳带来的轻微晃动、有呼吸感；**不得把「手持拍摄」写成「跟拍」**（维度区分见 `image-prompt.md`「统一运镜词表」）。
- **视频提示词必须落到的项**（逐项按 `video-prompt.md` 固定格式执行）：
  ① 开头**参考声明块一次说清**——故事板为场景/环境/道具/构图/景别的视觉底本（全程以该图为准、不得自行更改与新增），再按出场顺序逐个声明角色板，**角色板声明句只写类别名**（不附特征关键词、不加括号补充）；
  ② **「整体场景与氛围」段（固定第 2 段，必写）**——环境（定位性一句简述）／光源方向／大气介质／视角设定（沿用本条判定视角、整条不混用），**不得写入质感正向句、不重复配色**；
  ③ **道具**在剧情中出现时点名（名字＋动作过程＋状态，不描述外观、不带格号），该镜没有道具就不提、无须声明；
  ④ **人物**：正文里每出现一个角色，把其角色板 node_key 跟在该角色名字后一次（就地回指）；
  ⑤ 分镜时间轴按剧情推进写（不逐格回指），**必须写动态与时间性信息**，**每条分镜行以「硬切 分镜N（X-Y秒）：」起头、显式断开镜间**（每镜秒数如何分配由 agent 按剧情与总时长判断，不作硬性规定）；
  ⑥ 台词一律写成 `人物说：{台词}`，**逐字保留原文、不翻译、不改写、不节选**；**内心独白／旁白**改用 `内心独白（画外音，不开口）：{内容}`（见 `video-prompt.md`）；
  ⑦ 必须写**环境音设计**，点名本片可闻环境声，并声明「只保留丰富真实的环境音与对白，无背景音乐无配乐」；
  ⑧ **人物实体性常驻声明（与语言锁同级，每条必写）**：`人物全程实体清晰、边缘扎实，动作自然生活化，不摆拍、不对镜、不表演式，无穿模、无肢体融解、无半透明、无多余肢体`；
  ⑨ **皮肤去脏（仅视频阶段）**：必须写常驻声明「人物皮肤干净通透、暗部提亮不脏、肤色均匀无杂色偏色、自然肤质不油腻不磨皮」；**静态外观不复述、动态信息必写**（静态禁写／动态必写的完整判据见 `video-prompt.md`「静态禁写／动态必写」）。
