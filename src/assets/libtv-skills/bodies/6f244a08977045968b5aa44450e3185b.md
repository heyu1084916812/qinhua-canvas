# 东方宫廷写实电影感 · 生图转视频工作流

把一组东方宫廷风格的参考图沉淀成可复用的工艺：统一色调与影像基调、镜头卡结构、九维可选生图提示词，以及「先出图确认 → 再确认运镜/动作 → 最后生成视频」的分阶段链路。

## 铁律（优先级最高）

1. **每个确认门都必须停下等用户回答**，不得替用户拍板。
2. **未经用户确认，不得调用生图工具**；未经图片确认，不得进入视频 prompt 环节；未经视频 prompt 确认，不得生成视频。
3. 一个阶段只做一件事，用户没回话就等，不要「顺手把下一步也做了」。

---

## 一、风格锚点（固定不变，每次生成都带上）

### 1. 影像基调

写实电影感：真实皮肤纹理与布料纤维可见，中低对比、暗部保留细节，轻微胶片颗粒，电影级调色；避免塑料感、过度磨皮、过度饱和与 HDR 味。

### 2. 统一色调（东方宫廷配色，全片一致）

主色用途提示词写法朱红宫墙、红毯、嫁衣、灯笼，作为画面主色块朱红宫墙 / 正红嫁衣红毯鎏金凤冠、妆具、辇轿构件、器皿，作高光金属点缀鎏金凤冠 / 鎏金辇轿墨绿廊柱、帷幔阴影、庭院植被，压住画面暗部墨绿帷幔 / 墨绿廊柱粉牡丹花饰、刺绣、团扇、宴席插花，作柔和过渡色粉牡丹刺绣 / 粉牡丹团扇

用法：**朱红为主色、鎏金为高光、墨绿压暗部、粉牡丹做过渡**。每张图至少出现朱红与鎏金两种，全片不出现这四色之外的突兀色（禁止高饱和蓝紫、荧光色）。同一批次出图必须复用同一段色调描述文字，保证跨图一致。

### 3. 东方美学约束

对称与留白并重、器物纹样讲究（云纹/缠枝/缠头凤饰）、人物仪态端方；构图避免西式现代元素（玻璃幕墙、现代家具、塑料材质）。

---

## 二、镜头卡结构（锚点）

每张图/每个镜头都写成一张镜头卡，命名格式固定：

```
S##｜景别·运镜｜画面内容·叙事功能
```

- `S##`：镜号，按叙事顺序递增（S01、S02…）。
- `景别`：远景 / 全景 / 中景 / 中近景 / 近景 / 特写。
- `运镜`：正面固定 / 仰拍转平移 / 掀帘推进 / 跟随转固定 / 背对微拉 / 平移 / 推近 等；静态图也要写清运镜，供第二阶段复用。
- `画面内容·叙事功能`：人物 + 动作 + 关键道具，并用 `·` 接上这个镜头的叙事作用（建立人物 / 推动出发 / 展示盛况 / 烘托高潮 / 庄重收束 等）。

示例：`S01｜中景·正面固定｜公主端坐凤冠珠帘·通报吉时建立人物`、`S05｜全景·仰拍转平移｜鎏金粉绸凤辇出宫·仪仗展示盛况`。

## 三、分阶段工作流

### 阶段 0｜收集输入

向用户索取：题材与情节要点、主要角色设定（身份/年龄/服饰基调）、本次要出的镜头数量。用户未提供风格参考图时，按本文风格锚点执行；用户提供参考图时，把它作为色调与质感的对齐依据。

### 阶段 1｜拼装生图提示词（确认门 ①）

按下列 **9 个维度**逐项给出可选项，每项 2–4 个具体选项（带简短画面描述），让用户选择或直接输入自定义：

1. **题材** —— 如：公主出阁 / 宫廷夜宴 / 妆成辞母 / 登辇出宫 / 殿前献舞
2. **场景** —— 如：公主闺阁 / 宫门石阶 / 长街仪仗 / 凤辇辇厢 / 百席婚宴大殿
3. **景别** —— 远景 / 全景 / 中景 / 中近景 / 近景 / 特写
4. **构图** —— 居中对称 / 三分留白 / 前景遮挡（帘纱、花枝）/ 纵深框景（廊柱成框）
5. **光线** —— 晨间侧逆光 / 烛火暖调 / 宴席顶光 + 灯笼补光 / 逆光轮廓
6. **色调** —— 朱红为主+鎏金高光 / 墨绿暗部压色 / 粉牡丹柔和过渡（可多选，最终都并回统一配色）
7. **服饰** —— 凤冠霞帔 / 红金绣纹嫁衣 / 侍女素色宫装 / 舞姬粉纱广袖
8. **道具** —— 团扇 / 凤辇与仪仗 / 妆具与铜镜 / 灯笼 / 宴席器皿 / 花枝
9. **人物关系** —— 单人端坐 / 母女相送 / 主仆同行 / 宾客往来 / 舞姬群像

选完后按固定顺序拼成提示词（该顺序即锚点，不要打乱）：

```
[题材] + [场景] + [主体人物与人物关系] + [服饰] + [道具] + [景别] + [构图] + [光线] + [色调] + [东方美学与写实电影感风格锚点]
```

同时输出镜头卡（见第二节格式），一张图一张卡；多镜头时按叙事顺序编号，并给用户看完整提示词与镜头卡清单。

**确认门 ①：把提示词与镜头卡清单完整展示给用户，询问是否调整或确认。用户未确认前，停在原地，不出图。**

### 阶段 2｜生图参数选择并出图（确认门 ②）

用户确认提示词后，给出三组参数选项：

- **模型**：运行时先列出平台当前可用的生图模型供用户选择，不要写死模型名。
- **画面比例**：`16:9` / `9:16` / `1:1`
- **清晰度**：`1K` / `2K` / `4K`

**确认门 ②：展示参数选项并等用户选定。** 用户选定后，按所选模型、比例、清晰度逐张出图，每张图带上阶段 1 确定的提示词与镜头卡命名。

### 阶段 3｜图片确认（确认门 ③）

把生成的图片连同镜头卡一起展示，逐张询问：保留 / 重出（说明要改的维度）/ 替换。需要重出时，只改用户点名的维度，其余提示词逐字不变。

**确认门 ③：用户明确说「图片可以」之后，才进入阶段 4。**

### 阶段 4｜写运镜与角色动作（视频分镜 prompt）（确认门 ④）

基于已确认的图片，逐镜写视频分镜 prompt，每条包含四段，结构固定：

```
镜头卡（S##｜景别·运镜｜画面内容·叙事功能）
+ 运镜：起幅→落幅的运动方式与速度（如「正面固定起幅，缓慢平移过仪仗，落幅在凤辇」）
+ 角色动作：主体在镜头内的动作链与幅度（如「公主抬手掀帘，视线由辇外收回，唇部微动」）
+ 节奏与时长：单镜时长、快慢节奏、与其他镜的衔接（如「庄重铺垫→鼓乐高潮」）
```

运镜与动作要落在镜头卡里写过的「景别·运镜」上，不要另起一套运镜。

**确认门 ④：把全部视频分镜 prompt 展示给用户确认。用户确认前，不生成视频。**

### 阶段 5｜自动生成视频

用户确认分镜 prompt 后，按镜生成视频，并保持与图片一致的色调与画质设定；多镜可收束成一条成片。

**可选环节：BGM。** 询问用户是否需要配乐（如「大婚BGM·庄重铺垫→鼓乐高潮」），需要时再生成音乐并挂到成片下；不需要就跳过，不要默认生成。

---

## 四、推荐分镜组骨架（可泛化结构）

多镜项目按「分镜组」组织，命名格式 `分镜组NN｜场景动作链`（用 `→` 串起该组内的动作顺序），另设两类参考组：

- 分镜组 01｜妆成辞母·吉时→叮嘱→整衣
- 分镜组 02｜登辇出宫·辞别→仪仗→辇中
- 分镜组 03｜百席成婚·赴宴→献舞→入场
- 动态参考｜辇轿跟拍·辇内调度·宴饮蒙太奇
- 音乐参考｜大婚BGM·庄重铺垫→鼓乐高潮

组内的具体场景与动作是槽位，可随题材替换；「分镜组NN｜动作链」这套组织方式与命名格式是锚点。

---

## 五、每次运行的自检

- 每个确认门是否都真的停下等用户回答？
- 提示词是否带全风格锚点（写实电影感 + 四色配色 + 东方美学）？
- 每张图是否都有符合 `S##｜景别·运镜｜画面内容·叙事功能` 的镜头卡？
- 生图前是否让用户选了模型 / 比例 / 清晰度？
- 视频分镜 prompt 是否包含运镜、角色动作、节奏时长？
