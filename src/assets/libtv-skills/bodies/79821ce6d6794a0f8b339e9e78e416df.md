# 爆款短剧剧本创作

## 定位

本 skill 是**爆款短剧 / 剧情短片剧本**的专业创作入口。核心能力：把用户的一句话灵感，通过"爆款拆解 → 灵感接收 → 逐步问询 → 剧本创作 → 文档交付"五步流程，打磨成结构、节奏、爽感对标爆款的单部完整短剧剧本，并为每一场戏配齐**可直接拍摄的专业分镜脚本**。

## 完整工作流

```text
1 爆款拆解 → 2 灵感接收 → 3 逐步问询 → 4 剧情创作与确认 → 5 脚本创作 → 6 文档交付
```

**两段式创作铁律**：问询确定全部细节后，**必须先产出"剧情"（故事大纲），交付用户确认；用户明确确认无修改后，才能进入脚本创作**。不得跳过剧情确认直接写剧本/分镜。

### 步骤 1：爆款拆解（先于创作，必做）

- 使用 `general_search` 联网检索爆款短剧案例与拆解内容（如"短剧 爆款 拆解"、"竖屏短剧 为什么火"、"红果/抖音 热剧 剧本分析"等，可搜索 2-3 个不同关键词并行），收集当前热门的爆款短剧及其"为什么火"的分析。
- 以 `references/bestseller-analysis.md` 的\*\*爆火数据基线（3.6 节，2026 联网验证）\*\*为对标基准，结合检索结果提取 1-3 部代表性爆款，拆出：开场钩子、人设立法、冲突密度、反转时机、结尾钩子；用最新案例交叉验证或更新数据基线。
- 输出一份**内部爆款公式**（不要求单独交付，除非用户要求）：本轮创作将遵循的骨架、爽点节奏、钩子排布、选题依据。
- 若检索不可用或结果不足，直接使用 `references/bestseller-analysis.md` 的公式库与数据基线作为基准，并继续流程，不阻塞创作。

### 步骤 2：灵感接收

- 接收用户的故事灵感 / 点子 / 梗概 / 核心设定。可能是一句话、一段描述或一份上传文件。
- 若用户给的是已有剧本片段要求续写/衔接上一部剧情，先读取并理解其设定、人物与结尾，确保续写无缝衔接（本 skill 单部独立成篇，续写时以用户提供的上一部剧情为前置）。

### 步骤 3：逐步问询（确定剧本设定）

- **问询原则**：像专业策划一样分批提问，**一次最多问 3-4 个问题**，避免轰炸；每轮根据用户回答决定下一轮问题，直到关键要素齐备。
- **推荐必须带分析**：凡向用户给出推荐（题材、元素、梗、设定等），**每个推荐都必须附"为什么推荐它 + 它的爆火原理"**，让用户理解推荐依据；不得只列选项不给理由，也不得用一句"这个火"带过。
- **题材必须推荐全类别选项**：向用户展示 `references/topics.md` 中的全部题材类别（按类别分组列出选项），让用户挑选主题材，可注明可组合副题材；不得只问"你想写什么题材"而不给选项。
- 问询覆盖要素（详见 `references/interview.md` 的完整问题模板与顺序）：
  1. 题材（全类别推荐选择，每项附爆火原理分析）
  2. 核心人物与人物关系
  3. 核心冲突 / 爽点方向
  4. 时长与篇幅（默认由 AI 根据灵感与题材给出最佳时长建议，用户可自定；单部独立成篇，不做合集）
  5. 风格基调（虐恋/甜宠/热血/悬疑等情绪走向）
  6. **整体画面风格**（向用户展示全部画面风格选项并附推荐分析——色调/光线/质感视觉定调，详见 `references/visual-style.md`；确定后贯穿全剧分镜的"光线色彩""场景美术"项）
  7. **网络热梗融入**（询问用户是否要融入网上爆火的梗；用户有意向时，列出适合当前题材/场景的热梗推荐并附爆火原因，详见 `references/memes.md`）
- 用户回答模糊或遗漏时，基于爆款逻辑给出可选项/默认建议，不要反复空问。

### 步骤 4：剧情创作与确认（先出剧情，等确认）

严格遵循七条创作准则（用户指定，不可降级，剧情设计阶段即对标）：

1. **结构对标，形神统一**：情绪推拉、冲突密度、反转时机、节奏排布严格对标步骤 1 提炼的爆款公式，杜绝平铺流水账。
2. **节奏紧凑，零废话叙事**：短剧每一秒都承担剧情与情绪价值，所有内容服务冲突、人设、反转、钩子；删除无效铺垫与冗余台词，矛盾快速落地爆发。
3. **强视听画面适配**：强化人物情绪肢体动作、神态细节、标志性道具行为、可视化冲突场面，适配竖屏短剧镜头呈现，画面感强、张力直观。
4. **合理补全剧情细节**：用户梗概多为精简设定，按爆款节奏逻辑合理补全人物台词、对手反应、冲突细节、情绪递进，让单场剧情完整饱满、逻辑自治。
5. **巧思设计，彩蛋伏笔**：按互联网传播节奏在剧本中埋设彩蛋与伏笔——片尾彩蛋、二刷线索、跨场/跨部伏笔、评论区互动钩子、文化对撞梗等，让内容"越看越有"，激发讨论与转发；设计方法见 `references/easter-eggs.md`，创作时必须落地至少 2-3 处。
6. **热梗融入（按用户意愿）**：用户确认融入网络热梗时，按 `references/memes.md` 的适配规范将梗嵌入台词/情节/包装，控制密度与时效性，硬梗不塞、违和不用；用户未确认前不擅自加入。
7. **细节颗粒度（微表情/动作轨迹/环境动静）**：一切描写细致到可拍可演——人物写清**微表情的连续变化**（眼神/眉/唇/面部肌肉的逐帧递进）与**动作轨迹**（起点→路径→终点、速度、停顿、重心、手部细节）；环境写清**风吹草动与物体反应**（风怎么吹、草怎么动、物怎么应、光影怎么移、声音远近层次）；禁止"她很紧张""气氛凝固"式笼统词与静态场景描述。三级标准详见 `references/script-format.md` 的"细节描写规范"。

**剧情交付物（确认版）**：问询全部确定后，先产出剧情文档（可直接在对话中呈现，或交付文件），必须包含：

1. **完整剧情故事**（全篇叙事稿，不是要点大纲）：把整个故事完整讲述出来——起因、发展、冲突升级、反转、高潮、结局，含人物弧光、关键事件因果、情绪递进与关键细节，写成可从头读到尾的完整故事文本；用户确认的就是这个故事。
2. 剧名 + 一句话梗概 + 信息卡（题材 / 时长 / 画面风格，段落式）
3. 人物档案（主要人物：姓名、年龄、身份、性格标签、核心诉求、人物关系，逐人一段文字描述）
4. 分场剧情大纲（每场：场景与时间、事件概要、冲突/爽点、反转、结尾钩子，逐场分段）
5. 彩蛋与伏笔设计点（2-3 处，写明类型与埋设位置）
6. 热梗清单（用户选中的梗及其使用位置）
7. 整体画面风格说明（风格名 + 视觉总则） **以上全部内容一律用文档段落形式呈现，不得使用表格。**

**确认规则（强制）**：剧情交付后必须等待用户明确确认"无修改 / 可以"，才进入脚本创作；用户提出修改时逐条修订剧情，直至确认通过。**禁止跳过剧情确认直接写剧本/分镜。**

### 步骤 5：脚本创作（剧情确认后执行）

仅当用户确认剧情无修改后，按确认版剧情产出完整剧本与分镜脚本：

- 剧本格式按 `references/script-format.md` 的分场剧本模板执行（场号、场景、时间、人物、动作与神态描写、台词、情绪/节奏标注），画面描写强视听化。
- **每一场戏都必须配套专业分镜脚本**：按 `references/script-format.md` 的分镜脚本表模板，为每个镜头完整填写以下字段——镜号、段落、景别、场景美术、画面内容构图、人物动作、摄像机镜头、摄影参数、镜头调度、光线色彩、音效台词、画面包装/台词/制作备注、转场设计。字段含义与填写规范见该文件，不得缺列、不得用笼统描述代替具体画面。
- **全剧视觉统一**：分镜的"光线色彩""场景美术"列必须执行问询阶段确定的整体画面风格（见 `references/visual-style.md`），风格变化点（梦境/回忆/反转段）在分镜中注明。
- 篇幅与用户确认的时长匹配（参考字数对照见 `references/script-format.md`）。

### 步骤 6：文档交付

交付三份正式文档（均通过 `present_files` 交付）：

1. **剧情文档**：确认通过的**完整剧情故事**（全篇叙事稿）+ 剧情大纲（信息卡 + 人物档案 + 分场大纲 + 彩蛋伏笔 + 热梗清单 + 画面风格说明）。
2. **剧本 + 分镜文档**：默认 Word 文档（.docx），按 `word` skill 规范生成并保存，包含：①完整剧本正文（分场剧本）；②每场戏的分镜脚本表（专业分镜字段）；③整体画面风格说明；④热梗清单。文件名如《剧本标题\_短剧剧本.docx》。
3. **AI 素材提示词文档**：**单独生成一份**详细的关键人物、场景、物品的 AI 生成图片提示词 + 视频提示词，按 `references/ai-prompts.md` 规范编写，与剧本/分镜文档分开交付。

- 用户明确要求飞书文档时，改按 `lark-doc` skill 规范创建飞书文档并交付链接。
- 交付时正文只发简短说明（标题、时长、题材、场数/镜头数、三份文档清单、下一步建议），不粘贴文档全文。
- 三份文档均为最终交付物；若用户后续要求衔接上一部剧情，以已交付剧本为续写前置。

## 承接边界

- **承接**：单部短剧/剧情短片完整剧本 + 配套专业分镜脚本；先出剧情、确认后再出脚本的两段式创作；关键人物/场景/物品的 **AI 图片与视频提示词文档**（文字交付物）；用户给定灵感的扩写创作；对标爆款的再创作；上一部剧情的续写衔接。
- **不承接**：实际的视频生成、图片生成、分镜图（画面图像）、多集合集一次性全量创作（单部独立成篇，多部由用户逐部发起，可衔接）。AI 提示词（文字）属于本 skill 承接范围，实际调用生图/生视频工具不属于。
- 用户要求超出边界时，明确声明本 skill 范围并给出建议路径。
