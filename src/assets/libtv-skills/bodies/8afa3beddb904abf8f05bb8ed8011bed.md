# 小动物骑士视频

## 这个 Skill 做什么

把一句「小动物骑士」题材设定，做成一条完整短视频：**先出脚本 → 用户确认 → 出角色与场景资产图 → 生成小动物骑士与巨型神兽战斗的视频**。

适用题材：任何「小动物骑士」类设定——小猫骑士是最近爆火的典型示例，但小狗、小仓鼠、小狐狸等小动物骑士同样适用。核心特征始终是：**体型娇小的动物骑士，迎战体型悬殊的巨型神兽。**

不适用：与「小动物骑士」无关的普通图片/视频需求，不要触发本 Skill。

## 输入

用户给出**一句题材设定**即可，例如：

> 一只穿铠甲的小猫骑士，在废墟中迎战巨型神兽

如果用户只说了「小猫骑士」这类极简信息，用默认设定补全（铠甲、废墟战场、巨型神兽），并在脚本里写明你补了什么，让用户在确认环节纠正。

## 工作流

本 Skill 是**带确认环节的多步链路**，共三个阶段。**第一阶段产出的脚本必须先给用户确认，确认后才进入生成**——不要跳过确认直接出图出片。

### 阶段一：产出脚本（先评审，不生成）

根据题材设定，写出三份文字内容，交给用户确认：

1. **角色设定**：小动物骑士的外观（物种、铠甲样式、配色、标志性细节）、气质、武器；以及**巨型神兽**的外观（物种/形态、体量、标志性特征）。
2. **场景设定**：战场环境（如废墟、火山、古战场）、时间与光照、氛围关键词。
3. **战斗脚本**：分镜式的战斗过程，3\~5 个镜头，写清每个镜头里小骑士与巨型神兽的动作、相对位置和画面张力。

> 阶段一**只出文字**，不生成任何图片或视频。产出后停下来，请用户确认或修改；用户认可后才进入阶段二。

### 阶段二：生成资产图

确认后的脚本作为提示词依据，生成**三张**资产图：

1. **骑士角色图**：小动物骑士的形象图。
2. **巨型神兽角色图**：巨型神兽的形象图。神兽是战斗视频必需的**第二主体形象锚点**，不能遗漏——只出骑士角色图会导致视频里神兽形象不受控。
3. **场景图**：战场环境图。

三张图都应忠实于阶段一确认的设定，不要临时改设定。

**资产图呈现要求（必须遵守）**：每张资产图都是**干净的单主体身份卡**，用于锁定形象，不是设定说明页：

- 纯色或浅灰背景，画面干净；
- 一张图只放**单一主体**；
- **不要**任何文字、标题、设定说明栏或比例尺；
- **不要**多格/分格细节图（不要在一张图里拼多个角度或局部特写）。

### 阶段三：生成战斗视频

以阶段二的角色图与场景图为视觉依据，按阶段一的战斗脚本生成视频：小动物骑士与巨型神兽的战斗。

**硬约束（必须满足）**：视频必须呈现**体型悬殊的对比感**——小骑士要明显娇小，巨型神兽要明显庞大，两者的体量反差是这类视频的核心看点，不能拍成体型相近的对打。构图、镜头高度、参照物（如小骑士只到神兽脚掌）都要服务于这个反差。

## 画幅

**画幅不要写死。** 在进入生成前，向用户提供画幅选项供其选择，例如：

- 9:16 竖屏（短视频向，默认）
- 16:9 横屏
- 1:1 方形

用户未选择时使用默认值 **9:16**。用户选定的画幅应贯穿阶段二的资产图与阶段三的视频，保持一致。

## 通用要求

- **尊重用户设定**：用户确认过的角色、场景、脚本是后续生成的唯一依据，不要在生成阶段自行改动。
- **诚实补全**：用户信息不足时按默认值补全，并把补全内容显式写进脚本让用户看到，不要默默替他决定。
- **聚焦反差**：所有环节都围绕「娇小骑士 vs 巨型神兽」这一核心张力展开。
