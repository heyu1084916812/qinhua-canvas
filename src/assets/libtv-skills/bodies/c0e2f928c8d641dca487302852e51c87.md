# 多集短剧制作 Skill

## 使用场景

当用户要制作有完整剧本的多集短剧、竖屏/横屏短剧、分集剧情视频、单集片段、单个镜头、角色形象、场景图、道具图、镜头视频、BGM 或剪辑导出时，使用本 Skill。

用户通常会带着大量上下文进入对话，可能包含完整剧本、角色形象图、场景图、道具图或其他关键参考元素。制作不一定从第一集开始；用户可能从任意一集、任意镜头切入，也可能先从角色/场景建立阶段切入。

本 Skill 的核心原则是：接到用户当下任务后，按依赖关系补齐尚未就绪的前置项，再执行当前任务；不要假定用户会按固定顺序推进，也不要强行跑完整个工作流。

## 全局原则

1. 优先服务用户当前任务。
   - 如果用户只要建立角色/场景，只做 key_elements，不建立镜头。
   - 如果用户直接要求做某集或某镜头，先检查该任务所需前置是否就绪，缺什么补什么，再推进生成。

2. 不修改剧情事实。
   - 分镜中的对话、旁白、动作结果和场景顺序必须与上传脚本及当前制作内容的剧本原文一致。
   - 只允许技术性编辑：拆分镜头、合并镜头、添加更丰富的镜头语言。
   - 不得改写情节，不得改写台词，不得合并多句台词，不得用“……”省略对白。

3. 生成任何素材前必须先写 Prompt Draft。
   - 包括角色图、场景图、道具图、关键帧、镜头视频、BGM 等。
   - 等用户确认 Prompt Draft 后，才进入生成。
   - 如果用户已指定可用资产，直接绑定资产，不要重新生成。

4. 累加式更新故事板。
   - 做下一集、下一批镜头或新增元素时，在现有故事板基础上新增和补充。
   - 不删除已有内容，除非用户明确要求。
   - 出现新角色、新场景、新道具或新装造时，新增 key_element 或更新已有 key_element 描述。

5. 用户修改任何资产或素材时，同时评估故事板描述文字和资产是否都需要更新。
   - 不要只改资产导致故事板不一致。
   - 不要只改故事板导致资产不一致。

6. 语言规则。
   - 如果用户沟通语言是中文，可以使用中文沟通、中文描述和中文 Asset ID。
   - 所有 key_element、shot、audio_layer 的 ID 使用英文；若用户沟通语言是中文，也可采用中文 ID。
   - Prompt 使用用户语言书写；但旁白和对话内容必须严格遵循 Final_Video_Spec.md 中的 Output Language。

## 工具分工

使用以下工具完成对应任务：

- `resource_prepare_and_analyze`
  - 快速预览完整剧本全貌。
  - 对当前制作的一整集或大段内容进行完整逐字提取。
  - 分析用户上传的参考素材、剧本文件、图片或其他资源。

- `storyboard_designer`
  - 建立或更新故事板。
  - 新增 key_elements、shots、audio_layers。
  - 维护角色、场景、道具、镜头、音频层之间的依赖关系。

- `text_editor`
  - 建立或更新 `Final_Video_Spec.md`。
  - 维护标题、类型、画幅比例、单集时长、视觉风格、输出语言、模型偏好等剧本级全局规范。

- `media_generator`
  - 绑定用户已提供的关键元素图。
  - 生成角色图、场景图、道具图、关键帧、镜头视频、BGM 等。
  - 所有生成动作前必须先写 Prompt Draft 并等待确认。

- `video_assembler`
  - 按故事板镜头顺序剪辑镜头视频与音频。
  - 用户主动提出剪辑时，按当前已生成镜头顺序执行。
  - 剪辑就绪后，引导用户确认并导出。

## 两种初始切入模式

以下两种模式描述的是项目最初如何切入，不是固定工作流。项目启动后，用户随时可能提出当下任务，例如“直接做某个镜头”。接到任务后，只补齐当前任务需要的前置依赖，再执行当前任务。

### 模式 A：先建立角色/场景形象

适用情况：

- 用户上传完整剧本，但还没有角色图、场景图、道具图等关键参考元素。
- 用户已有部分关键参考元素，但不完整。
- 用户希望先建立主要角色和场景的视觉形象，确认满意后再制作具体集数或镜头。

执行原则：

- 此阶段只做 `key_elements`。
- 不建立任何镜头。
- 故事板里只包含角色、场景和道具定义。
- 等用户明确说“开始做第 X 集”或“开始做某个镜头”后，再按模式 B 的依赖准备推进。

典型推进：

1. 快速预览剧本全貌。
   - 使用 `resource_prepare_and_analyze`。
   - 总结故事纲要、主要角色、主要场景和整体基调。
   - 不逐字提取完整剧本。

2. 建立主要 key_elements。
   - 使用 `storyboard_designer`。
   - 建立主要角色、场景、道具的 key_elements。
   - 角色描述包含身份、外观、服装、配饰、声音/音色。
   - 场景描述包含布局、重要物体位置和朝向。
   - 道具描述包含形状、材质、颜色、尺寸、状态、独特标记。
   - 不建立任何镜头。

3. 建立关键元素素材。
   - 使用 `media_generator`。
   - 用户已提供的图直接绑定到对应 key_element。
   - 缺少素材时，先写 Prompt Draft，确认后再生成。

4. 元素图确认满意后，询问用户是否开始制作具体集数或镜头。

### 模式 B：直接制作某集或某镜头

适用情况：

- 用户提供剧本，并明确要制作某一集、某些镜头或某个具体镜头。
- 用户可能同时提供角色、场景、道具参考图。
- 制作内容不限第一集，可从任意集、任意镜头开始。

执行原则：

即使用户一上来就要求做某个镜头，也必须先确认前置是否就绪：

- 剧本理解是否完成。
- `Final_Video_Spec.md` 是否已建立或确认。
- 故事板是否包含该镜头及所需 key_elements。
- 当前镜头涉及的关键元素素材是否已就绪。

缺什么补什么，再生成视频。

典型推进：

1. 前序准备，可跳过已完成项。
   - 使用 `resource_prepare_and_analyze` 快速预览剧本全貌，总结故事纲要、主要角色、主要场景和整体基调，不逐字提取。
   - 使用 `text_editor` 建立或确认 `Final_Video_Spec.md`。
   - `Final_Video_Spec.md` 是剧本级全局规范，不是某一集专用。
   - 至少包含：标题、类型、画幅比例、单集时长、视觉风格、输出语言、模型偏好。

2. 提取当前制作内容的剧本原文。
   - 如果是一整集或大段内容，使用 `resource_prepare_and_analyze` 完整逐字提取。
   - 不得省略、摘要、改写或合并台词。
   - 必须完整输出该集场景描述、台词、旁白、画外音。
   - 提取结果作为依赖项传给 `storyboard_designer`。
   - 如果是单个镜头或内容很少，可自行阅读对应段落，将原文不改格式、不改文字地写入任务描述传给 `storyboard_designer`，无需单独调用多模态提取。

3. 制作或更新故事板。
   - 使用 `storyboard_designer`。
   - 将剧本原文传给故事板工具。
   - 新增当前需要的分镜、关键元素和音频层。
   - 台词和画外音写进镜头描述，不写进独立音频层。
   - 按累加逻辑新增，不删除已有内容。
   - 出现新角色、新场景、新道具或新装造时，新增 key_element 或补充已有 key_element。

4. 建立关键元素素材。
   - 使用 `media_generator`。
   - 用户已提供的图直接绑定。
   - 缺少素材时，先写 Prompt Draft，确认后再生成。

5. 逐镜生成视频。
   - 每个镜头先写视频 Prompt Draft。
   - 用户确认后再使用 `media_generator` 生成。

6. 生成音频层。
   - 根据故事板 `audio_layers` 生成 BGM 或其他独立音频。
   - 使用 `media_generator`。

7. 剪辑与导出。
   - 所需镜头视频与音频就绪后，按故事板镜头顺序剪辑。
   - 用户主动提出剪辑时，也按当前已生成镜头顺序执行。
   - 使用 `video_assembler`。
   - 剪辑就绪后引导确认并导出。

## 素材分析规则

当任务是为某一集或某些镜头提取剧本时，必须对剧本文件进行完整逐字提取，而不是摘要或概括。

禁止：

- 将多句台词合并。
- 用“……”省略对白。
- 用概括性情节描述代替原文。
- 改写场景描述、台词、旁白或画外音。

允许：

- 在快速预览完整剧本全貌时，只总结故事纲要、主要角色、主要场景和整体基调。
- 在故事板阶段对镜头进行技术性拆分、合并和镜头语言补充。

## 故事板设计规则

### 脚本忠实度

- 分镜中的对话、旁白、动作结果和场景顺序必须与上传脚本及当前制作内容的剧本原文一致。
- 只允许技术性编辑：拆分镜头、合并镜头、添加更丰富的镜头语言。
- 不要修改情节。
- 不要改写台词。

### ID 命名

- 所有 `key_element`、`shot`、`audio_layer` 的 ID 默认使用英文。
- 如果用户沟通语言是中文，可以采用中文 ID 或中文 Asset ID。

### 关键元素设计

关键元素通常包括：

- 关键角色。
- 关键地点/场景。
- 关键道具。

设计要求：

- 当前任务可能是为整个长剧本设计关键元素，也可能是为某一集设计关键元素。
- 如果用户提供参考媒体并指定为关键元素，描述必须与该资产匹配，不要与所见或所听内容矛盾。
- 如果用户引入资产库里的参考媒体且已有描述信息，可以直接复用该描述信息，无需重新编造。
- 如果当前是在更新故事板，例如新增一集内容，需要识别是否有新的关键元素，或已有元素是否出现新信息、新造型、新状态。

角色 key_element 必须包含：

- 身份特征。
- 年龄、体型、种族或族裔信息，若剧本或用户指定。
- 面部特征。
- 发型、发色、妆容。
- 服装、配饰、材质、剪裁、颜色和状态。
- 声音/音色。
- 多种状态或外观时，用“外观 1：...；外观 2：...”清楚描述每一种。
- 已有角色出现新造型时，在原元素描述中增加即可，无需新增元素。

场景 key_element 必须包含：

- 场景类型与空间基调。
- 布局。
- 核心物件。
- 重要物体的位置和朝向。
- 道具或发生主要动作/表演区域的位置。
- 空间关系和情绪基调。

道具 key_element 必须包含：

- 形状。
- 材质。
- 颜色。
- 尺寸。
- 状态。
- 独特标记。
- 与角色或场景的使用关系。

### 镜头设计

- 在保持剧本内容不变的情况下，可以合并或拆分剧本镜头。
- 尽量保证每个镜头 15 秒内能表达完。
- 过短镜头可以与后续镜头合并。
- 过长镜头必须拆分。
- 倾向使用带内部剪辑的长镜头，每个镜头约 10-15 秒。
- 在镜头内部设计剪切，而不是拆成许多短镜头。
- 每个镜头不得超过 15 秒。

每个镜头描述必须包含：

1. 场景。
2. 故事和表演。
3. 具体台词。
4. 镜头语言，包括景别、角度、运动。

镜头描述规则：

- 台词和画外音写在镜头描述中，而非独立音频层。
- 视觉设计和故事事实必须与脚本相符。
- 如果脚本省略镜头覆盖范围，可以从类型和基调专业推断构图和运动，但绝不能改变情节事实或对话。
- 镜头有内部剪切时，在场景/设定之后按剪切顺序排列故事内容和镜头语言。
- 使用明确剪切标记，例如：“Shot 1：... Shot 2 切至：... Shot 3 切至：...”。
- 不要依赖过细的逐秒时间计划。

### 独立音频层

- 至少设计一个全局背景音轨。
- BGM 风格和节奏必须与参考资料或 `Final_Video_Spec.md` 匹配。
- 如果参考资料有明确节奏或情绪变化，拆分 BGM 片段并定义范围。
- 每个音频层都有自己的 `audio_id` 和范围。
- 台词和画外音不写入独立音频层，除非该旁白确实是后期单独音轨且故事板明确需要。

## 媒体生成规则

### 元素生成

- 如果用户已为元素指定资产，例如产品图、角色图、场景图，直接使用，不要生成。
- 如果缺少素材，角色、场景、道具使用 TextToImage 或项目约定的生成方式。
- 同一角色有多种状态时，使用 ImageToImage 参考第一张，以保持一致性。
- 推荐模型：Nano Banana 2（Gemini 3.1 Flash Image）。
- 推荐分辨率：2K。

角色图推荐：

- 生成一张横向 16:9 角色图。
- 画面从左到右包含半身特写和全身三视图：正面、侧面、背面。
- 目的是帮助 Seedance 读取身份和服装信息。

场景图推荐：

- 生成一张 1:1 场景四宫格图。
- 展示同一场景的不同视角全貌。

### 最终镜头视频生成

- 使用 MultiModalToVideo。
- 推荐模型：Seedance2.0。
- 推荐分辨率：720p。
- 每次生成镜头视频之前，必须重新检查当前镜头涉及的所有关键元素下已有资产。
- 用户可能随时新增资产，不可依赖上次记忆。

生成前参考选择规则：

- 角色图：如果角色有多套装造的参考图，只选择与当前场景服装一致的一套，无需同时放入多个。
- 音色：如果元素下挂有音色资产，必须一并作为音频参考。
- 站位/姿态参考图：如果元素下或当前镜头里有与场景相关的站位参考图，必须纳入参考。

### BGM

- BGM 风格和节奏必须与最终视频规范和参考资料匹配。
- 时长和范围按故事板执行。
- 生成前同样先写 Prompt Draft，用户确认后再生成。

### 修改素材

当用户对任何资产或素材提出修改时：

1. 判断故事板描述文字是否也需要同步更新。
2. 判断资产本身是否需要重新生成或替换。
3. 保证 key_element、shot、audio_layer、资产之间一致。

## 提示词总规则

当用户使用中文输入或加载中文语言环境时，提示词使用中文书写。但 prompt 中有关旁白或对话的内容，必须严格遵循 `Final_Video_Spec.md` 中的 Output Language。

### 图像生成提示词

图像提示词要像真正的电影导演和调色师在指导团队：

- 使用通顺自然语言描述主体、行为、环境。
- 使用简短词组描述视觉美学、颜色、光影和构图。
- 不要文学化修饰。
- 不要解释角色动机或内心状态。
- 不要描述屏幕外或不可见元素。
- 只描述物理上可见的内容。

所有图像提示词必须自然融入以下六大核心规则，不要输出成带标签的章节：

1. 专业风格术语。
   - 结合专业艺术或电影术语与具体风格锚点。
   - 示例：Neo-Noir style、David Fincher style、inspired by Se7en。

2. 构图与镜头。
   - 明确电影化构图和景别。
   - 示例：over-the-shoulder shot、Dutch angle、close-up、medium shot。

3. 光影。
   - 详细说明主光。
   - 强调负补光以增加对比度和戏剧感。
   - 示例：strong chiaroscuro contrast、dramatic interplay of light and shadow。

4. 调色。
   - 使用高端电影调色。
   - 保持克制色调。
   - 除非用户明确要求，禁止红蓝霓虹冲突、crimson bleed、霓虹洋红 vs 青色。
   - 约 90% 画面区域只使用一种主色调。

5. 视觉渲染。
   - 描述整体视觉质量和纹理。
   - 示例：fine rendering quality、rich intricate details、soft-focus effect with subtle Gaussian blur。

6. 氛围与潜台词。
   - 描述角色微表情和戏剧性定格瞬间。
   - 示例：oppressive suffocation、no mercy、predatory stillness。
   - 无生命物体可描述状态和气氛，例如 destined aura、piercing gaze、cold detached atmosphere。

文字渲染规则：

- 如果画面中需要出现文字，自然整合准确文本。
- 用引号包裹需要渲染的确切文字。
- 示例：背景霓虹灯牌写着 “DANGER”。

### Key Element 图像提示词

当目标是 key_element 时，提示词必须提供清晰、详细、可复用的视觉定义，方便跨镜头保持一致。

主体与身份：

- 说明元素是什么。
- 角色需包含年龄、体型、种族或族裔信息，若指定。
- 角色需包含显著特征和声音。

特征细节：

- 角色写清面部特征、发型/发色、妆容、服装、配饰、材质、剪裁、颜色和状态。
- 道具写清形状、材质、颜色、尺寸、状态和独特标记。
- 场景写清布局、核心物件、空间关系和情绪基调。

画面整洁：

- 不要在画面中生成文字，除非用户或脚本明确要求。

### 关键帧提示词

当目标是起始帧、结束帧或高亮帧时：

1. 先在镜头 description 中定位对应时刻。
2. 如果镜头描述不够清晰，模拟主体运动、摄像机运动和环境变化。
3. 想象该瞬间的静态画面。
4. 只描述可见内容、构图方式和物体状态。

起始帧：

- 展示动作开始前的场景。
- 描述主体运动前姿态、注视方向、环境基础状态、摄像机初始构图和角度。

结束帧：

- 展示动作完成后的直接结果。
- 描述主体终结姿势或表情、环境变化后的状态、摄像机准备下一次剪辑的最终位置。

高亮帧：

- 确定镜头中视觉或情感冲击最强的瞬间。
- 详细描述姿势、表情、光照状态和构图。

### 视频生成提示词

视频提示词必须遵循故事板内容，绝对不可更改故事内容、台词、场景、镜头语言等客观事实。

按照 Seedance 顺序编写：

1. 摄像机。
2. 主体。
3. 空间。
4. 音频。

摄像机：

- 描述运动、镜头或剪辑变化。
- 示例：static to push-in、cut to new angle、orbit、pan。

主体：

- 描述动作和表情。
- 说明谁做了什么、面部动作节拍。

空间：

- 描述主体或摄像机的位置变化。
- 描述背景运动、空间深度或布局转换。

音频：

- 描述对话、音效，以及无音乐约束。
- 如果分镜脚本表明该镜头有单独旁白音轨，不要在视频提示词中写入旁白文本，避免音频冲突。

动作描述规则：

- 动作要基于具体身体部位，例如手、腿、头、肩膀。
- 添加幅度、速度、强度。
- 多个节拍按故事时间顺序列出主要动作，再列次要动作。
- 当工具接受长提示词时，可以在单次生成中标记“镜头 1、镜头 2、镜头 3”，表示摄像机或故事节拍序列。
- 不要强制逐秒计划。
- 不要写“第 2 秒时...”或“5-8 秒”。
- 描述按顺序发生的事情，而不是精确时间表。

Seedance 包装符：

- 音乐：使用圆括号 `(...)`，例如 `(fast-paced rock playing in the background)`。
- 音效：使用尖括号 `<...>`，例如 `<distant dog barking>`。
- 口头对话：使用花括号 `{...}`，花括号内只放对话文字，不保留故事板里的引号。
- 如果台词不是项目原始语言，在花括号前标注语言，例如 `Says in Japanese: {こんにちは}`。
- 屏幕标题、章节、字幕文字：使用方括号样式 `【...】`，例如 `【Chapter One: Departure】`。

负面约束：

- 几乎始终包含 `no music`，防止模型添加不需要的背景音乐。
- 始终包含 `no subtitles`，因为字幕在后期剪辑添加。
- 如果镜头有独立旁白音轨，不要在视频提示词中写旁白文本，避免音频冲突。
