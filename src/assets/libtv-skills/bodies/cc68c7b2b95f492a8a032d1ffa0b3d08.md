## #做什么

彻底解决AI动作片/互动影游“高潮戏做不出来、一镜到底接不上、交互钩子无意义”的痛点。

输入场景类型、情绪节奏、骨架类型，一键生成带虚拟一镜到底、动作锁定轨迹、6秒骨架锁节奏、交互钩子设计的高潮段落，可导出为 Twine / Harlowe 互动影游 DEMO。

覆盖8大高潮场景：短剧高潮、漫剧大决战、悬疑揭秘段、追逃段、审讯段、反派摊牌段、主角觉醒段、最终绝杀车轮战。

## #需要什么输入

**最少提供：**

- 场景类型（8大场景选1）
- 情绪节奏（慢→快→爆发 / 快→更快→极快 / 挨打→反击→冷峻）
- 骨架类型（主动打击型 / 挨打反击）——仅武打场景需要
- 主角设定（三视图/定妆照，或文字描述）
- 敌人设定（群像/单人锚点图，或文字描述）
- 场景设定（场景参考图，或文字描述）

**可选提供：**

- 视频素材（如前3秒+后3秒，或整战版）
- 目标时长（6秒单关 / 30-60秒长段落 / 48秒一镜到底）
- 互动影游DEMO需求（是否导出 Twine 工程）

### 三、两套方法的衔接（混合场景专用）

对于既含武打又含情绪的场景（如主角觉醒段、追逃段），按以下顺序切换：武打部分 → 调用方法A（火柴人6宫格+前3后3）\
↓ 硬切（切换点=情绪转折点）\
情绪部分 → 调用方法B（情绪锚点+微表情七层）\
↓ 硬切（切换点=情绪转折点）\
武打部分 → 再调回方法A\
\
\
**强制声明：** 火柴人6宫格与前后3秒，仅适用于武打场景。非武打场景禁止使用火柴人，改用情绪锚点+七层微表情。

### 四、骨架与情绪节奏的底层关系（仅武打场景）

骨架不是“打斗动作”，是“情绪节奏的结构”。

- **骨架A（主动打击型）** = 强势碾压节奏。主角从头压到尾，观众看到的是高能体验。
- **骨架B（挨打反击）** = 先抑后扬节奏。主角先挨打、先狼狈，一击反杀。观众看到的是“揪心→爆发”。

八大场景的本质，就是八种情绪节奏。选不同骨架，就是在选不同情绪节奏。

### 五、底层规则自动加载

静默调用父级【顶级大导演思维】的16个通用影视MD，叠加母级4个互动影游专属副文件，并根据场景类型自动激活对应LOCK指令：

- 武打场景 → 70系列
- 非武打场景 → 50系列
- 混合场景 → 70系列+50系列切换

### 六、一镜到底首帧衔接规则（通用）

- 第一关（或第一个子镜）独立生成首帧图，仅此一次。
- 从第二关起，start_frame 必须接上一关（或上一子镜）的尾帧截图。
- 从第二关起，每关只有“前3秒 + 后3秒”两段视频，没有独立首帧图。

### 七、伪一镜到底剪辑技法（通用）

- **动作中段切**：硬切不切在动作完成时，切在动作进行中。
- **运动向量对齐**：前段尾帧的运动方向/速度 = 后段首帧的运动方向/速度。
- **视线引导转移**：主角打完一个、目光转向下一个，就是最佳剪辑点。
- **声音桥接**：环境音在剪辑点上连续不断，有0.3-0.5秒重叠。
- **构图锚点继承**：视觉锚点前后位置必须一致。

### 八、互动影游接入（调用顶级游戏开发大师）

- **节点设计**：每战=先手前3秒→二选一→判定→后3秒→翻转→回流。
- **变量系统**：体力、伤势、蓄力、进度、气势、犹豫次数、核心目标安危。
- **交互钩子检查表**：每一次“下一步”必须有危机/反转/局势变化，禁止无意义翻页。
- **结局系统**：完美/血战/惨胜/力竭/失守，路径互斥完备。
- **工程输出**：.twee 工程 + 程序化 JSON + 完整性校验报告。

**【Twine/SugarCube 工程强制规范（LOCK 60_03）】**

- 引擎锁定：SugarCube 1.0.35（唯一，不可更换/升级）
- 禁用格式：Harlowe / Chapbook / SugarCube 2.x
- 建立方式：手动一个一个建节点，禁止使用「导入twee/txt文件」
- 变量语法：`<<set $x = 0>>`，禁止 `<<set $x to 0>>`
- 变量运算：`<<set $x = $x + 5>>`，禁止 `+=` 简写
- 条件判断：eq/ne/gt/gte/lt/lte，禁止符号
- 跳转：`<<goto "节点名">>`，链接：`[[文字->段落名]]`
- 变量命名：`$F`=主角，`$E`=对手，`$snap`=快照，逐字符一致
- 临时变量：也必须用 `$` 前缀（`<<set $roll = ...>>`），禁止裸用 `roll` / `read`
- 保留字禁令：禁止使用 `read` 作变量名，改用 `$readv`
- 随机数：`random(1,100)`，禁止 `either`
- 排版：相邻宏之间至少留一个空格
- 提交前：跑自检清单10条，全部通过才交付

### 九、安全过审铁律

禁止火柴人实体化、红领带/红眉/箭头/黄圈/蓝虚线、枪械、卡通头、黑色描边、文字/Logo/水印、角色脸崩、服装漂移、A/B位置互换、人物消失、空场景、场景重置。

用词替换：

- 挨打 → engaging and immediately rotating waist to neutralize force
- 敌人 → male figure
- 出拳 → arm extended forward
- 击中 → making contact

### 十、引擎切换铁律

低成本引擎连续2次跑废 → 立刻停止修改提示词，切换顶级引擎（高积分）→ 一击必中。绝对禁止用“改提示词”掩盖“选错工具”。

## #产出什么

最终交付：

- **视频文件（MP4格式）**：30-60秒高潮段落，可直接用于参赛、展示、接入游戏引擎。

- **互动影游DEMO**：可点击的 Twine/SugarCube 工程（.twee 文件 + JSON + 完整性校验报告）。
- 骨架选择规则表、痛苦表情规则表、物理反馈死锁规范。
- 交互钩子检查表、变量系统与结局库。

## #什么时候问你

出现以下情况时，必须停下来问用户：

1. 当用户未明确选定**场景类型**（8大场景选1）时。
2. 当用户未明确选定**骨架类型**（主动打击型/挨打反击）时——仅武打场景需要。
3. 当用户未明确选定**长段落方案**（A 40秒 / B 20秒 / C 12秒）时。
4. 在【6宫火柴人分镜图】和【首帧图】生成后，向用户确认一次动作轨迹和画面构图——仅武打场景需要。
5. 在【前3秒视频】生成后，向用户确认一次物理反馈是否真实——仅武打场景需要。
6. 当**交互钩子检查未通过**（某节点无危机/反转/局势变化）时。
7. 用户要求输出视频脚本、Prompt清单、视觉方案，但缺少关键输入时。
8. 本模块与上游主SKILL或其他附MD规则冲突时。
