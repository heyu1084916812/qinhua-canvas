# retro-ccd-vlog

## Skill 定位

- 只负责：使用 LibTV 原生图像、视频、音频和画布能力，为31–49秒社交媒体复古CCD Vlog完成创意开发、视觉锚点、逐镜脚本、图片/视频Prompt、视频片段、音乐声音方案、剪辑执行提示词、质量审核与成片组织。
- 支持“直闪快照型”和“可用光叙事型”两条并列路线。
- 完整成片是目标交付之一，但不是本Skill唯一价值；完整、可复用的制作包是稳定交付基础。
- 如果智能剪辑或导出受到平台能力限制，必须保留并交付完整脚本、Prompt、素材节点、剪辑提示词和审核结果，不得把异常成片冒充为合格成片。
- 不使用脚本、代码、命令行或外部自动化。
- 类别边界：主旨是分享生活、娱乐互动或展示个人魅力，不强求完整故事；以教学或技能传授为主时不做成教程，以完整短剧剧情为主时不伪装成Vlog。

## 输入

- 需要什么：一句话想法、生活片段、故事、简短脚本或人物/场景参考图，至少提供其中一种。
- 可选信息：人物、地点、动作、情绪、目标时长、镜头数、画幅、发布平台、目标观众、标题/主题、互动方式、音乐方向、必须保留项和绝对避免项。
- 时长规则：制作包必须面向大于30秒且小于50秒的Vlog，即31–49秒。
- 默认值：用户没有指定时，默认规划40秒、10–14个镜头、4:3画幅；不默认夜景，不主动添加具体时刻、日期或时间戳。

## 输入使用

- 严格遵守：用户已确认的故事、人物身份、参考图可见特征、服装、场景、道具、时长、画幅、音乐方向、必须保留项和绝对避免项。
- 严格遵守：竞赛目标时长为31–49秒。用户给出30秒及以下或50秒及以上时，说明竞赛限制，并在不改变核心内容的前提下调整到合法范围；未指定时默认40秒。
- 严格遵守：企划前和交付前读取 `QUALITY_RUBRIC.md`；主题清晰、视听可辨、真实性和类别边界不可放宽。
- 只是参考：情绪词、风格参考片和示例Prompt只用于提取方法与视觉语言，不复制参考中的人物、地点、台词、歌曲、事件或连续镜头顺序。
- 参考图先判断用途：用户要保留人物或场景时作为资产锚点；用户只说“参考感觉”时只作为风格参考。
- 画幅：严格使用用户指定画幅；没有指定时默认4:3。不得信任智能剪辑节点的默认画幅，执行前必须再次检查。
- 视觉路线与音乐路线相互独立。直闪快照型不等于必须使用快速、电子或强节拍音乐。
- 用户没有明确CCD路线时，先各生成2张“直闪快照型”和“可用光叙事型”情绪测试图，再选择更适配内容的一条作为全片主路线。

## 内部流程和 Knowhow

- 故事脚本编写

  - 企划前读取 `QUALITY_RUBRIC.md` 的“类别边界”“硬性门槛”和“内部竞争标准”。
  - 读取 `REFERENCE.md` 的“路线选择”和“故事脚本编写”，把输入扩展为一句话主题、状态变化、音乐变化和可执行逐镜结构。
  - 每个Shot必须包含：编号、时间码、时长、画面动作、景别/机位/构图、光线、声音、起止状态、连续性和采用资产。
  - 完整生产顺序：类别与主题Gate → 企划 → 路线选择 → 情绪板 → 人物/场景/道具/音乐锚点 → 逐镜脚本 → 连续关键帧 → 图片与视频Prompt → 视频片段 → 音乐声音方案 → 剪辑执行提示词 → 智能剪辑与完整成片 → 发布包装 → 质量审核。

- 资产锚点创作和使用

  - 读取 `REFERENCE.md` 的“资产锚点创作和使用”。
  - 实际生成并锁定人物、服装、场景、道具和音乐方向。
  - 选定版本成为后续镜头的唯一采用版本，不得中途随机换脸、换服装、换场景或换道具。
  - 剪辑前必须输出“采用资产清单”，标明每个Shot使用的节点、版本和实际时长。

- 分镜创作

  - 读取 `REFERENCE.md` 的“分镜创作”。
  - 建立每镜首尾状态、动作接点、声音接点和人物/场景/道具连续性，再生成关键帧。
  - 每个镜头只安排一个主动作和一条主摄影机路径。

- Prompt Guide

  - 读取 `REFERENCE.md` 的“Prompt Guide”。
  - 为每个Shot输出可复制的图片Prompt、视频Motion Prompt和负面词。
  - 视频Prompt必须写明：采用资产、目标时长、起始状态、人物动作、摄影机运动、CCD成像要求、结束状态、声音提示和连续性限制。
  - LibTV通用节点不使用Midjourney的 `--` 参数。
  - Prompt必须作为正式交付内容显示给用户，不能只隐藏在节点内部。

- 音乐与声音

  - 读取 `REFERENCE.md` 的“音乐、声音与视频剪辑”。
  - 音乐生成前必须建立音乐方向卡：音乐气质、主要乐器、禁止音色、速度、情绪结构、目标时长和结尾方式。
  - 用户明确音乐方向时严格继承，不得被CCD视觉路线覆盖。
  - 用户没有明确音乐方向时，先输出两套音乐文字方案，再选择更符合人物状态和内容的一套。
  - 实际音乐时长短于目标成片时，必须在审核清单中标明，不得声称音乐已完整覆盖成片。

- 视频组织与剪辑

  - Skill必须自行读取已确认的完整逐镜脚本，将其编译为LibTV智能剪辑节点可执行的完整提示词。
  - Skill必须实际把剪辑提示词填写到智能剪辑节点，不得要求用户重新复制、缩写或填写脚本。
  - 剪辑提示词必须保留Shot顺序、逐镜时间码、动作、景别/光线、连续性、声音和音乐结构。
  - 执行前必须检查目标画幅、目标时长、全部视频输入、音乐输入和采用版本，不得直接使用节点默认的16:9、30秒或其他错误参数。
  - 如果平台不能修改旧智能剪辑节点，可以新建节点，但必须明确标记当前采用节点、当前成片节点和废弃节点。
  - 智能剪辑成功后组织生成完整成片；如果失败，保留完整制作包并如实标记成片状态。
  - 默认不中途等待用户逐项确认；只在人物身份、核心事件、主路线、音乐方向或交付规格会发生实质改变时询问一个关键问题。

## 输出

### 核心交付

- 面向31–49秒Vlog的完整逐镜脚本。
- 采用路线的CCD视觉情绪板。
- 人物、场景、道具和音乐锚点。
- 连续故事板或关键帧。
- 每个镜头的图片Prompt、视频Motion Prompt和负面词。
- 实际生成的视频片段及采用版本清单。
- 音乐方向卡、音乐生成Prompt、声音结构和环境声设计。
- 可直接填写进智能剪辑节点的完整剪辑执行提示词。
- 制作包审核清单、问题清单和修改建议。
- 发布封面或封面帧、标题和简短发布文案。
- 有对白或旁白时，输出准确、易读、与声音同步的字幕方案。

### 目标交付

- 在素材完整、平台能力正常时，建立智能剪辑节点并组织生成31–49秒完整成片。
- 成片必须使用已确认的脚本、采用版本、画幅、音乐和声音结构。
- 成片异常时，明确标记“制作包已完成／成片未通过”，不得把异常成片描述为最终合格结果。

## 自检

### 制作包检查

- 逐镜脚本总时长是否为31–49秒。
- 每个Shot是否包含时间码、动作、景别/构图、光线、声音、起止状态和连续性。
- 每个Shot是否有完整可复制的视频Motion Prompt。
- 是否输出采用资产清单，并且每个Shot只使用一个明确版本。
- 人物、服装、配饰、场景结构和道具是否连续。
- 音乐方向是否与用户要求一致，没有因为直闪路线自动变成电子快节奏音乐。
- 音乐Prompt是否写明主要乐器、禁止音色、能量变化、目标时长和结尾方式。
- 剪辑执行提示词是否继承完整脚本，而不是只有镜头名称和时长摘要。
- 是否输出明确的问题清单和修改建议。
- 是否全流程只使用LibTV原生能力，没有依赖脚本、代码或命令行。

### 成片检查

- 只有实际生成成片时才执行本部分。
- 是否存在独立、可播放的完整视频，而不是灰色占位节点。
- 播放器读取的实际时长是否大于30秒且小于50秒。
- 实际画幅是否与用户要求一致。
- 是否包含全部采用镜头，顺序、时长和脚本一致。
- 音乐实际时长是否覆盖目标时间线，最后一秒是否有合理声音收尾。
- 是否不存在黑帧、缺帧、持续频闪、爆音、乱码、错误字幕或素材版本混用。
- 是否完整播放检查人物漂移、肢体错误、道具变化和声音错位。
- 是否按 `QUALITY_RUBRIC.md` 完成六维评分并达到内部竞争标准。
- 未实际播放验证时，不得声称“成片完成”“精确31秒”或“全部通过”。

## Ask User

- 多张人物图身份冲突，无法判断主角。
- 用户提供的故事、人物或结局互相矛盾，合理推断会改变核心内容。
- 画幅会实质影响发布用途，但用户没有说明。
- 用户明确同时需要两种CCD路线，但没有说明分别制作还是同片分段。
- 用户提供的音乐要求互相冲突，无法建立唯一音乐方向。
- 用户输入主要是教学、技能传授或完整短剧，继续制作会超出本类别边界。
- 当前画布缺少完成目标所必需的图像、视频、音频或剪辑能力。
- 某个源视频实际时长不足脚本要求，继续会改变时间线结构。
- 其他信息缺失时使用最合理的生活化选择直接完成，不连续追问小字段，不要求用户重复提供Skill已经生成的脚本或Prompt。
