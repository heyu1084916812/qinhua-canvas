# LibTV 口播视觉包装

## 目标

把“几张参考截图 + 一份口播稿”转成同一风格、与具体内容匹配的视频包装素材。让用户只提供必要输入；自行判断风格、内容结构、元素类型和数量。

使用官方 LibTV CLI 完成项目、节点、模型、视觉素材和动态片段生成。把准确文字与生成式视觉分开控制：优先让 LibTV 输出可用成品；文字不准确时，改为生成无字底板并附上准确文字清单，不接受错字成品。

## 接收输入

要求用户只提供：

1. 一至五张参考图片；推荐三至五张。
2. 一份完整口播稿；接受直接粘贴的文本或 UTF-8 `.txt`、`.md` 文件。

接受但不要求：

- SRT/VTT 字幕时间轴；
- 画面比例、人物位置、品牌字体或颜色；
- 不想出现的元素；
- 已有 LibTV 项目 UUID 或已绑定项目目录，用于继续修改。

不要要求用户标注图片、解释设计术语、填写表格或先整理设计规范。

读取 input-contract.md 处理图片质量、数量不足、风格冲突和默认值。

## 执行流程

### 1. 检查最小输入

- 确认至少存在一张可读参考图和非空口播稿。
- 有三至五张合格截图时直接继续。
- 只有一至两张时继续执行，并在内部降低对字体、动效或组件变体的确定性；不要因此阻塞。
- 多于五张时优先选择最清晰、最完整、重复最少且风格最一致的五张。
- 图片混入播放器按钮、弹幕或平台界面时，识别并忽略这些覆盖物，不把它们当成风格元素。
- 只有输入无法读取、口播稿缺失或参考图彼此完全冲突且无法判断主风格时才向用户追问。

### 2. 建立风格 DNA

从全部参考图共同出现的特征中提取：

- 主背景、辅助背景和强调色；
- 明暗关系、饱和度、对比度和材质；
- 标题、正文、数字和强调词的字形气质；
- 字号层级、字重、对齐方式、行距和留白；
- 卡片的圆角、描边、阴影、透明度和内边距；
- 图标、插画、线条、贴纸和装饰语言；
- 元素在画面中的主要区域、密度和视觉重心；
- 可从连续截图判断出的动效线索。

优先采用多张图片反复出现的规律，不放大单张偶然细节。不要复制水印、平台按钮、账号标识、商标或无关人物。

只在内部形成简洁风格摘要，不让用户先确认。除非用户明确要求预览，否则直接进入生成。

### 3. 拆解口播稿

先按语义而非按标点划分章节，再识别：

- 开场钩子和核心命题；
- 章节切换与论点升级；
- 定义、步骤、清单、因果、对比和流程；
- 数据、日期、金额、比例和结论；
- 案例、引用、提醒、反例和行动建议；
- 需要图像化解释的抽象概念；
- 只需字幕、不值得额外包装的过渡句。

按照 element-routing.md 选择元素。不要给每句话都添加包装。视觉元素必须帮助理解、记忆、节奏或情绪，不能只是填空。

没有时间轴时，根据章节顺序和文本位置建立相对顺序，不伪造精确时间码。有 SRT/VTT 时使用其真实时间码。

### 4. 确定生成清单

默认从以下类别中按需选择，不要求每次全部生成：

- 干净主背景或章节背景；
- 开场标题画面；
- 章节转场和小标题；
- 普通字幕条与关键词强调样式；
- 概念卡、步骤卡、清单卡、对比卡；
- 数据卡、引用卡、提醒卡、结论卡；
- 图标、简单插画、关系图或流程示意；
- 适用于口播人物周围的透明或留白覆盖元素。

把元素数量与稿件长度、章节数和信息密度绑定。遵守 element-routing.md 中的密度规则。

### 5. 通过 LibTV CLI 生成

只使用官方 `libtv` CLI 操作 LibTV。不要调用已停用的 `im.liblib.tv/openapi/session`，不要自行拼装旧 HTTP API。

先定位 CLI：

```powershell
$libtv = "$env:USERPROFILE\.libtv\libtv.exe"
& $libtv --version
```

CLI 缺失时按照 [LibTV CLI 官网](https://www.liblib.tv/cli) 的官方安装方法安装。出现“用户未授权”时运行 `libtv login web --open`，让用户亲自在浏览器完成登录；不要索取账号、验证码、Cookie 或 token。

为每套包装建立一个项目并绑定当前输出目录：

```powershell
& $libtv project create "项目名"
& $libtv project use "项目 UUID"
```

上传每张参考图为独立资源节点：

```powershell
& $libtv upload "参考图-01" -t image --resource "C:\path\ref-01.png"
```

先运行 `libtv model search --type image` 和 `libtv model search --type video` 获取当前模型，再用 `libtv model <modelKey>` 检查真实 schema。除非用户明确指定其他配置，图片默认使用 `lib-image-2`、`quality=medium`（标准画质）、`resolution=2K`、`count=1`；视频默认使用 `star-video2-mini`（Seedance 2.0 Mini）、`resolution=720p`、`count=1`。按照 model-policy.md 处理比例、时长、声音、例外和模型变更。

为每个实际需要的包装元素建立可辨认的图片节点，把参考图连到左侧，设置 prompt、model、ratio、quality 和 count，再触发生成：

```powershell
& $libtv node create "章节转场-01" -t image `
  --prompt "根据参考图和本章节内容生成……" `
  -s model=z-image -s ratio=9:16 -s quality=1K -s count=1 `
  --left "参考图-01"

& $libtv node "章节转场-01" --run
```

保持同一套包装在同一个 LibTV 项目中。一个元素对应一个语义清楚的节点；只重做失败节点，不把整个项目拆成大量无关项目。

读取 libtv-execution.md 处理登录、项目绑定、生成、失败、继续修改和结果下载。

### 6. 检查结果

逐项检查：

- 是否与参考图的共同风格一致；
- 是否服务于口播中的真实内容；
- 是否保持统一比例、留白和安全区；
- 是否出现错误文字、乱码、无关文案或水印；
- 是否把参考图中的平台界面误当作设计；
- 是否存在过度装饰、重复卡片或视觉密度过高；
- 同类组件是否具有统一结构；
- 动态片段是否有足够的首尾静止区，方便剪辑。

按照 quality-control.md 处理问题。先在同一会话中要求 LibTV 定向修改；不要无差别整套重做。

### 7. 交付

生成完成后下载结果，并按以下类别说明：

- `backgrounds`：背景；
- `transitions`：章节转场和标题；
- `subtitles`：字幕及强调样式；
- `cards`：各类信息卡；
- `illustrations`：图标、插画和示意图；
- `motion`：动态片段；
- `manifest`：元素与口播段落的对应关系。

向用户提供：

1. 本地结果文件；
2. LibTV 项目画布链接；
3. 一句简短说明：生成了哪些类别、哪些文字需要在剪辑软件中叠加。

不要在生成未完成时提前展示项目画布链接。最终交付规则见 output-contract.md。

## 默认决策

- 画面比例：优先采用参考图多数项的比例；无法判断时采用 `9:16`。
- 人物安全区：参考图有人物时继承人物所在区域；没有人物信息时保持中部主体区干净，并把装饰放在边缘。
- 动效：静态参考图无法判断时使用克制的淡入、位移、遮罩揭示和轻微缩放，避免夸张弹跳。
- 字体：只能判断字体气质时不要声称识别出具体字体；选择合法可用的近似类别。
- 文字：只使用口播稿中的准确文字，允许压缩成短标题，但不得改变原意或捏造数据。
- 风格冲突：采用多数图片共同风格，把离群图仅用于其清楚展示的组件类别。

## 边界

- 不承诺仅凭静态截图精确复刻原视频的动画曲线。
- 不复制受保护的 Logo、水印、人物身份特征或平台 UI。
- 不把生成式模型绘制的长段中文当作最终字幕。
- 不上传参考图片到 LibTV，除非用户已明确要求使用此 Skill 生成或编辑。
- 不使用已停用的 LibTV Access Key 旧接口；使用 CLI 的本地登录凭据。
- 不因缺少可选参数而阻塞；使用默认决策继续。
