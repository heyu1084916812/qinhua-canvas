### 暂停与保存

**每个阶段都支持暂停**。用户说"暂停""保存""先这样"时，Skill 立即：

1. 保存当前阶段已完成产物
2. 写入项目状态文件（`.project_state.json`），记录：当前阶段和子步骤编号、各步骤完成状态、已确认产物路径和参数
3. 确认："已保存进度，下次从第 X 阶段第 X.X 步恢复。"

### 恢复与继续

用户下次进入时（或说"继续"），Skill 自动读取状态文件并展示进度（精确到子步骤），用户选择后恢复执行，已确认产物不重复生成：

```
检测到未完成的工程：[项目名]
当前进度：第二阶段 第2.6步 - 人物形象图生成

已完成步骤：
  ✅ 第一阶段：商品图获取（已确认）
  ✅ 第二阶段 2.1-2.5：品类/视觉路线/目标/受众/风格（已确认）
  ⏳ 第二阶段 2.6：人物形象图生成（进行中）
  ⬜ 第二阶段 2.7：人物三视图生成
  ⬜ 第二阶段 2.8-2.9：人物描述卡/全阶段确认
  ⬜ 第三阶段及之后...

请选择：
A. 从断点继续
B. 回到某个已完成步骤重新做
C. 从头开始新工程
```

### 回到某一步骤

每个阶段内部划分为带编号的子步骤，用户可在任意位置精确跳转。

**导航方式**：

- 阶段级："回到第 X 阶段" → 定位到该阶段第一个子步骤
- 步骤级："回到第2.6步" → 精确定位到该子步骤
- 语义匹配："换个风格重新做" → 自动识别对应步骤，触发级联依赖链
- 相对跳转："回到上一步" → 回退到上一个子步骤

**回溯入口**（关键节点展示）： 每个阶段完成后展示简洁回溯菜单，日常推进时不展示。用户随时可用自然语言触发回退。

```
✅ 第二阶段完成，核心参数已确认。
接下来进入第三阶段：三视图生成
📍 可回溯到：A. 第二阶段 B. 第一阶段
要继续还是调整？
```

**回退规则**：

- 回退时，该步骤后的下游产物自动标记为"需重新生成"
- 说明影响范围，用户确认后执行回退，已确认的上游产物保持不变
- 同一阶段内的子步骤回退不影响之前阶段

### 项目状态一览

用户随时说"项目状态""进度"，Skill 展示当前工程完整状态：各阶段完成状态、当前进度、已完成产物、版本列表。

### 多项目并行

支持同时维护多个独立项目，互不干扰。用户可新建、切换、暂停、删除项目，每个项目有独立的状态文件和产物目录。

### 第一阶段：商品图获取 + 质量检测

**目标**：获取合格的商品图片素材。

**子步骤清单**：

- 1.1 来源选择（上传商品图 / 文字描述生成）

- 1.3 质量检测（分辨率/清晰度/背景/完整度）
- 1.4 去背景处理（按需）
- 1.5 多商品确认（仅套餐商品）
- 1.6 用户确认商品图 ✓

> 📄 **详细规则**：[商品图获取与质检详细规则.md](2-05-%E5%95%86%E5%93%81%E5%9B%BE%E8%8E%B7%E5%8F%96%E4%B8%8E%E8%B4%A8%E6%A3%80%E8%AF%A6%E7%BB%86%E8%A7%84%E5%88%99.md)包含：图片质量量化标准（分辨率/清晰度/背景/完整度）、文字描述引导问题清单、按品类细分的生成prompt模板、去背景处理规则、多商品命名与关系确认、不合格图片的具体处理建议。

**流程**：

1. 询问用户：有商品图片还是从文字描述生成？
2. **线路A（上传商品图）**：用户上传 → Skill 自动检测质量（分辨率/清晰度/背景/完整度，按详细规则量化标准）→ 不合适则提醒换图并给建议，合适则进入确认
3. **线路B（文字描述生成）**：按详细规则引导用户描述（两轮：必填项+补充项）→ 按品类选prompt模板生成 → 轮询获取结果 → 下载展示
4. **去背景处理**（按详细规则判断）：自动触发（用户要求/纯色背景）/ 建议触发（背景复杂）/ 不建议（场景化需求/边缘复杂）→ 去背景后必须质量检查
5. **多商品场景**（仅套餐商品）：每个商品独立选线路A/B → 统一命名编号 → 确认主从关系和互动关系

→ **用户确认商品图** ✓（确认后进入第二阶段）

**引导方式**：默认推荐式引导（基于品类自动推荐完整方案），用户要求自定义时切换为逐项引导。详见详细规则文档。

逐项引导用户选择（每项给推荐选项，可自定义）：

参数说明示例选项品类商品所属类别食物饮品 / 美妆护肤 / 服饰鞋包 / 电子产品 / 数码配件 / 家居日用 / 家电 / 母婴用品 / 运动户外 / 珠宝饰品 / 汽车用品 / 宠物用品 / 文具办公 / 健康养生**视觉路线实拍 or 动画实拍质感**（追求真实感/摄影质感） / **动画风格**（追求动画/插画/图形化表达）广告目标/CTA广告核心目的品牌曝光 / 促销转化 / 新品上市 / 活动引流目标受众面向人群年龄段 / 性别 / 兴趣标签 / 消费场景风格预设视觉风格（根据视觉路线展示不同选项）实拍路线：16种实拍风格（详见映射文档）；动画路线：6种动画子风格（详见映射文档）。按品类推荐首推风格，可多选，支持参考案例（用户上传参考图/视频）微调色调/氛围微调暖色调/冷色调/高对比/低饱和/柔和等投放渠道/画面比例投放平台抖音9:16 / 小红书9:16 / 朋友圈1:1 / 电商横屏16:9 / 自定义时长目标视频时长5秒 / 15秒 / 30秒 / 自定义（💡 15-30秒是广告主流时长，初次建议15秒起步）全局转场风格镜头间过渡效果硬切 / 溶解 / 划像 / 缩放 / 无转场 / 混合**人物出镜是否需要人物出现在画面中是**（需进一步设定人物形象） / **否**（纯商品展示）**人物出镜说明**：

- 选择"是"后进入人物设定子环节，确定形象后贯穿全链路
- 人物风格默认与商品视觉路线和风格一致，用户可自定义覆盖
- 人物设定作为视觉锚点传递给场景图和视频生成阶段，确保全片人物一致

> ⚠️ **人物出镜审核提醒**（选择"是"时必须告知）：
>
> - 涉及真人形象的内容审核更严格，生成可能被拒绝或需多次调整
> - 人物相关提示词和上传图片由 LibTV 平台审核，Skill 不前置过滤
> - 建议：顾虑审核可选纯商品+场景方案，或用非写实风格降低风险

**人物设定**（仅当人物出镜=是时执行）：

1. **人物来源**：
   - **用户上传参考图**：提取人物特征（面部/体型/发型/服装）生成统一描述卡
   - **AI 生成虚拟人物**：基于品类+商品风格自动推荐人物形象方案，用户可调整
2. **人物形象确认**：
   - 先生成纯白背景（#FFFFFF）人物形象图，画面只有人物本身，展示给用户确认造型
   - 用户确认后生成人物三视图（正面、正侧面、背面），作为后续视觉锚点
   - 人物风格默认沿用商品风格，可自定义覆盖

4. **一致性约束**：描述卡+形象图+三视图作为视觉锚点，在场景图和视频生成时强制引用

→ 人物设定确认 ✓

→ **素材单独导出**：用户可选择仅下载人物形象图或人物三视图（用于其他创作场景），无需等到成片。

**视觉路线说明**：

- **实拍质感**：追求真实感、摄影质感。风格库含 16 种实拍风格（质感/场景/文化/营销四大类）

- **视觉路线影响**：人物设定和三视图生成受视觉路线影响。实拍路线生成真人模特+实拍三视图，动画路线生成虚拟人物+动画设定稿。第四阶段起两条路线合流
- 详细的品类→风格推荐映射和三视图规则见 `2-07-品类风格三视图映射.md`

**模式说明**：

- **精细模式**（默认）：每个环节逐步确认，质量可控

最后 → **生成前时间预估** → 用户确认 ✓

> 注：不主动展示成本/费用信息，避免用户犹豫。若用户主动询问成本，再根据模型单价和生成量给出估算。

### 第三阶段：三视图生成

**目标**：生成商品三视图，锁定商品外观，作为后续场景图的视觉锚点。

**核心规则**：三视图的质量直接决定后续所有画面的一致性。详见 `2-06-三视图生成详细规则.md`。

**子步骤清单**：

- 3.1 商品形象图生成（单独一张，纯白背景）→ 用户确认
- 3.2 三视图生成（基于确认后的形象图，实拍路线/动画路线）
- 3.3 内部质量自检
- 3.4 用户确认三视图 ✓

**流程**：

**第一步：生成商品形象图**

1. 先生成一张商品本身的形象图（非三视图），背景纯白（#FFFFFF），画面中只有商品本身，无其他元素
2. 展示给用户确认商品外观
3. 用户确认后进入三视图生成

**第二步：实拍路线三视图生成**

1. 固定 3 个视角：正面、正侧面、背面
2. 逐张生成三视图，prompt 必须包含：参考声明 + 视角描述 + 商品描述 + 风格关键词 + 统一光照 + 背景描述 + 一致性约束 + 画面比例
3. 光照和背景 3 张统一
4. 调用 LibTV 生成：先 `upload_file.py` 获取 OSS URL，再在消息中引用
5. 轮询获取结果 → 下载 → 内部质量自检 → 展示给用户

**第三步：动画路线三视图生成**

1. 根据动画子风格生成动画设定三视图（详见 `2-07-品类风格三视图映射.md`）：正面设定、正侧面设定、背面设定，保持造型风格统一
2. 调用 LibTV 生成，prompt 策略详见 `2-06-三视图生成详细规则.md` 第三节
3. 轮询获取结果 → 下载 → 内部质量自检 → 展示给用户

**多商品套餐**：每个商品独立生成各自的形象图和三视图，风格统一，主角商品可更精细。

→ **用户确认三视图** ✓（精细模式下确认；快速模式跳过）

→ **素材单独导出**：用户可选择仅下载商品三视图（用于其他设计/电商场景），无需等到成片。

### 第四阶段：品牌元素与片头片尾确认

- 4.2 Slogan确认
- 4.3 片头类型与内容确认
- 4.4 片尾类型与内容确认
- 4.5 品牌一致性确认 ✓

> 📄 **详细规则**：[品牌元素与片头片尾详细规则.md](2-08-%E5%93%81%E7%89%8C%E5%85%83%E7%B4%A0%E4%B8%8E%E7%89%87%E5%A4%B4%E7%89%87%E5%B0%BE%E8%AF%A6%E7%BB%86%E8%A7%84%E5%88%99.md)包含：Logo获取/检测/生成规则、Slogan生成规范、片头类型与时长规则（含风格匹配表）、片尾类型与CTA文案规范、二维码展示规则、品牌一致性规则（色彩/位置/全链路）、确认流程（精细/快速模式）、下游传递信息格式。

**流程**：

1. 是否需要 Logo/Slogan？（是/否）
   - 是 → 用户上传（按详细规则做质量检测和处理）/ Skill 生成（收集品牌信息→生成候选→用户确认）✓
   - 否 → 跳过
2. 片头片尾内容确认：

    - 转场风格
    - 配音/音效概要
    - 向用户展示分镜脚本，提供以下选项：
      - **A. 确认通过** — 进入下一步（生成分镜图选择）
      - **B. 修改指定条目** — 用户指定要修改的镜头编号，局部修改后重新展示完整脚本，再次给出 A/B/C 选项，循环直到用户选择 A
      - **C. 全部重新生成** — 重新生成分镜脚本，再次进入确认流程
    - 列出所有镜头编号及画面描述摘要
    - 用户可选择全部生成、部分生成或跳过不生
12. **生成所选镜头的分镜图**
13. **用户确认分镜图**（支持局部修改循环）：
    - 展示所有已生成分镜图，提供以下选项：
      - **A. 全部确认通过** — 进入第八阶段
      - **B. 修改指定分镜图** — 用户指定不满意的图片编号，仅重新生成这些图片，已确认的图片保持不变；修改后再次展示全部图片，重新给出 A/B/C/D 选项，循环直到用户选择 A

**多商品套餐**：按已确定的主次关系和时长分配编排各商品出场顺序。

**执行流程**：

1. **分段生成**：按分镜逐镜头生成视频片段
   - 单片段时长受 LibTV 模型上限约束（通常 5-10 秒/段）
   - 使用场景图作为起始帧参考，确保画面一致性
2. **用户预览确认各片段**：所有片段生成完毕后，**暂停**，逐个展示给用户预览
   - 展示每个片段的预览视频/截图，标注对应镜头号
   - **动作连贯性重点检查**（铁律7）：
     - 运动方向检查：主体（车辆/人物/物体）在相邻片段中的运动方向是否与分镜一致，不得出现方向矛盾（如车辆一会向左一会向右）
     - 人物动作检查：人物动作时序是否连贯，不得出现动作倒序或重复（如下车后又开车门）
     - 位置关系检查：物体/人物在画面中的位置关系在相邻片段间是否合理过渡
   - 用户可逐一点评：满意→标记通过 / 不满意→指出问题→重新生成该片段
   - 所有片段确认后，才进入合成拼接阶段
   - 避免合成后发现问题导致整体返工
3. **片段拼接**：按分镜顺序拼接所有片段，自动插入转场效果
4. **音频合成**：
   - 叠加配音 + 音效（按分镜时间线对齐）
   - 字幕、BGM 仅在用户明确选择时叠加
5. **合规检查（第二轮：成片前最终审查）**：Skill 内部执行
   - 确认最终画面、配音、文字均合规
   - 不合规 → 标记具体问题，回到对应环节修改后重新生成，再次合规检查直到通过
6. **成片预览**：合规通过后，完整播放给用户（含画面+配音+音效+字幕/BGM）

## LibTV API 调用规范

本 Skill 通过 LibTV 官方脚本完成所有图片/视频生成任务：

### 核心脚本

脚本用途调用时机`create_session.py`创建会话/发送消息每个需要生成的环节`query_session.py`查询会话进展轮询生成结果`upload_file.py`上传文件到 OSS用户上传商品图/参考图时`download_results.py`下载生成结果每个环节生成完成后`change_project.py`切换项目多项目/多版本派生时

### 调用流程（每个生成环节通用）

```
1. upload_file.py /path/to/file → 拿到 OSS URL（如有文件需上传）
2. create_session.py "生成指令描述" → 拿到 sessionId + projectUuid
3. 每 8 秒调用 query_session.py SESSION_ID --after-seq N 轮询
4. 当 messages 中出现 assistant 消息且包含结果 URL → 任务完成
5. download_results.py SESSION_ID --output-dir ./项目目录/阶段名 --prefix 有意义的前缀
6. 向用户展示结果
```

### 轮询策略

- 间隔：每 8 秒查询一次
- 增量拉取：首次用 `--after-seq 0`，后续用上次拿到的最大 seq 值
- 完成判断：messages 中出现 assistant 消息且 content 包含结果 URL
- 超时：连续轮询 3 分钟仍无结果，告知用户"生成时间较长，可稍后查看"
- 错误重试：单次查询失败可重试 1 次，连续 3 次失败则停止并告知用户

### 关键约束

- 用户侧不做创作，只做传话：把用户的原始描述 + OSS URL 传给 create_session.py
- 不要在消息中自行添加 prompt 修饰词（如"超写实风格，电影级光影"）
- 风格描述在第二阶段由用户选定，通过 create_session 消息原封不动传递
- 项目画布地址仅在任务完成后展示给用户，过程中不展示

## 合规检查规则

合规检查词库详见 `3-17-合规检查词库.md`，基于《广告法》《互联网广告管理办法》《直播电商监督管理办法》《广告绝对化用语执法指南》（2026年实施）整理。

### 第一轮（分镜完成后）

- 审查剧本+分镜中的文字内容（含旁白/台词/对话/画面中可见文字/音效描述）
- 检查项：绝对化用语、虚假承诺、医疗暗示、诱导消费、政治敏感、低俗迷信、对比贬低、专利/认证违规、行业专属规则
- 处理方式：
  - 一级词（绝对化/政治敏感/低俗/欺诈）→ 自动替换为合规表述，标记修改位置
  - 二级词（虚假承诺/医疗暗示/诱导消费）→ 自动替换，无法替换时删除重写
  - 三级词（模糊数据/时限不明）→ 标记风险，提醒用户确认或补充
- 不合规 → 自动修正后重新检查，直到通过

### 第二轮（成片生成后、预览前）

- 审查最终视频中的画面+配音+字幕/文字叠加内容
- 检查项：画面合规、配音文字合规、文字叠加合规、大小字一致性、AI标注要求
- 不合规 → 标记问题，回到对应环节修改，重新生成后再次检查

### 修改后重审

- 任何修改后重新生成的版本，必须再过一次对应轮次的合规检查

### 2026年特别规则

- 谐音/变体/拼音缩写/符号替代视为与直接使用同等违规
- 误导性大小字广告可认定为虚假广告
- AI生成内容须显著标注
- 提示性用语（如"本品不能代替药物"）弱化标注可罚款

## 注意事项

- 鉴权方式为请求头 `Authorization: Bearer <LIBTV_ACCESS_KEY>`
- 上传文件仅支持图片（image/*）和视频（video/*）类型，文件大小须在 200MB 以下
- 上传返回的 OSS 地址格式为 `https://libtv-res.liblib.art/claw/{projectUuid}/{uuid}{ext}`
- 生成过程中只告知用户"正在生成中"，不提前给出项目画布链接
- 任务完成时同时给出：结果链接（图片/视频 URL）+ 项目画布链接（projectUrl）
- 项目画布地址固定为：`https://www.liblib.tv/canvas?projectId=` + projectUuid
