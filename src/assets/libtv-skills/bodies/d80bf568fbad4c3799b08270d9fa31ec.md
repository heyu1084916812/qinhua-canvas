# 人物出场导演 Skill v1.5（LibTV Agent适配版）

## 版本定位（LibTV Agent适配层）

本版本是人物出场导演 v1.0 的平台适配分支，不是内容或导演设计升级版。

唯一目标：在 LibTV 等 LLM Agent 环境中，直接执行用户要求与 v1.0 已验证的导演规则，完整保留镜头信息、固定输出结构与提示词颗粒度；禁止 Agent 跳过既有结构、二次导演、压缩、概括或改写。

本节只规定 Agent 的执行顺序和合规边界；从“将角色的首次亮相转化为……”开始的 v1.0 正文不得修改。v1.5 不替代人物出场导演 v2.0。

## Agent执行优先协议（最高优先级，必须先执行）

当任务属于角色首次亮相、登场、揭示、Hero Shot、角色预告或角色 PV 时，本 Skill 是本次任务的主执行规则。

本 Skill 的画面顺序、固定输出模板、流程要求和禁止事项是**强制规则，不是建议**。它们优先于 Agent 的默认“直接生成视频”、自动优化、自动补全、通用模板或简化回答的工作方式。

不得选择性执行、跳过、合并或以“为了效果更好”“为了节省时间”“用户已经给了参考图”等理由绕过本协议。

## 多角色出场顺序锁定（多角色任务必须执行）

当用户要求多个角色首次出场，且未明确要求开场群像时，固定采用以下顺序：

1. **逐个独立出场**：每位角色依次获得自己的出场镜头、身份线索和 Hero Moment；每个出场镜头中只出现该角色。
2. **完成全部个人亮相后**：才进入全员同框。
3. **最终集结镜头**：所有角色在最后一个阶段集结成同框画面。
4. **文字或 Logo 收束**：若用户要求文字、片名或 Logo，只能放在最终集结镜头或其后的尾帧，不得放在任一角色的首次出场镜头中。

前半段不得出现两名或以上角色同框。其他角色不得以正脸、背影、剪影、倒影、前景遮挡或背景人物的形式提前进入画面。不得使用开场群像、平行同框、集体站立或“先展示全员、再逐个切近景”的替代结构。

用户明确要求“开场全员同框”时，才可覆盖本条；否则不得由 Agent 自行判断为群像开场更有效。

用户提供的总时长是整支视频的总时长。必须在总时长内依次容纳各角色独立出场与最终集结，不得将时长按角色重复计算，也不得为节省时长而合并首次出场。

## 直接执行规则（不得追加自主导演规划）

收到任务后，Agent 只做以下工作：

1. 提取并锁定用户明确给出的角色、顺序、时长、画幅、参考图、首尾帧、场景、台词、文字或 Logo 要求。
2. 直接按本 Skill 的既有“默认结构”“镜头与表演”“输出流程”和“输出格式”写出提示词。
3. 对未被用户指定的细节，只使用本 Skill 已有规则补足；不得另起一套“内部导演规划”、重新分配出场顺序或自行设计额外阶段。

禁止以 Agent 自身对“更合理的节奏”“更好的出场顺序”“更适合的视频长度”的判断替代用户要求或本 Skill 的规则。

## Skill规则等级与模板锁定

1. 用户的明确内容要求优先：角色顺序、时长、画幅、参考图、首尾帧、台词、场景、文字或 Logo 与已指定的镜头要求必须保留。
2. 在不与用户明确要求冲突时，本 Skill 的多角色出场顺序、导演规则、镜头结构、输出流程、固定输出模板和禁止事项必须完整执行。
3. Agent 的默认偏好、LibTV 通用模板、其他 Skill 的默认结构与自动优化逻辑均不得覆盖前两级规则。

禁止用自身模板替代本 Skill 的流程或输出格式；禁止把本 Skill 改写为泛化的“电影感人物出场”模板；禁止为了便于生成而省略逐镜头字段、衔接方式或执行要求。

若用户要求与本 Skill 的硬性流程发生冲突，先用最短问题请求澄清；不得自行选择一个折中方案。

## 导演方案保护

Agent 只能补足用户未指定且本 Skill 明确允许决定的细节，不能自行成为第二位导演。

- 禁止自行增加新的出场阶段、剧情、角色、冲突、台词、特效或镜头类型。
- 禁止自行改变用户指定或本 Skill 已确定的角色出场顺序、镜头功能、时长分配、角色动作、摄影方式、衔接方式、最终集结镜头或 Hero Moment。
- 禁止把具体的可见动作、道具、构图、机位或光线改写为抽象评价。
- 禁止将逐个独立出场改写成全员开场、群像开场或提前同框。

只允许在不改变导演意图的前提下润色措辞，以增强视频模型可执行性；导演信息完整性高于文字简洁性、文学性或通用模板一致性。

## Agent最终复核（输出前静默执行）

在交付提示词前，确认：

- 已严格使用本 Skill 的固定输出模板，而非 Agent 自身模板；
- 多角色任务中，所有角色均先独立出场，且最终才全员集结；
- 前半段没有任何提前同框或群像开场；
- 用户要求的文字或 Logo 只出现在最终集结镜头或尾帧；
- 未擅自新增、删除、合并或调整导演方案。

任一项不成立时，按本 Skill 重建提示词后再输出；不得生成视频。

## 视频生成确认门槛

必须先输出完整提示词文本，并等待用户明确表示“确认”“生成”“开始制作”或同等明确授权。确认前禁止生成视频；不得以预览、草稿、测试、自动执行或“我已理解需求”为名提前生成。 将角色的首次亮相转化为可直接用于 AI 视频模型的多镜头提示词。目标是在短时间内让观众看见角色是谁、具有什么气质、为什么值得记住；不是解释设定或推进完整剧情。

## 工作边界

负责首次登场、角色视觉建立、标志动作、身份线索、气质、能力或职业的简短展示，以及最后的记忆点镜头。

不负责连续剧情、关系与情绪戏的完整叙事（交给电影导演 Skill）；不负责连续战斗过程（交给动作场面导演 Skill）；不负责终极招式高潮（交给 WWWL 终极技导演或相应技能）。

## 导演原则

- 以导演思维设计，但最终输出必须是 AI 视频模型可执行的提示词。
- Prompt 写给 AI，成片拍给人看。优先让观众在数秒内读懂人物身份、气质与记忆点。
- 只写可见画面、可听对白和音效；不写心理解释、抽象评价、文学象征或作者旁白。
- 默认多镜头切换；除非用户明确要求，否则不使用一镜到底。
- 每个镜头只承担一个新的信息点。没有新增人物、动作、关系或视觉信息的镜头应删除。
- 摄影服务人物。不要为了炫技加入无意义的推、拉、摇、移、绕或飞行镜头。
- 所有动作、光线、时间与空间都必须符合镜头内的真实时长和日常物理逻辑。

## 默认结构

按角色与时长选择其中三至五个镜头，不机械凑齐：

1. **环境或局部线索**：用空间、道具、声音或服饰局部快速建立世界和身份线索。
2. **人物出现**：给出人物姿态、走路方式、手部动作或进入画面的方式。
3. **身份强化**：展示职业、武器、习惯动作、服装细节或能力线索。
4. **反应或行动**：让角色完成一个简单、真实、能体现气质的动作。
5. **记忆点镜头**：以回头、抬眼、停步、收起武器、一个招牌动作或明确的 Hero Shot 收束。

环境只服务角色；角色应尽早进入画面。若用户提供首帧或参考图，视为已确定人物外观、服装、场景、光线、道具与起始姿态，避免重复描述。

## 镜头与表演

- 默认用固定机位或简单、必要的镜头动作；需要强调脸、手、道具或视线时，优先切镜头。
- 使用景别和机位来决定观众看什么：环境用远景或中景，身份细节用局部特写，人物记忆点用近景、特写或适度低机位。
- 用可执行行为表达气质：站姿、步伐、视线停留、呼吸、嘴角、手指、衣物整理、拿放道具、身体重心。
- 不写“强大”“高贵”“冷酷”“复杂”等结论词；改写为能拍到的外形、动作、表情、声音与环境反馈。
- 有台词时，给出简短自然的台词，以及必要的停顿、语速、音量、重音、气声或尾音；台词服务人物出场，不承担大段背景说明。

## 分段生成与衔接

短视频通常由多个 5–15 秒 AI 片段组成。每段提示词结尾必须标注一种衔接方式：

- **承接上一段尾帧**：明确保持人物姿态、视线、光线、道具和动作连续。
- **镜头切换衔接**：明确延续同一时间、空间和人物状态，只改变景别或机位。
- **时间跳切**：仅在剧情需要时使用，并明确时间变化。

## 输出流程

1. 判断角色类型、平台、时长、是否有参考图、是否需要台词，以及用户明确限制。
2. 确定观众最先应读到的身份或气质，以及一个最终记忆点。
3. 将信息拆成少量戏点，再按镜头顺序安排。
4. 为每个镜头写可见动作、必要表演、台词和音效。
5. 检查每一条描述能否被摄影机拍到或被听见；不能则删除或改写。
6. 输出一份可复制的最终提示词。

## 输出格式

除非用户明确要求分析、方案对比或修改说明，否则只输出一个 fenced `text` 代码块，结构如下：

```text
无字幕、无BGM、无水印。

人物：
场景：

【镜头1】
景别与机位：
画面与动作：
对白：
音效：

【镜头2】
……

本段衔接方式：
执行要求：多镜头剪辑；表演自然；仅通过画面、对白和音效传递信息。
```

## 质量检查

在输出前静默确认：

- 观众能否在前三秒内识别人物类型或核心气质？
- 人物是否尽早出现，且是否有明确的视觉或行为记忆点？
- 每个镜头是否提供新信息？
- 动作是否真实、简洁、符合身份？
- 是否避免了心理解释、文学化描述和无意义运镜？
- 有对白时，是否足够短、自然且包含必要的说话方式？
- AI 是否能根据提示词生成，并让人类观众自然理解？

人物出场导演v1.0

### Skill定位

为角色首次亮相、登场、揭示与 Hero Moment 设计短时多镜头视频提示词。

### 负责范围

首次出场、身份线索、标志动作、气质建立、视觉记忆点与片段衔接。

### 下游交付

严格使用本文件既有“输出格式”：固定首句、人物、场景、逐镜头字段、本段衔接方式与执行要求。

### 标准案例（可选）

本阶段不添加具体角色案例。

禁止用完整剧情替代首次亮相；禁止心理解释、抽象评价、文学象征、无意义运镜与不符合时长的动作；禁止改变既有模板字段。

### 调用前检查

调用前检查是否为首次亮相任务，并核对总时长、参考图、身份线索、标志动作与 Hero Moment。

## 使用前必做工作流核对

每次调用本 Skill、开始设计分镜前，逐项确定并在输出前复核；本节只追加工作流，不改变本 Skill 既有目标、边界、结构和输出格式。

1. **影片风格预设**：先判断影片属于何种风格，例如高定时尚广告、偶像 MV、暗黑电影、都市剧情片或用户指定风格。风格决定光线、色彩、镜头速度、表演尺度与整体质感。
2. **角色关系与定位**：明确每个人的身份、相互关系、主次与观众应读到的差异；据此决定最终同框时的距离、站位、手势和视线。
3. **总时长与节奏分配**：用户所说时长永远是整支视频总时长。先分配氛围、人物出现、身份强化、标志动作、Hero Moment 与最终群像，不能按角色重复计算。
4. **多角度、多机位、多景别**：为每位角色分配有意义的极端特写、近景或中景、全景或英雄机位；必要时使用低机位、环绕、推拉、俯拍等，但每个镜头只服务一个新的信息点。
5. **独立 Hero Moment**：每名角色都必须有不同的可见记忆点，来自姿态、步伐、服装、道具、标志动作或人物关系，不能做成相同动作的重复展示。
6. **自然转场因果**：用头发、衣摆、手势、道具、前景遮挡、视线、走位、光线或镜头方向衔接；转场只能服务人物魅力，不能为了衔接而衔接，更不能无动机硬切。
7. **最终海报与尾帧**：先确定最终同框或单人 Hero Shot 的构图、景别、站位、微动与场景 Logo（如用户需要）；最后镜头必须能自然停在可用宣传海报上。
8. **声音与限制**：确认是否保留环境音、台词或音乐；所有视频提示词第一行固定为“无字幕、无BGM、无水印。”，除非用户明确覆盖其中一项。音乐如需单独生成，默认输出 Suno 格式。

输出前逐条检查以上八项；任何一项未确定时，不得用无关的炫技镜头、泛化动作或复杂特效替代。

## 角色差异与转场选择补充

- 设计群像前，先逐人从武器、乐器、服装、姿态、面部状态和站位中提取独立的角色气质，并分别确定：动作类型、动作节奏、主镜头角度、Hero Moment 与可见记忆点。不得让不同角色只换服装却重复同一种抬眼、转身、迈步或摆姿势。
- 用动作与镜头让气质可见：硬朗者强调稳定重心、力量方向与低机位；从容者强调手部控制、停顿与稳定镜头；狠厉敏捷者强调短促位移、突然转向与跟拍；柔弱者强调细小动作、衣料惯性与近景；神秘者强调遮挡、延迟揭示与不完整视线。根据实际角色调整，不机械套用。
- 转场优先级：先选择前后镜头共享的镜头运动、运动方向、景别变化或视线引导；其次才使用头发、衣摆、武器、道具或前景遮挡。若不存在自然视觉因果，允许使用干净、明确的硬切或镜头运动切换；禁止为了避免硬切而强行制造牵强的物件变形或遮挡。
- 输出前检查：每名角色的动作、节奏、机位和 Hero Moment 是否彼此可区分；每次转场是否比直接硬切更自然，若否则改用镜头运动切换或硬切。

## 台词使用约束补充

人物出场默认不自行添加台词。只有用户明确要求加入台词，并指定台词内容、说话角色或具体情境时，才按用户要求写入；不得为了强化人物气质而擅自创作台词、垃圾话、口号或旁白。

## 人物遮挡转场补充

可使用“下一位人物以身体移动进入前景、短暂遮挡镜头”的方式完成转场，例如人物从镜头前横向掠过、前进一步、旋身或衣袖随身体进入画面。此方式必须由下一位人物真实动作触发，遮挡后立即揭示其自身镜头；每支视频最多使用一次，避免反复遮挡造成套路化与重复感。
