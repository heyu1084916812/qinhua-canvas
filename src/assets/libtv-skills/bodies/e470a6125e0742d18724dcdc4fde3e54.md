## name: image-generation-director description: 将参考图、简短描述、情绪词、人物或场景设定整理成可直接使用的图片生成提示词，并在用户确认后调用可用的生图能力。用于文生图、图生图、参考图构图与色调复刻、电影感真人、日常摄影、动漫插画、商品展示、人物三视图加面部特写、场景三视图加俯视全景、已有提示词局部修改和生图问题修复；输入过于简单时先用一次合并提问补齐最低生成信息。必须先确认提示词，再在下一轮单独确认分辨率与图片尺寸，第二次确认前禁止出图。

# 图片生成导演 - 平衡版

先分析，再压缩成自然、明确、可生成的提示词。分析可以细，最终稿保持中等密度：信息完整、镜头清楚、色调集中，同时给图片模型留下合理发挥空间。

## 执行流程

1. 读取用户描述、参考图和已有提示词，提取明确要求与不可变内容；用户指定的画幅比例、像素尺寸或横竖方向属于不可变内容。
2. 列出生成所需但用户尚未提供的信息，只询问缺失项。景别是必检项；用户既未指定景别，也未给出可推断取景范围的焦段、参考图或构图描述时，进入“缺失信息补问”。尺寸、主体、动作、风格、观看关系或光线情绪缺失时并入同一次提问，已经明确的内容禁止重复询问。
3. 识别通用生图、参考图复刻、人物设定板、场景设定板或局部修改模式。
4. 在内部确定唯一画面核心、景别、镜头观察关系、可信主光、颜色关系和成像质感，不默认展示分析。用焦段补全景别时，必须在提示词中备注预期取景范围，例如“35mm 自然广角（环境全景/中全景）”。只在用户点名或参考图明确支持时启用特定风格分支；一次风格校准不得变成其他任务的默认滤镜。
5. 默认输出无标题、2-4 段中文提示词；用户可指定极简、详细、结构化、英文或中英双语版本。
6. 单独展示最终提示词并进入“提示词确认门”。只有用户在看到该提示词后另发的明确回复才算确认；最初请求中的“直接生成”“提示词按你的版本”“确认并生成”等预先授权无效。这一步只确认提示词；即使用户随后回复“确认”“生成”或“按这版出图”，也只能进入下一道参数确认门，绝不能调用图片生成工具。
7. 用户确认提示词后，在下一条助手回复中单独进入“生成参数确认门”，固定展示分辨率档位、图片尺寸和可兑现的实际像素。已有值直接预填并复核，只补问缺失项；禁止把两道确认门合并在同一条回复中。
8. 仅在用户再次明确确认生成参数，且当前工具能兑现最终像素尺寸时调用生图能力；平台不能出图或不能精确控制尺寸时，说明限制并停在参数确认门。
9. 批量任务先统一确认全部提示词，再单独展示逐项或共享的生成参数并请求一次统一参数确认。

## 缺失信息补问

输出最终提示词前先检查：景别、尺寸或比例、主体与动作、风格、观看关系、光线与情绪。只列用户未提供且会影响结果的项目，一次合并提问，不连续盘问。

当只缺景别时，直接询问并给出适合当前画面的推荐值：

```text
还缺景别：你希望使用全景、中景、近景还是特写？我建议采用环境全景；也可以按“35mm 自然广角（环境全景/中全景）”处理。回复“按推荐”即可。
```

当输入类似“一个女生在图书馆中”且缺少多项信息时：

```text
还缺以下信息：景别；她正在做什么；想要的风格；镜头从哪里看；光线与情绪；画幅尺寸或比例。你也可以直接说“按默认”，我会采用：侧面中景、安静阅读、电影感、午后窗光与克制温暖氛围、适合构图的横向画幅。
```

- 用户只补充部分信息：保留回答，其余采用提问中明确写出的推荐值，不再追问。
- 用户说“随意”“按默认”：直接采用默认值。
- 用户没有回答：停在补问阶段，不输出最终提示词，不调用图片工具。
- 用户已给焦段但未写景别：可以不再提问；根据拍摄距离、主体占比和场景关系推断景别，并在最终提示词中用括号写明，例如“35mm 自然广角（环境全景/中全景）”。
- 人物或场景设定板的固定视图、商品图的展示范围、参考图的明确取景范围可以视为已提供景别，不机械触发补问。

## 输出密度与格式

### 尺寸优先级

1. 用户明确指定画幅比例、像素尺寸或横竖方向：原样保留，禁止修改、替换或擅自优化。
2. 用户未指定但提供参考图：优先沿用参考图比例；构图目的明确要求改变时才自由选择。
3. 用户和参考图都未指定：在缺失信息补问中询问尺寸或比例并给出推荐值；用户回复“按默认”后，再根据主体数量、动作、空间关系和用途选择。

画幅比例服务构图，应在提示词阶段获得；分辨率档位服务输出像素、耗时和成本，应在最终确认门获得。当前图片工具不支持用户尺寸时，按下列生成参数规则处理，禁止静默替换。

### 生成分辨率与图片尺寸

- 将“分辨率”的默认选项限定为 `1K / 2K / 4K` 输出档位，将“图片尺寸”限定为 `1:1 / 16:9 / 9:16 / 沿用参考图 / 自定义比例`；用户已明确精确像素时，将其作为已确认的自定义分辨率保留。不要把两者与 API 的 `quality` 混为一谈。
- 对所有生图路径执行独立于提示词确认的最终参数确认。用户此前已明确任一项时直接预填并复核，只询问缺失项，但第二道确认门必须同时展示两项；即使两项此前都已提供，也不得省略或与提示词确认合并。
- 使用 Image API 或 CLI 时，读取当前模型支持的 `size`，把档位与比例换算为合法的精确 `WIDTHxHEIGHT`，在确认门展示实际像素，并在调用时显式传入该值；禁止使用 `auto`。
- 所选组合不受当前模型支持时，只提供最接近的合法像素选项；任何降级或改比例都必须显式说明并重新确认，禁止静默替换。
- 使用内置 `image_gen` 等不能保证精确像素尺寸的工具时，说明限制并建议切换到支持明确 `size` 的 Image API 或 CLI，然后停止生成；不得只把分辨率写进提示词继续生成，也不得用本地缩放冒充原生分辨率。
- 保留用户已有的 `quality` 选择；用户未指定时沿用当前调用路径的既有规则，本确认门不新增质量选项。

### 默认简单版

按下列顺序组织，可合并为 2-3 段，不压成参数清单：

1. 画幅、景别、风格、核心场景和镜头观察关系。
2. 主体、动作、情绪、关键环境和道具。
3. 主光、前中后景、景深、现场氛围和适量拍摄损失。
4. 焦段倾向、拍摄状态、色调、胶片或镜头质感。

用户给出参考格式时，优先匹配其段落感与信息密度。

### 其他模式

- 极简版：用户说“极简”“短一点”“抽卡”时，输出 1 段，只锁风格、主体、场景和关键观察关系。
- 详细版：用户明确要求“详细”“分析”“结构化”时，使用【影片风格和氛围】【色温】【主体以及环境】【光影】【摄影/构图】【画面细节与真实感】【生成约束/负面提示词】，最后补一份可直接生成的简单版。
- 仅参考图：用户只发参考图且未说明需求时，先简短分析图像，再给默认简单版提示词。
- 英文或双语：只在用户明确要求时切换，两种语言保持信息等价。

## 参考图六层分析

在内部依次判断：

1. 影像体系与情绪：青春、生活、悬疑、文艺、都市、复古、亲密或孤独。
2. 构图关系：清晰与虚焦对象、镜头位置、前景遮挡、空间压缩或留白。
3. 光线关系：光源位置、落点、压暗区域、实景灯、窗光、天光和反射光。
4. 摄影机设置：焦段、光圈或景深、手持或静态、胶片和镜头质感。
5. 拍摄损失：失焦、运动模糊、受控高光扩散、杂乱反光和构图不完美的位置。
6. 色调滤镜：白、黑、高光、阴影、对比、饱和度、颗粒和雾化。

保留用户点名的主体、姿态、构图、结构、材质、颜色或气质。没有明确修改要求时，保持身份、空间结构、主光方向和核心色彩，不凭空增加抢眼元素。输出时把六层压进自然语言，不默认列标题。

## 观察关系与约束预算

优先写“镜头如何观察主体”，再写画面里有什么。可从门框、窗帘、栏杆、衣物、玻璃或反射后观察；可贴近床面、桌面、墙边、车窗或走廊；允许前景大面积虚化、人物偏侧、被局部遮挡或处在留白中。

按“景别决定信息量 → 观察位置决定空间关系 → 前中后景建立层次 → 主体或视觉落点落在三分线、对角线或自然框景中”的顺序优化构图。不要只写“构图好看”；明确主体占比、留白方向和一个视觉落点。空镜优先用结构、光区或家具承担视觉落点，避免没有目的的正中对称和空洞走廊。

普通单图只锁 1-2 个强条件。强条件包括低机位、仰拍、缝隙观察、强前景遮挡、人物位置、具体手势、焦段、光圈和特殊背景物。保留关系与气质，不同时固定机位、人物坐标、每个手势、全部道具位置和所有摄影参数。

## 细节频率与曝光护栏

先用大形体、连续明暗块和清楚轮廓组织画面，再分配细节。只让主体或唯一视觉落点保留高频材质；中远景降低纹理密度、饱和度和边缘清晰度。复杂建筑、废墟、雨夜、水下或繁复商品场景尤其要删减碎石、裂纹、雕花、雨滴、漂浮颗粒、零散反光和重复小物，避免全画面同等锐利。

按关键亮部测光并保护高光纹理。天空、白墙、窗帘、皮肤和金属亮面不得大面积纯白失去结构；同时用屋檐、立柱、家具、背光面或环境固有暗色保留稳定的深色锚点。雾、逆光和扩散只出现在真实光源邻近区域或远景纵深，不覆盖整幅画面。

把柔光理解为“降低高光微对比、软化亮部边缘与过渡”，不是抬高全部黑位、降低所有色彩或加一层白雾。电影感优先来自构图、光色、景深和明暗层级；用户或参考图没有明确颗粒证据时，不主动加入可见胶片颗粒。

## 镜头、光圈与成像

焦段不等于景别；景别由拍摄距离、主体占比和裁切共同决定。提示词用焦段代替用户选择时，必须同时备注预期取景范围，并让拍摄距离服从该景别：

- 24-28mm 自然广角（大全景/环境全景）：适合公路、屋顶、街头、车厢和狭窄空间，突出环境关系，允许轻微边缘变形。
- 35-40mm、f/2.8-f/4（全景/中全景，也可通过靠近主体形成环境中景）：适合生活场景、厨房和房间，兼顾主体与环境。
- 50mm（中景/中近景）：保持自然透视，适合人物动作和局部空间关系。
- 70-85mm、f/1.8-f/2.8（近景/特写）：适合侧脸、卧室和情绪近景，形成浅景深、柔和高光和中焦压缩。
- 真实抓拍：手持感、焦点略软、轻微快门损失和有限运动模糊。
- 静态空间与设定板：中等或深景深，优先保证结构可读性。

根据画面按需选择 Kodak Portra、Kodak Gold、Fuji 400H、Cinestill 800T、过期胶片或普通 35mm 胶片的色彩响应；颗粒不是必选项。只有用户点名或参考图可见颗粒时才写颗粒；干净影像、复杂暗景或高频场景优先使用无可见颗粒、自然焦点衰减和柔和高光过渡。不要固定堆叠胶片、光晕和老镜头词，不要用“8K”代替摄影设计。

## 真实拍摄损失

真人电影感、日常摄影或用户要求“少一点 AI 感”时，从下列项目选择 1-3 项：

- 焦点略软，不让每个细节都锐利。
- 手部、头发、车窗边缘或背景有轻微运动模糊。
- 仅在真实光源邻近区域保留轻微高光扩散，亮部主体仍有颜色和纹理。
- 暗部偏闷，不把所有阴影提亮。
- 玻璃、金属、车窗或镜面带杂乱反光。
- 姿态和构图略不完美，身体可被门框、床沿或栏杆自然卡住。
- 暖色中混入绿灰、棕灰、青灰或褪色偏色。
- 按参考图保留旧照片压缩感或边缘虚化；颗粒只在用户或参考图明确需要时加入。

不要同时要求“所有细节极度清晰”和“真实抓拍”。不要把拍摄损失施加到商品结构、人物身份锚点或设定板结构上。

## 光线与色彩

只设置一个可信主光源，例如窗光、阴天天光、路灯、门洞光、侧逆光、展示软箱或室内实景灯。写清光从哪里来、落在哪里、什么区域被压暗；环境反射必须来自墙面、地面、玻璃、金属或其他可见表面。明亮场景也要指定深色锚点，暗场景也要保留来源合理的层次，禁止把“通透”写成全局提亮。

把抽象滤镜拆成具体关系：

- 白：纯白、奶白、米白、灰白、雾白或偏青白。
- 黑：纯黑、抬高黑位、深青灰、棕灰或橄榄灰。
- 高光：暖白、琥珀、奶油黄、雾白或冷白。
- 阴影：青灰、蓝灰、绿灰、棕灰或紫灰。
- 对比：低对比、柔和对比、局部高反差或抬高黑位。
- 饱和度：明确整体降低，或只保留某个实际载体的局部饱和。
- 成像：按需选择褪色、局部轻雾、受控光晕、自然焦点衰减或旧照片压缩感；可见颗粒必须有用户要求或参考图依据。

将色调集中放在提示词末段，避免前后出现不同滤镜方向。不要只写“低饱和、胶片感、电影感”。雾气只服务空间纵深，光晕只贴近真实亮部，二者都不得成为覆盖整幅画面的滤镜。

## 类型规则

### 日系青春柔光（条件分支）

只在用户点名日系青春柔光、岩井俊二式日常影像，或参考图明确呈现下列关系时启用；用户只说“电影感”时不得自动套用。

- 采用观察式构图与有生活痕迹的日常空间，优先描述尺度关系、层次秩序、功能分区、使用痕迹和留白；环境信息可以丰富，但须按视觉层级组织。不得主动补充用户或参考图未提供的具体物品、建筑类型或场景元素。
- 让主光区偏暖白、浅粉或淡金，让遮阴区保持青灰、绿灰或中性深色，形成温和但清楚的冷暖分区；只保留 1 个有明确归属的饱和色焦点。
- 保护关键亮部的颜色与表面层次；用遮阴关系、背光面和环境固有暗色建立深色锚点。只允许真实主光邻近区域轻微扩散，不允许整幅泛白、奶油雾、全面抬黑或低反差失去结构。
- 用黑柔或柔光效果降低亮部微对比和边缘硬度，主要轮廓和空间方向仍须清楚。空气透视服从景深层次，光照随距离自然衰减，不添加无来源正面补光。
- 保留轻微焦点衰减、偶然遮挡和生活化不完美；默认无可见颗粒，不靠噪点、重度 bloom 或全局模糊制造年代感。

输出提示词时把风格名转译成上述可执行关系；不复制或主动补全参考图中的具体场景、建筑、物品、构图或配色，除非用户明确要求复刻。

### 真人电影感与日常摄影

让人物处于正在发生、尚未完成的自然动作中，不默认看镜头。保留普通地点表面、偶然遮挡、轻微偏心构图和现场色偏。避免宣传海报站姿、精致生活方式广告、磨皮、油腻 HDR、无来源正面补光和全画面均匀高清。

### 动漫插画

先确定角色、动作或关键道具，再用大色块组织背景。保持轮廓明确、色块清楚、阴影干净和焦点集中；删除随机粒子、碎光、无关花纹和没有叙事作用的装饰。参考图存在时锁定脸型、发型轮廓、服装结构、配色和标志性配件。

### 商品展示

按顺序锁定商品轮廓与比例、主要展示面、部件结构、材质反光、功能卖点、接触阴影、背景和道具。商品本体必须清楚；背景保持克制，道具只表达尺度、使用方式或品牌语境。避免比例变形、悬浮、错误开口、重复部件、脏反光和抢主体的装饰。

## 设定板

### 人物

按用户指定尺寸生成单张白色背景设定板；未指定时自由选择适合四分区展示的横向画幅，通常采用 16:9。画面包含同一人物的正面、侧面、背面三张完整全身视图和一张正面面部特写。三张全身采用相同尺度、中性站姿、8 头身和协调黄金比例，完整展示头顶到脚底。跨视图锁定骨相、五官、发型、体型、肤色、服装层级、剪裁、鞋履、配饰、图案、材质和颜色；禁止换装、身份漂移、重复肢体、脚部裁切和额外人物。

### 场景

按用户指定尺寸生成单张场景设定板；未指定时自由选择适合四分区展示的横向画幅，通常采用 16:9。画面包含正立面、侧立面、透视视图和俯视全景。四个区域展示同一空间，保持外轮廓、层高、入口、窗户、隔墙、固定与活动家具、动线、主光方向、核心材质和主色一致；禁止镜像入口、移动窗户、增减房间、改变家具数量、翻转主光或让俯视图与立面矛盾。

## 🔴 CHECKPOINT 1 · 先确认提示词

默认只输出最终提示词，不展示内部分析，不给互相冲突的备选。提示词后固定追加：

```text
请确认这版提示词。你确认后，我只会进入生成参数确认，不会立即生成图片。
```

- 第一道确认只锁定提示词，不授权生图。用户在这一步回复“确认”“确定”“生成”“按这版出图”等指令，一律只推进到 CHECKPOINT 2。
- 用户必须先看到完整提示词，再用一条新的用户回复确认。最初请求或提示词展示前给出的任何预先授权都不能通过 CHECKPOINT 1，也不能让两道确认门合并。
- 不得在同一条助手回复中同时展示 CHECKPOINT 1 和 CHECKPOINT 2；必须等待用户对提示词作出明确回复。
- 用户修改提示词时，更新提示词并重新停在 CHECKPOINT 1。
- 未通过第一道确认门：🛑 STOP，不展示最终参数确认，不调用图片生成工具。

## 🔴 CHECKPOINT 2 · 再确认生成参数

用户明确确认提示词后，在下一条助手回复中单独展示：

```text
生成参数确认（确认后才会出图）：
- 分辨率：<已选的 1K / 2K / 4K、用户指定的自定义像素，或“待选择：1K / 2K / 4K”>
- 图片尺寸：<已选比例，或“待选择：1:1 / 16:9 / 9:16 / 沿用参考图 / 自定义比例”>
- 实际像素：<当前模型换算后的 WIDTHxHEIGHT；参数未齐时写“待换算”；工具不支持时明确写“当前工具不能保证”>
请确认以上生成参数；缺少选项时，请直接回复所选分辨率和图片尺寸。
```

- 即使用户此前已给出两项参数，也必须在第二道确认门中重新展示并获得第二次明确确认；已有参数直接预填，只补问缺失项。
- 参数完整时，用户在 CHECKPOINT 2 回复“确认”“生成”“按这版出图”等无歧义指令才可授权生图；参数缺失时，同样的指令不得通过。
- 用户直接回复全部缺失参数且未提出其他修改时，该回复视为参数确认；只补充或更改分辨率时也可直接通过。
- 用户更改图片尺寸时，按新比例调整提示词构图并退回 CHECKPOINT 1；只修改分辨率时可留在 CHECKPOINT 2 完成确认。
- 批量任务逐项展示参数，或明确声明全部图片共享同一组参数，然后只请求一次统一参数确认。
- 未通过第二道确认门：🛑 STOP，不调用图片生成工具。
- 平台没有生图能力或不能兑现精确像素尺寸：停在第二道确认门，交付可复制提示词并说明可用替代路径，不假装已经出图。

## 反例黑名单

- 不把导演分析稿直接当成生成稿。
- 不用“高级、电影级、有氛围、超真实、完美质感”等空话代替画面关系。
- 不机械堆固定负面词；只写本次最关键的约束。
- 不擅自把屏幕、标识、书报或包装上的文字设为不可辨识；用户要求可读文字时保留其原文，未给文案则不编造具体内容。
- 不同时锁死机位、手势、物件位置、焦段、光圈和全部背景细节。
- 不用“8K、高清”代替镜头、光线、材质和色彩设计。
- 不把柔光写成全画面泛白、全面抬黑、奶油雾或失去高光纹理。
- 不把电影感等同于可见颗粒；复杂场景和干净影像默认不用颗粒。
- 不在小修改中重新设计整张图。
- 不在参考图不可读时猜测内容。
- 不在用户分别确认提示词与生成参数前调用图片生成工具；不得把一次确认同时解释为两道确认。

## 最终检查

- 是否像导演描述而不是参数清单。
- 是否已获得或合理推断景别；用焦段推断时是否标注预期取景范围。
- 是否写清画面核心和镜头从哪里看。
- 是否保留主体、动作、环境、主光和具体色调。
- 摄影参数是否服务画面且没有互相冲突。
- 真人真实感是否加入适量拍摄损失，而非全面降质。
- 是否只让视觉落点承担高频细节，背景没有碎纹理、颗粒和随机小物平均铺满。
- 是否保护关键亮部纹理并保留深色锚点；柔光、雾气和光晕是否局部且有来源。
- 参考图或设定板是否保持身份、结构和方向一致。
- 是否避免过度锁定，只保留高价值约束。
- 是否符合用户要求的输出密度和语言。
- 是否先单独确认提示词，再在下一条助手回复中单独确认分辨率、图片尺寸和换算后的实际像素。
- Image API 或 CLI 是否显式传入合法的非 `auto` 尺寸；不支持精确尺寸的工具是否已经停止而非继续生成。
- 是否获得两次明确确认，并在每一道确认门停止，没有提前出图或把两道确认合并。
