# 启星亲子短视频总控 Skill

## 一、Skill 定位

本 Skill 只负责管控一条启星亲子竖屏短视频的完整制作流程。

它不直接替代各子 Skill 的创作逻辑，而是负责：

- 检查输入和必要素材
- 判断使用哪一个旁白 Skill
- 管理各阶段的输入与输出
- 管理人工确认节点
- 调用后续分镜、视频、音乐和剪辑流程
- 控制局部修改后的回退范围
- 保证 Logo、旁白音色、时长和视频规格一致

默认制作规格：

- 单条视频
- 竖屏 9:16
- 720 × 1280
- 默认总时长约 60 秒
- 共 6—8 段视频，最后一段为固定品牌片尾
- 每段视频的时长严格按照策划结果设置，不按 5 秒或 10 秒取整

## 二、文件结构

执行任务时按阶段读取：

- `references/qstar-brand-guidelines.md`\
  品牌定位、文案、画面、人物、Logo、片尾和声音规范。

- `skills/qstar-script-material/SKILL.md`\
  启星旁白skill 材料解析版。用于解析用户上传的产品、活动、路线或项目资料。

- `skills/qstar-script-creation/SKILL.md`\
  启星旁白skill 发散版。用于用户只有一个主题、想法或大方向的情况。

- `workflows/01-script-routing-and-storyboard.md`\
  负责输入判断、旁白 Skill 路由和分镜拆分。

- `workflows/02-video-with-narration.md`\
  负责根据每段旁白生成带固定音色旁白的视频。

- `workflows/03-bgm-subtitles-final-edit.md`\
  负责生成 BGM、字幕、剪辑、混音和最终导出。

## 三、启动前检查

执行完整流程前，先检查：

1. 用户是否提供了视频主题或资料。
2. 用户是否说明目标时长；未说明时默认 60 秒。
3. 用户是否上传了启星亲子 Logo 原始文件。
4. 用户是否提供了必须出现或禁止出现的内容。
5. 是否存在已确认的旁白、分镜或视频素材。

### Logo 强制规则

固定品牌片尾必须展示启星亲子 Logo。

因此：

- 用户必须上传清晰、可用的 Logo 原始文件。
- 不得用纯文字代替 Logo。
- 不得由 AI 猜测、重绘或重新设计 Logo。
- 不得使用其他项目中的近似 Logo。
- 未上传 Logo 时，必须明确要求用户上传。
- 在 Logo 缺失的情况下，不得进入正式视频生成和最终合成阶段。

可以先进行资料梳理和旁白讨论，但不能把完整制作流程标记为可执行。

## 四、旁白 Skill 路由

读取：

- `workflows/01-script-routing-and-storyboard.md`

根据用户输入选择旁白 Skill。

### 使用材料解析版

满足以下任一情况时，调用：

`skills/qstar-script-material/SKILL.md`

典型输入：

- 产品说明书
- 活动方案
- 行程介绍
- 路线资料
- 项目 PDF、PPT、Word
- 官网或宣传资料
- 详细的卖点、服务和场景信息
- 用户已经给出较完整的业务内容

核心原则：

> 先解析真实材料，再进行策略提炼和旁白创作，不编造材料中不存在的事实。

### 使用发散版

当用户只有以下内容时，调用：

`skills/qstar-script-creation/SKILL.md`

典型输入：

- 一个主题
- 一个概念
- 一个目的地
- 一个活动方向
- 一个简单创意
- 没有可供解析的详细材料

核心原则：

> 围绕主题进行启星亲子式发散，但不虚构具体机构、路线、认证、价格、成果或安全承诺。

### 混合输入

当用户既提供了材料，又提出额外想法时：

- 以材料解析版为主。
- 用户提供的创意作为软约束。
- 不得用发散内容覆盖真实材料。
- 对材料未提供的关键事实，不得自行补造。

## 五、完整流程

严格按以下顺序执行：

`输入与 Logo 检查 → 旁白 Skill 路由 → 策略确认 → 画面内容确认 → 旁白确认 → 分镜规划 → 分镜确认 → 带旁白视频生成 → 视频确认 → BGM → 字幕与剪辑 → 最终审核与导出`

不得自动跨过确认点。

## 六、阶段一：旁白与分镜

读取：

- `workflows/01-script-routing-and-storyboard.md`
- 被路由选中的旁白 Skill
- `references/qstar-brand-guidelines.md`

阶段输出依次为：

1. 视频策略
2. 核心人物、场景、事件和画面内容
3. 最终旁白逐字稿
4. 6—8 段视频规划

未经旁白确认，不进行分镜拆分。\
未经分镜确认，不进入视频生成。

## 七、阶段二：带旁白视频生成

读取：

- `workflows/02-video-with-narration.md`
- 已确认旁白
- 已确认分镜
- Logo 原始文件
- 固定声音设定

每段视频直接生成：

- 画面
- 固定音色旁白
- 对应的准确时长

视频中不生成：

- BGM
- 字幕
- 人物对白
- 额外口播
- 未确认文字
- 正文 Logo

最后一段视频固定：

- 展示用户上传的 Logo
- 使用同一固定音色念出 Slogan
- 不再重复正文旁白

所有视频确认后，才进入最终包装。

## 八、阶段三：BGM 与最终合成

读取：

- `workflows/03-bgm-subtitles-final-edit.md`
- 已确认的带旁白视频
- 已确认的 Logo 和片尾
- 视频主题与情绪路径

完成：

1. 生成匹配总时长的无歌词 BGM。
2. 根据视频内旁白音轨制作中文字幕。
3. 按确认顺序连接所有视频。
4. 完成 BGM 混音、字幕、转场和片尾。
5. 输出 720 × 1280、9:16 的最终视频。

## 九、时长规则

目标总时长是全流程硬约束。

- 用户未指定时，默认 60 秒。
- 总时长包含正文视频、品牌片尾、必要转场和结尾停留。
- 60 秒版本的正文旁白默认控制在 180—200 个中文字符，不含固定 Slogan。
- 每个旁白段落不超过 40 个中文字符。
- 旁白段落数量应与视频段落数量一致。
- 全片共 6—8 段视频，最后一段为固定片尾。
- 片尾默认占 5—7 秒。
- 每段时长根据对应旁白字数、动作复杂度和镜头切换计算。
- 每个内部切镜最低 2 秒。
- 每段视频必须使用策划得到的精确时长，不按模型常见的 5 秒、10 秒规格取整。
- 所有视频时长之和应与目标总时长一致，允许最终误差不超过 1 秒。
- 不得通过明显加快旁白语速强行压缩过长文案。

## 十、确认规则

只有用户明确表达以下意思，才视为确认：

- 确认
- OK
- 通过
- 按这版执行
- 继续下一步

没有明确确认时，不进入下一阶段。

## 十一、修改与回退

- 修改产品事实、活动内容或核心策略：回到对应旁白 Skill 的策略阶段。
- 修改人物、场景或事件：回到画面内容确认阶段。
- 修改旁白：重新确认旁白，并重新计算受影响视频时长。
- 只修改某一段分镜：只重做该段提示词和视频。
- 只对某一段视频不满意：只重做该段带旁白视频。
- 修改固定音色：所有带旁白视频都需要重新生成。
- 修改 BGM：只重做 BGM 和最终混音。
- 修改字幕：只重做字幕和最终导出。
- 修改 Logo：只重做片尾视频和最终导出。
- 调整段落顺序：重新检查旁白、视频、字幕和音乐结构。

不要把局部修改扩大为不必要的全量重做。

## 十二、Ask User

只在以下情况提问：

- 没有主题，也没有可解析材料
- 无法判断用户提供的是资料还是简单创意
- 用户没有提供目标时长，且上下文无法使用默认 60 秒
- 未上传 Logo
- 需要忠实呈现固定人物、产品或装备，但没有参考
- 涉及健康、安全、认证、教育成果等需要事实依据的承诺
- 用户要求与已确认内容或固定片尾规则冲突
- 进入下一阶段前需要取得确认

信息足以继续时，不重复询问。

## 十三、自检

每次输出前检查：

- 是否选择了正确的旁白 Skill
- 是否以用户材料为事实边界
- 是否要求并取得了 Logo
- 是否保持 720 × 1280、9:16
- 是否确定目标总时长
- 是否控制 60 秒旁白为 180—200 字
- 是否每段不超过 40 字
- 是否规划为 6—8 段，且最后一段为固定片尾
- 是否每段视频直接包含固定音色旁白
- 是否无 BGM、无字幕、无人物对白
- 是否只在片尾展示 Logo
- 是否在旁白、分镜、视频三个阶段分别等待确认
- 是否只让受修改影响的内容失效
