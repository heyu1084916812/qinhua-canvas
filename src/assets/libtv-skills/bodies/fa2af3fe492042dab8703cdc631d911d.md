# 批量换脸_ssky

### 一句话介绍

本 Skill 用于将一张或多张底图中的人脸，精准统一地替换为指定参考模特的脸，并批量产出高分辨率成品图，适用于电商模特更替、广告分镜修改、角色形象统一等场景。

**核心目标：换脸。** 默认只替换五官与脸型；少数情况需要换头；极少数情况才整体反推提示词重绘。

### 如何使用

- **底图**：一张或多张需要换脸的原始图片。
- **参考脸**：对话指定的模特图、当前上传的模特图，或画布中命名为「【指定模特】」的节点。

### 相似度优先级（最高准则）

**让位顺序（冲突时按此裁决，不得使用「并列第一」这类模糊表述）**：

1. **第一优先：骨相相似度**——换脸的根本目的，脸型轮廓、下颌线、眼型、鼻型、唇形等**结构特征**必须落地。
2. **第二优先：四项必锁中的妆容、光感、色感**——融合度，决定成品是否违和。
3. **皮肤质感不参与排序，属非验收项**——仅作精简约束与交付后提示，不参与成品合格与否的判定。
4. **表情与眼神单列最高，不参与上述排序**：肌肉状态与情绪指向同属「表情眼神」这一不让位类别，任何时候都不得为骨相相似度或融合度让位。

**作用范围澄清（重要）**：上述「骨相相似度第一优先」仅适用于脸型轮廓、下颌线、眼型、鼻型、唇形等**结构特征**；而**肌肉状态与情绪指向**同属「表情眼神」这一不让位类别。即：**结构让位规则与表情让位规则分别作用，不得用骨相优先去覆盖情绪基调**。

**统一裁决句**：「骨相相似度与四项必锁发生冲突时，优先保骨相相似度；妆容、光感、色感在不牺牲骨相相似度的前提下尽量满足。表情与眼神例外，始终最高，不让位。」

其余说明：脸的相似度永远第一位；同时与原底图人物的表情、角度、光影高度一致；只迁骨相、不迁妆容（妆容、肤色与皮肤质感一律保留底图原样，详见 `references/reference-division.md` 中的分工铁律）。

### 四项必锁总纲（每次生成 prompt 的强制骨架，缺一不可）

在「骨相替换」之外，以下四项为并列必锁项，构成每次换脸生成的六段必备结构：
**骨相替换 → 锁妆容 → 锁光感 → 锁色感 → 锁眼神表情 → 底图其余逐像素保持。**

1. **锁妆容**：唇色唇质与唇纹、眉形眉色眉流、眼影眼线睫毛卧蚕、腮红色调与位置、修容高光分布——全部沿用底图，参考脸不提供任何妆容信息。
2. **锁光感**：底图光线的来源方向与数量、主光在面部的落点与高光形状、明暗交界线位置与软硬、阴影过渡的渐变节奏、光比强弱、眼神光（catchlight）的数量/位置/形状与大小——眼神光尤其不得丢失或改位，它是「同一双眼睛」最直观的证据。
3. **锁色感**：底图整体色温与色调倾向（暖黄/粉紫/冷白等）、面部肤色的冷暖基调、环境光在皮肤上的染色程度、白平衡与色彩氛围——严禁把参考脸的中性白平光或冷调白平衡带入，成品脸部必须像泡在底图同一锅光色里。
4. **锁眼神与表情**：沿用「表情最高优先锁定」写法（逐要素描实口唇张开幅度、牙齿暴露量、嘴角上扬角度、苹果肌状态、下唇位置，双向禁令，冲突时优先保表情），并新增眼神三项——视线方向与聚焦位置、眼睑开合度与睁眼力度、眼神的情绪基调（如慵懒/清亮/含笑/疏离）。表情是肌肉状态，眼神是情绪指向，两者各自锁定，不得只锁其一。

以上四条须写成可复制的 prompt 段落模板，与「骨相替换」共同构成六段必备结构。四项必锁与骨相相似度冲突时，按「相似度优先级」的统一裁决句处理。皮肤质感另作精简约束（见 `references/reference-division.md`），不占六段结构篇幅。

### 操作步骤

1. **解析输入**：通过优先级匹配（对话指定 &gt; 指定模特图 &gt; 命名节点 &gt; 顺序约定）确定目标脸。检测节点类型，排除非图片节点。
2. **差异评估**：对目标脸与底图人脸进行六维评估（脸型、颅面、发色、发型、肤色、五官），判定相似度分档（A/B/C 三档）。
3. **前置裁切判断 / 路径选择（关键前置步骤）**：
   - **判定顺序（固定）**：第一步回读实测人脸宽度 → 第二步才判断是否适用外部增强例外。
   - **像素判断必须回读实测**：底图尺寸与人脸原生像素宽度必须以 `get_node_details` 返回的真实分辨率为准计算，严禁凭预览缩略图目测估算。
   - **回读失败的兜底口径**：`get_node_details` 未返回分辨率时，依次尝试其他可核实的实测途径（读取节点元数据、从生成参数中的 ratio+resolution 反推实际输出尺寸、比对同源已实测节点）。上述途径均不可得时，必须暂停并向用户说明「无法核实像素规格，路线判断可能不准」，请用户提供或确认底图实际尺寸后再继续。任何情况下都禁止以预览缩略图目测估算代替实测来定路线。若最终仍未取得实测值而用户同意继续，须在核对报告「路径与规格」项标注 ⚠️ 并写明「规格未经实测核实，路线判断存在偏差风险」。
   - **实测人脸原生宽度 ≥250px：路线 A（整图直出）**。整图直接换脸交付。
   - **实测人脸原生宽度 &lt;250px（含原 100–250px 与 &lt;100px 两档）：裁切腰上像路径**。裁切出腰上像 → 放大 → 在这张腰上像上完成换脸 → 直接以该腰上像换脸图作为成品交付。**默认不回贴原图**，回贴环节已从默认流程中删除；仅当用户额外提出回贴要求时才回贴。
   - **裁切成本提示（触发式、非阻断）**：
     1. **触发时机**：一旦按判定顺序确认本张底图要走「裁切腰上像」路径（含临界区 225–275px 按小脸处理的情形、以及裁切放大后仍 &lt;250px 需追加超分前置的情形），必须在该次生成开始之前向用户提示，不得事后补说、不得省略。
     2. **提示内容三要素，缺一不可**：
        - 告知本张人脸偏小、需要走裁切腰上像路径；
        - 明确成本区间：在本工作流内完成「裁切放大 + 换脸」大概率需要约 150~200 积分；
        - 给出替代建议：建议用户先在其他方式／其他工作流中把腰上像裁切放大好，再把成品交回本 Skill 直接换脸，这样可省去裁切放大那一步的开销。
     3. **性质为温馨提示，不是阻断**：用户知悉后若仍希望在本工作流内一步做完，照常继续执行，不得拒绝或反复劝阻；用户选择自行准备腰上像时，把该图直接作为换脸底图，跳过裁切放大步骤。
     4. **若用户已自备腰上像（外部裁切放大好的图）**：不触发本提示，直接以其为底图换脸，但仍须按既有像素回读口径核实其人脸宽度是否 ≥250px，不足则按「裁切放大后仍不足」分支追加超分前置。
     5. **报告留痕**：凡触发过本提示的张次，须在核对报告「路径与规格」项注明「已向用户提示裁切成本与替代方案」，并写明用户最终选择（本工作流一步完成 / 自备腰上像）；批量场景下逐张标注，不得合并省略。
     6. **批量情形**：一次多张且其中若干张需裁切时，先汇总告知共几张需裁切、合计大致积分区间，再逐张执行，避免逐张打断用户。
   - **临界区处理**：实测人脸宽度落在 250px 的 ±10% 区间（即 225–275px）时，按小脸路径处理（裁切腰上像放大后换脸）更稳妥，避免因几个像素的误差在两条路径间抖动。
   - **裁切放大后仍不足**：走小脸路径裁切腰上像并放大后，若实测人脸宽度仍 &lt;250px，则追加一次超分前置，再继续换脸。
   - **异常输入**：底图无人脸、或存在多张人脸而未指明换哪一张时，一律暂停并询问用户，不得自行选取目标脸。
   - **已外部增强的例外**：适用前提为「实测人脸宽度 ≥250px 且该底图已经外部人脸增强」（如 topaz），两个条件缺一不可，且实测值优先于外部工具的已知事实；满足时直接走路线 A 整图直出。回读失败时按上述兜底口径处理，不得以「底图已由外部工具增强」为由跳过实测、直接判定走路线 A。
   - **腰上像取景定义**：
     - **上边界**：保留头顶发丝与少量头顶留白，不得裁掉头顶。
     - **下边界**：收在腰线以上，以人物腰部为界，不包含手提包、裙摆、膝部及以下、坐姿的下半身、手持道具位于腰线以下的部分。
     - **包含范围**：头部、肩颈、胸部至腰部以上，以及该范围内可见的服装上身（领口、门襟、纽扣、袖型）、首饰（项链、耳饰）、手部若位于腰线以上则保留、该范围内的背景与道具。
     - 仍以人脸为视觉中心；不得切成紧贴面部的大特写方图（须保留肩颈与服装上下文，这是判断妆面、光感、色感与 proportions 的依据）；画幅按裁切后的实际比例换算到预设档位，不支持 Adaptive；裁切放大这一步须原样保真、不得重绘五官、不得改变表情幅度、视线方向、情绪基调与光影色温，遵循既有的像素回读与保真要求。
     - **例外处理**：若底图人物为坐姿、蹲姿或腰线以下主体占比较大，导致按「腰上像」裁切会切掉关键服装或道具信息，则在裁切前向用户说明该情况并确认取景下边界，不得自行扩大或缩小范围。
4. **分级策略（按需升级，默认最低档）**：详见 `references/tiered-strategy.md`。
   - **默认档——换脸**：仅替换五官与脸型，保留底图发型、表情、角度、光影、服装、场景。适用于绝大多数情况。
   - **升级档——换头**：仅在满足量化升级条件时使用（少数情况）。换头档解决的是「侧面能否换」，不解决「侧面该换到什么强度」；正侧面下必须同时启用 `references/profile-translation.md` 的侧面转译，否则会出现结构过度表现导致的扭曲。
   - **重绘档——整体反推提示词重绘**：仅在满足量化升级条件时使用（极少数情况）。
   - 升级必须在核对报告中写明命中的具体条目，不得默认跳档。
5. **引用分工**：在 `reference_nodes` 中插桩。主参考负责身份特征，辅参考负责角度依据，并为底图设置硬性禁令，严禁读取旧五官特征。详见 `references/reference-division.md`。
6. **神态锚点复核（硬约束，撰写神态类 prompt 之前必须完成）**：
   - **适用范围**：视线方向、头部朝向与偏转角度、情绪基调三项，统称「神态锚点」。凡撰写这三项的 prompt 描述，必须先完成复核，不得凭缩略图或第一印象直接下笔。
   - **复核方式（按路径分别规定）**：
     - 小脸／腰上像路径：裁切放大完成后，必须回读该腰上像节点、查看其图像本体，以放大后的清晰面部为准确认三项，再撰写换脸 prompt。这是本条最主要的适用场景——裁切本身就是把脸看清的过程。
     - 整图路线 A：以**底图原生宽度**为准（与输出档无关），人脸原生宽度 ≥400px 且五官清晰时可直接以底图复核；若底图人脸原生宽度 &lt;400px、为侧脸、或有遮挡或光线偏暗，必须先临时裁切一张面部局部图用于复核神态（该局部图仅作核对用途，不作为换脸底图、不进入交付物、不参与引用分工），复核后丢弃或保留均可，但不得据其提供五官特征。
   - **复核必须落到可写下的结论（量化字段清单，复核时逐项填值、写 prompt 时逐值落实）**：
     - **上眼睑下盖量**：上眼睑边缘盖住虹膜上缘的比例（如 0%／四分之一／三分之一／二分之一）。
     - **眼裂开合度**：相对常态平视的开度（半垂／正常／睁大）。
     - **视线夹角**：与水平线的夹角及方向（如向下 15–20°），并注明投向镜头／画外左／画外右／画外下／看手中物件。
     - **眼球在眼裂内的位置**：偏向哪侧、上下眼白露出情况。
     - **眉部高度**：舒展／微抬／高抬，眉与上眼睑间距的松弛程度。
     - **上睫毛朝向**：朝前／朝斜下。
     - **眼尾线条**：平收／向下柔和收束。
     - **笑意类型**：闭唇浅笑／微张露齿／开口露齿／无笑意，并附嘴角上扬幅度与牙齿暴露量。
     - **失焦感（延伸项，单独写明）**：虹膜与眼白的对比强度、注视的聚散程度、眼神的「醒」或「柔」。失焦感必须单独写出，否则模型默认给眼睛加神采。
   - **禁令**：禁止用「平视略偏下」「眼神温柔」「眉眼低垂」等未量化的日常词作为锚点结论；这类词只能出现在量化值之后的补充描述里。
   - **与既有规则的关系**：本条是「像素判断必须回读实测、禁止凭缩略图目测」在神态维度的延伸，二者同源同理——都是「判断依据必须来自实际读到的图像，而非印象」。
   - **冲突处理**：若复核结果与第一印象不一致，一律以复核为准，并在核对报告中注明「初判与复核存在差异，已采复核值」；若复核后仍无法确定（如极端侧脸看不清眼球朝向），须向用户说明不确定项并请其确认，不得自行猜测填入。
   - **报告留痕**：核对报告新增一行「神态锚点复核」，注明三项复核结论与复核所用图像（腰上像 node_key 或临时局部图说明）；该项为必填项，缺失视为流程未走完。
   - **边界澄清**：本条不改变情绪与视线不让位规则，也不改变换头档量化阈值，只是让那些判断建立在经过复核的事实上；复核得到的偏转角若明确达到 60°，仍按阈值升级换头档并留痕。
7. **段落互相抵消检查（撰写完成后必做）**：
   - 撰写完成后必须做一次交叉检查：侧面结构类、骨相类、妆容类等描述性条款中的用词，是否会与视线／低垂／表情／情绪这些最高级锚点发生抵消。
   - **高风险词点名警示**：居中、摆正、自然位置、不前置、立体、有神、睁亮、饱满、挺拔、清晰锐利——这类词若落在眼球位置、眼睑、眉部、唇部附近，可能把神态往「醒／正／强」方向推。
   - 若在最高级锚点附近必须使用这类词，须在同句内写明优先级裁决，格式如「本条不得被理解为把眼睛睁开摆正，低垂优先」。
   - 冲突裁决口径与既有优先级一致：视线、低垂、表情、情绪始终高于结构与融合度类描述，结构类条款一律让位并被限定。
8. **表情最高优先锁定（标准写法）**：
   - **肌肉状态（逐要素描实）**：口唇张开幅度、牙齿暴露量、嘴角上扬角度、苹果肌状态、下唇位置。
   - **情绪基调（与肌肉状态并列的独立锁定项）**：情绪基调（如温婉／含笑／慵懒／清亮／疏离／甜美）不得为骨相相似度让位；即便照搬参考脸的五官结构，成品传递的情绪必须与底图一致——**五官可以换、笑意不能丢**。
   - **情绪基调必须逐要素描实，不能只写形容词**：写明笑意类型（闭唇笑／浅笑／露齿笑）、嘴角上扬幅度、眼周参与程度（眼角是否下弯、卧蚕是否隆起、眼神是否放软）、眉部状态（是否舒展、有无挑眉），并与底图逐项对齐。
   - **双向禁令**：既不得收敛（露齿→浅笑/抿嘴），也不得夸大（浅笑→大笑露龈）。
   - **裁决句**：「若脸部相似度与表情保留发生冲突，优先保证表情不丢失。」
   - 头部朝向、倾斜角度与视线走向同段落锁定。
   - 眼神三项（视线方向与聚焦位置、眼睑开合度与睁眼力度、眼神情绪基调）与表情各自锁定，不得只锁其一。
9. **参数设置（quality: high, resolution: 2K）**：
   - **质量档**：一律 high（界面显示「高画质」）。换脸成品与所有中间步骤（裁切腰上像放大、超分前置、神态复核局部图）统一 high，不得在同一批次内混用不同档位。
   - **分辨率**：一律 2K。比例仍按底图实测值换算到预设档位、不支持 Adaptive，原有比例换算规则不变。
   - **写法（关键）**：quality_spec 一律使用带维度名的英文枚举形式，固定为一句：`quality: high, resolution: 2K`。禁止使用任何中文档位词作为档位指定，包括但不限于「高画质」「高质量」「超高画质」「超清」「极致」「最高」——前者映射结果随机（已实证「高画质」落到 xhigh），后者会直接拔高到 max。
   - **例外情形（仅此两种，且须在报告中写明理由）**：
     - 用户明确指定其他档位或分辨率时，遵用户指定；
     - 某张成品经核对确认因 2K 尺寸不足导致细节缺失（如放大后纹理糊化、发丝断裂、人脸像素低于可核对下限），可在重跑时升分辨率，但须先向用户说明并征得同意，不得自行升级。档位一律维持 high，不得以「提升质量」为由自行升到 xhigh 或 max。
   - **档位留痕（防追认机制）**：核对报告的「规格」项必须回读节点保存的实际参数，逐项比对 quality 是否等于 high、resolution 是否等于 2K；任一不符须在报告中明确标注偏差并写明实际落到的枚举值及其对应的中文标签，不得静默接受、不得凭措辞推断映射关系而宣称合规。特别警示：不得假设某个中文词会映射到某个枚举值，一律以回读到的枚举值为准判断合规。
10. **执行生成**：单次最多并发 5 个节点。若存在历史产物则优先复用。

### 输出要求

- **成品图片**：比例、构图、光影必须与底图严格一致；换脸后的表情、角度、光影须与原底图人物高度一致。
- **小脸场景交付说明**：小脸场景交付的是裁切放大后的腰上像换脸成品，其画幅、取景与原整图不同属预期结果，不属于违反构图约束；核对报告的「规格」项按腰上像成品的实际画幅核对。报告中须注明本张走的是腰上像路径而非整图直出，以及原始整图的 node_key 以便追溯。
- **皮肤质感交付后提示**：凡成品皮肤质感明显偏软（判定标准：与底图对比可见毛孔细节丢失或皮脂高光被抹平），在核对报告之外向用户补一句提示——「皮肤质感偏软属模型能力上限，如需可后期局部补纹理」，并说明这不是重跑能解决的问题，不建议为此重复生成。2K 输出下皮肤质感不作任何期待，仅保留精简约束。
- **核对报告**：逐张核对，并保留原有要求。核对项详见 `references/checklist.md`。
- **消耗说明**：列出生成次数明细与预计积分消耗，注明复用节点及性价比方案。
